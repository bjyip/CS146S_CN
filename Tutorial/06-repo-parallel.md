# 06 Agent 就绪仓库与并行开发

[上一章](05-skills-automation.md) | [目录](README.md) | [下一章：测试与审查](07-testing-review.md)

## 1. 仓库结构决定 Agent 的工作成本

Agent 每次需要重新定位入口、猜测试命令和判断生成文件时，都会增加调用次数与错误机会。对人友好的明确架构、稳定接口和可运行测试，同样对 Agent 有帮助。

“Agent 就绪”不是增加一个规则文件就完成，而是降低研究、修改、验证与恢复的不确定性。仓库应当让一个新参与者能够从任务定位到行为证据。

## 2. 一个自学用审计表

下面是教程自定义评分，不是课程或行业认证。每项 0 分表示缺失，1 分表示有文档但未验证，2 分表示在新环境中验证过，总分 16 分。

| 项目 | 要求的证据 |
| --- | --- |
| 启动 | 明确前置条件、工作目录和启动命令 |
| 测试 | 独立测试数据、可重复测试命令 |
| 架构 | 入口、模块边界和数据流可定位 |
| 契约 | schema、错误行为与文档一致 |
| 配置 | 示例配置无秘密，真实配置隔离 |
| 修改范围 | 生成物、第三方文件和并发工作可识别 |
| 质量门禁 | 检查失败能阻止合并或发布 |
| 恢复 | 回滚、数据库迁移和故障处理说明 |

分数只帮助定位缺口。一个没有授权隔离的高分仓库仍可能危险。不能通过添加文档来假装获得未执行的验证分。

## 3. 分解任务要按依赖，而不按人数

“让一个 Agent 改接口，另一个改同一个 schema，第三个改测试”看似并行，实际依赖强。schema 未确定，另外两人只能猜，最后集成返工。

可以先统一契约，再让独立工作区分别做前端适配与文档；或让一个实现，另一个只读审查。任务分工应明确文件所有权、共享接口、基线提交、输出格式和合并顺序。

并行收益取决于独立程度。理想化地，串行部分占比为 `s`、使用 `n` 个工作者时，加速比上限约为 `1 / (s + (1-s)/n)`；实际还要扣除沟通、重复研究和集成成本。更多 Agent 不保证更快。

## 4. worktree 隔离了什么

`git worktree` 为同一仓库提供不同工作目录和分支，减少同时编辑相同文件的干扰。它不隔离端口、环境变量、用户全局配置、外部账号或共享数据库。

以下只是练习命令示例，不是教程作者已执行的操作。先确认当前已有工作和分支，父目录存在；未经本人决定不要创建提交或清理其他人的目录。在自己的练习仓库中：

```powershell
git status --short
git worktree list
git worktree add "../cs146s-ui" -b lab/ui
git worktree add "../cs146s-tests" -b lab/tests
```

worktree 从提交基线开始，不会自动包含当前未提交修改。如果任务依赖这些修改，先决定如何提供一致基线，不能让不同 Agent 对不同版本工作。使用不同端口、临时数据库和任务凭据；依赖环境的隔离也应记录。

集成时检查每个分支完整差异与测试，合并后再跑联合测试。两个分支各自通过，不意味着合在一起通过。出现冲突按规格解决，不按谁的代码更多决定。

## 5. 后台 Agent 需要持久任务状态

异步任务可能在用户离线时运行，需要记录任务 ID、基线、预算、权限、租约与状态。推荐状态链为“待办、运行、等待批准、验证、待合并、完成”，失败或取消则进入独立状态。

同一个 Issue 重复触发时需要幂等识别，避免多个 Agent 同时实现同一任务。失败恢复要判断是否留下部分文件或外部写入。取消应停止活动进程并保留诊断，不只是停止显示进度。

Issue-to-PR 的“完成”应至少表示差异和测试已经提交给审查，而不是已自动上线。默认后台 Agent 无部署凭据；合并和发布仍按项目门禁处理。

## 6. 动手：修补就绪度，再测并行

1. 使用审计表检查第 4 或第 5 周练习副本，给每项证据而不是主观分数。
2. 修复两个最影响复现的缺口，例如遗漏工作目录和测试数据库隔离。
3. 选择两个真正独立任务，先固定接口和基线，分别列出允许修改文件。
4. 在独立工作区执行，一个任务失败时记录原因，不让另一个悄悄覆盖它。
5. 比较串行与并行的总墙钟时间、调用成本、人工纠错与集成时间。不同任务难度会造成混杂，应在结论中说明。
6. 合并后运行联合检查，并演练取消一个后台任务。

原 [2025 第 5 周作业](../_assignments/2025%20fall/week5/assignment.md) 还要求 Warp 的共享工作流、规则或 MCP 以及并发 Agent。通用 worktree 实验是自学改编，不自动满足 Warp 产品要求。

验收：两个任务没有共享文件写冲突，有统一基线和集成结果，端口/数据库隔离清楚，有取消与失败交接证据。

## 7. 自测与答案

**问：为什么两个 worktree 仍可能互相影响？** 它们可能共享外部数据库、账号、端口或全局设置；文件目录隔离只是一个层面。

**问：并行两项任务一定快一倍吗？** 不会。串行依赖、协调和集成有成本，错误还可能增加返工。

**问：给每个 Agent 任意写权限是否最自主？** 可能最危险。明确所有权和最小权限通常更容易获得可靠成果。
