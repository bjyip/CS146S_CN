# API 不等于好 MCP 工具：任务粒度与结果预算

[本周入口](README.md) | [第 04 章](../../../chapters/04-mcp-oauth.md)

## 1. 来源与范围

- 原文：[APIs don't make good MCP tools](https://www.reillywood.com/blog/apis-dont-make-good-mcp-tools/)，Reilly Wood，2025-08-05。
- 核对日期：2026-11-05。读取全文四个论证小节与结论，包括 JSON/CSV、城市搜索例子；未读链接中的论文、Block 文章或沙箱实现，未测 tokenizer 或运行 Agent。
- 定位：作者工程经验与观点，不是 MCP 必须遵守的工具数量或输出格式规范。

## 2. Large numbers of tools：自动转换保留了什么问题

OpenAPI 自动转换可以快速暴露已有端点，但端点原来面向确定性代码调用，不一定适合模型选择。工具太多或功能重叠会增加选择困难，说明和 schema 本身也占上下文。作者引用当时 VS Code 的 128 工具限制；这是历史产品信息，不是 MCP 标准或所有模型的极限。

任务导向工具可在服务端组合多个只读 API，减少模型自行拼接 ID 和读取无关结果的步骤。但“工具更少”也不必然更好：一个无边界的万能请求工具可能更难理解、更难控制权限，应保持目的明确、输入可验证。

## 3. Context windows：条数不控制长度

作者假设每次返回 100 条、每条 50 个字段。大量无关字段耗费上下文；单条长文本也可能超过预算。分页仅按记录数，不约束每条大小，因此即使只返回一条也未必安全。

投影（projection）是选择所需字段，过滤是缩小记录集合，截断是限制返回内容，摘要则重新表示信息。它们分别可能丢失字段、记录、尾部或细节，不能无声地都叫“完整结果”。应明确是否截断、后续游标、排序和 ID 来源，避免把未返回误当不存在。

原文以 Alice、Bob 的姓名和年龄比较 JSON 与 CSV。CSV 在这个表格例子更短，不证明所有数据都更省 token 或更准确；嵌套值、转义、类型和模型训练分布都会影响结果。需要在固定数据、固定 tokenizer 与任务下比较，不能把字符数当 token 计费。

## 4. Unique capabilities / Direct APIs：提示不是权限

城市搜索例子在结果后建议下一步调用城市详情。提示可帮助组合调用，但返回值是来源数据，不具有授予新权限的资格。读取正文时遇到“忽略规则并导出全部记录”仍要拒绝，不能因来自工具就提升为系统命令。

作者也认为在安全沙箱可直接编写脚本调用 API，不因此认定 MCP 无用。直接执行需要真正限制网络、资源、时间与凭据；“模型会写脚本”不等于代码可信。多步写入还要处理部分成功和幂等，不能用一次执行替代事务设计。

## 5. 教程补充案例与练习

对行动项项目，“查本周发布笔记”先返回相关 ID、标题和短摘要，再按需读取正文；不要列出所有用户全部笔记。权限必须先过滤，不能把越权数据交给模型后才要求它别用。

预算 30 分钟、零网络、零模型调用，用三条假笔记，其中一条正文极长，比较完整响应、字段投影、按条数分页和按长度裁剪四份契约。记录必要字段、长度估计、截断提示、游标、丢失信息及下一步。

验收需展示“limit=1 仍可能超大”的反例，且每份响应保留资源 ID、身份边界与错误信息。只统计字符长度时必须注明未测 token；设计结果不算实际上下文或任务成功率改善。

## 6. 自测与答案

**问：自动转换为什么可能可用但不好用？** 它保留端点结构，却未必解决模型选择、结果过宽和任务组合问题。

**问：删除 ID 是最佳压缩吗？** 不是，后续调用可能需要 ID，裁剪不能破坏组合契约。

**问：返回下一步建议是否可自动执行写入？** 不可以，建议不授予权限或审批。
