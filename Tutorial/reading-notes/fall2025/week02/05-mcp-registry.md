# MCP Registry：发现目录与可信执行不是一回事

[本周入口](README.md) | [第 04 章](../../../chapters/04-mcp-oauth.md)

- 核对日期：2026-11-05。已读发布公告全文；未读取 Registry API、发布 quickstart、moderation policy 或实现仓库，未查询实时目录、发布 Server 或安装任何条目。

本篇解释 2025 年预览公告，不据此断言 Registry 当前仍处于预览，也不视作现行 API 使用教程。

## 2. Single source of truth：维护者报告的信息

Registry 是公开 MCP Server 的目录与 API，目的是让分发和发现更一致。维护者发布并维护自报信息，下游目录再筛选、增强并展示给用户。所谓集中来源是元数据组织方式，不代表官方逐个审计实现或保证所有 Server 可用。

发现解决“到哪里找候选能力”；连接解决“客户端能否建立协议通信”；授权解决“谁可以操作哪些资源”。这三个问题不能用一个目录条目同时回答。

## 3. Public and private sub-registries：下游可以有自己的规则

公告允许公开 marketplace 加入面向自身用户的筛选，企业私有目录则可以遵循自己的隐私与安全要求，并尽量共享 API schema。私有目录不需要把内部 Server 公开；从上游获取公共元数据也不意味着接受上游所有条目。

教程补充：企业笔记工具目录可只展示已批准版本，并记录维护者、来源、允许主体、数据边界和撤销状态。这个治理表是教学设计，公告没有提供已运行的企业权限系统。

## 4. Moderation / Getting started：事后移除的能力边界

社区可以报告垃圾、恶意代码或冒充服务，维护者可 denylist 并移除公开访问。这种事后治理有价值，但不能证明恶意版本从未被发现、缓存或运行，也不会自动撤销下游凭据和已发生的写入。

公告明确预览不提供数据持久性或其他保证，并可能发生破坏性变更。历史限制不能反推现行状态；若实际接入，应另读当前 API、版本及政策，不把此公告中的入口视为固定契约。

## 5. 受控练习与验收

预算 20 分钟、零网络、零安装，以三条虚构候选记录做目录分诊：官方域名但未知版本、名称相似的第三方服务、已批准版本但已撤销权限。分别决定允许发现、允许连接、允许调用哪一层，以及还需什么证据。

验收是一张三层状态表和撤销方案；不能填入真实秘密。答案要点：目录存在不等于安全认证，版本批准不等于用户授权，撤销后需执行端拒绝而非仅隐藏条目。本练习不证明真实目录或门户已实施治理。

## 6. 自测与答案

**问：官方 Registry 收录是否等于可以自动安装？** 不等于；仍需核对代码来源、版本、许可、运行能力和独立安装授权。

**问：条目被移除是否撤销了运行中的 token？** 不保证，授权服务器与执行层需要自己的撤销机制。

**问：公告是否要求企业公开内部目录？** 没有，公告明确讨论私有 subregistry。

第 04 章用本篇区分目录、连接和授权；门禁与撤销练习为教程扩展。
