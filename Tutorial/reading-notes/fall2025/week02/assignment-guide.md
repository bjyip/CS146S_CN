## 3. 按调用链理解当前行为

### 规则提取与语义提取不同

[extract.py](../../../../_assignments/2025%20fall/week2/app/services/extract.py)先按行匹配项目符号、TODO/Action/Next 前缀或复选框。项目符号行不做任务语义判断；`- 发布已经完成`也会被选入。关键字前缀保留在返回文本中，复选框清理则只处理特定的小写形式，不能由识别时的小写转换推断所有标记都被清理。

仅当没有任何行命中时，才用英文标点加空白切句，并以英文祈使动词表选句。因此含一条项目符号和一条无前缀祈使句时，后者可能被遗漏；中文无前缀任务也没有相同的规则覆盖。大小写去重只处理一次提取结果，不是跨请求数据库去重。以上是代码静态推导，不是本批模型实验。

### Schema 发送与解析验收不同

LLM 请求提供对象 schema，要求 action_items 为字符串数组且不含额外属性。但本地 `_parse_action_items`没有执行完整 JSON Schema 校验：它也接受顶层列表、items 别名、含 text 的对象项；跳过非字符串项，去空白并 casefold 去重。合法解析到空列表就正常返回，不触发规则回退。

例如教程构造响应 `{"action_items":[17]}`会被清理为空列表，`{"items":[{"text":"Write tests"}],"extra":true}`也可被解析。这些与发送的 schema 不同，需在规格里区分“严格拒绝”与“兼容清理”，不能声称所有畸形响应都导致回退。发送 schema 不证明当前模型遵守它，更不证明列表中的任务有原文依据。

服务空白输入直接返回空列表，不调用模型；两条 HTTP 提取路由却对空白文本返回 400。函数与接口是两个契约层，不能把其中一个预期直接作为另一个测试答案。

### 静默回退不能证明模型成功

模型调用或解析异常由宽泛 catch 转入规则函数，返回仍是列表，没有引擎、失败类别或降级标志。页面选择 LLM 按钮并显示结果，不代表真实模型路径完成；200 与结果非空也不能证明语义质量。温度 0 不是跨版本或全部运行条件下确定性保证。

第 03 章的“实际引擎与降级可观测”是教程目标，不是当前响应字段。改变它应调查路由、前端和测试，不凭本导读给原作业新增虚构字段。

### 提取也是写操作，不是只读预览

[notes.py](../../../../_assignments/2025%20fall/week2/app/routers/notes.py)与[action_items.py](../../../../_assignments/2025%20fall/week2/app/routers/action_items.py)在提取后都会调用 insert_action_items。save_note 只控制是否保存原笔记；即使 false，非空行动项仍入库，note_id 为 null。空列表不新增行动项行，但保存函数仍会获取连接并提交。两个提取端点都不是 dry-run，重复点击或重试可能重复创建。

[db.py](../../../../_assignments/2025%20fall/week2/app/db.py)将笔记与行动项分别提交，整个提取请求不是一个事务。保存笔记后若后续失败，可能留下没有对应行动项的笔记；无任务的笔记本来就可能合法，需结合请求状态而非仅看“没有行动项”判断。建表声明外键，但 get_connection 没有显式开启 SQLite 外键校验，不据 DDL 就声称关联完整性已强制保证。

列表按 id 降序，不是显式按 created_at 排序，没有分页与身份过滤。修改完成状态端点不检查 UPDATE 影响行数，不存在 ID 也可能得到成功形状响应。这是本地教学应用边界，不能无鉴权部署成多用户服务。

### 宽松输入与 UI 状态需单独验收

路由用 Dict[str, Any]，对文本调用 str、对 save_note 判断真值、对 done 调用 bool，不是严格业务字段校验：text 为 null 会变为字符串 `None`，save_note 为字符串 `"false"`仍为真，done 为字符串 `"false"`也会成为真。缺文本返回 400 不等于所有错误类型都已正确拒绝；非法请求体等框架行为本批未运行确认。

[前端](../../../../_assignments/2025%20fall/week2/frontend/index.html)通过 textContent 展示笔记和模型文本，避免在这些位置将其拼为 HTML。提取、列表与复选框请求有 finally 释放按钮状态；但只禁用当前提取按钮，两个提取按钮仍可能并发覆盖同一结果容器。requestJson 将 JSON 解析失败替换为空对象，200 非 JSON 结果可能被当作空列表展示。异常复选框会被回滚，但错误显示会清空整个行动项容器。这里没有浏览器或并发验证，不将静态走查写成 UI 测试通过。

## 4. 测试证明什么

[test_extract.py](../../../../_assignments/2025%20fall/week2/tests/test_extract.py)有七个测试函数：一个规则提取、六个 LLM 相关测试。六个都替换 chat，覆盖不可用回退、非法 JSON 回退、空输入不调用、无任务回退、结构化响应清理、JSON 围栏；其中还检查发送的 required 字段与温度。测试名称中的“旧模型”不证明任何实际旧模型行为已测。

规则测试只断言包含三个预期条目，没有断言不存在额外条目；LLM mock 输出由测试直接指定，无法评价真实语义提取。当前测试文件不覆盖 HTTP、数据库、前端、身份权限、跨请求幂等或严格 schema 拒绝。无需真实推理不等于无需安装 Python/Ollama 包，模块依赖仍须可导入。报告与 README 声称的覆盖要按实际断言核对；本批未执行测试，因此不填写通过数。

## 6. 零调用练习与验收

教程扩展，限 50 分钟、零网络、模型与数据库写入，仅纸面用假数据，不执行应用，也不修改原作业。

1. 用 15 分钟画“LLM 按钮 → 提取路由 → 按 save_note 真值决定是否先保存笔记 → 模型/回退 → 保存行动项 → 展示”的链路，为每步标副作用和证据来源，并为异常标出可能中断的位置。
2. 用 15 分钟推演五种假条件：save_note=false、save_note 字符串 false、模型抛异常、模型返回 action_items=[17]、笔记提交后行动项保存失败。分别记录结果可确定部分、持久化可能状态与未知项，不预填 ID 或 HTTP 实测值。
3. 用 10 分钟为“LLM 不可用仍返回 200”写当前行为和目标行为两列。目标需让用户识别降级，不自行断言已经存在 engine 字段；列出路由、前端与测试的受影响位置。
4. 用 10 分钟制作测试矩阵，分开函数 mock、HTTP、假数据库、浏览器与真实模型。每类写一个正常及一个失败预期，记录预算与停止条件，所有执行结果填未运行。

验收交付为调用链、五条件表、一页规格和测试矩阵。答案要点：对非空文本，false 布尔值不保存笔记但仍尝试保存提取结果，非空结果会新增行动项；字符串 false 会进入保存笔记分支；模型异常走规则回退；非字符串数组可被清为空且不回退；分开提交可能留下已保存笔记。写入是否成功仍取决于数据库操作，纸面推演不证明真实服务、数据库或降级提示已通过。

## 7. 自测与答案

**问：Save as note 不勾选是否零写入？** 不是。它只控制原笔记保存，行动项仍会写入。

**问：Schema 和 mock 都有，能声称模型可靠吗？** 不能。还需本地契约验证、独立语义标注与真实模型实验，失败和回退不能隐藏。

**问：空输入应返回空列表还是 400？** 服务函数与 HTTP 入口当前不同；按测试对象的实际契约判断，目标变化则先明确规格。

**问：表有外键、SQL 用参数就保证安全了吗？** 不能。还需外键执行状态、事务、身份归属、权限与输入检查；参数化 SQL 只解决其中一类风险。

**问：模型响应没有任务一定是模型判断吗？** 不是。可能是清理非字符串、规则回退或真正空结果；当前接口不能区分这些原因。
