## 1. 从股票助手看能力叠加

演示包含编排 Agent、新闻 Agent 和股票 Agent。新闻 Agent 搜索并读取网页；股票 Agent 查询数据库、读取历史价格并执行 Python 绘图。正常业务把网络、数据和代码能力连接起来，攻击者因此不必直接接触底层接口，只要能影响编排或工具参数就可能推动能力跨界。

决定风险的不是 Agent 数量，而是哪些来源能影响哪些工具、工具使用谁的身份，以及工具端是否再次验证请求。

## 2. 九个场景的共同结构

| 原文场景 | 能力或信息 | 主要边界问题 |
| --- | --- | --- |
| 识别参与 Agent | 架构信息 | 暴露协作结构可帮助选择后续入口 |
| 提取系统指令 | 内部提示 | 透露行为规则，但不等于取得真实权限 |
| 提取工具 schema | 参数与工具能力 | 让攻击者了解可调用能力与约束 |
| 网页工具访问内网 | 网络读取 | SSRF：外部请求能力触达不应开放的地址 |
| 挂载目录秘密外传 | 文件与外网 | 过宽挂载把秘密带进执行器范围 |
| 云 metadata token 外传 | 云凭据 | metadata 可达性导致服务身份凭据泄漏 |
| SQL 注入读取所有交易 | 数据查询 | 不可信文本进入查询结构 |
| BOLA 读取他人交易 | 对象查询 | 对象 ID 合法仍缺少主体-对象授权 |
| 网页间接注入外传历史 | 低信任网页与网络工具 | 将会话内容编码进外部请求形成泄漏 |

这里转述原文场景和机制，不提供真实目标、攻击地址、SQL 或外传步骤，也不把作者演示当作本地实验结果。

## 3. 身份冒充不只存在于提示文本

文本说“我是管理员”只是在声称身份，不是认证。更危险的链条是先从挂载文件或云 metadata 取得凭据，再用凭据代表服务身份访问资源。系统若只按 token 是否有效放行，而不限制该身份的权限、受众与资源范围，泄漏会扩展为跨资源访问。

BOLA 则说明另一种缺口：参数格式完全正常，用户仍可请求他人的交易。关键校验不是“参数是否看起来恶意”，而是当前主体能否对这个对象执行这个动作。模型输出合法 schema 不会自动补上对象授权。

所谓“只读网页”也不是无副作用：请求一个外部地址时，URL、查询参数或其他请求数据可能承载会话内容。只读描述的是对目标页面不写入，不代表没有网络传输和泄漏。

## 4. 五层防护及其限度

原文讨论提示加固、内容过滤、工具参数验证、SAST/DAST/SCA、执行器沙箱。这些应互补，而不是选一个就宣布安全。

提示加固帮助表达任务边界，过滤降低部分恶意输入进入链条的概率；两者都不能代替执行层权限。参数验证需要核对类型、地址与业务范围，SQL 应避免把输入拼入查询结构，不能仅过滤特殊字符。业务授权还必须绑定主体、对象和动作。

执行器沙箱需控制网络、挂载、capabilities、syscalls、CPU 与内存。使用容器这个事实本身不足以证明隔离安全，过宽挂载或内网可达仍会暴露能力。静态和动态检查也只覆盖实际纳入的规则与路径。

产品宣传与能力声明不是独立效果评测，本轮没有验证原文提到的商业防护产品。

## 5. 零执行练习：给工具补授权契约

预算 35 分钟；零网络、零模型、零数据库、零代码执行，只手工设计。教程假设一个行动项助手具有 `read_page`、`get_task` 和 `draw_chart` 三个工具，不提供可执行实现。

1. 用 10 分钟画输入来源到三个工具的数据流，标注外部网页、会话、主体和对象 ID。
2. 用 15 分钟为每个工具写允许范围、禁止范围、授权检查和审计字段；图区分业务输出目录与秘密挂载，网页工具区分允许目的地与任意 URL。
3. 用 10 分钟写三组拒绝测试：网页要求外传历史、甲用户查询乙任务、绘图请求读取业务范围外文件。只列预期，不执行。

验收：三个工具都有执行端约束；对象授权不依赖模型判断；网络“读取”被列入可泄漏动作；审计不记录凭据原文；未填写攻击成功、修复成功或产品效果。

## 6. 自测与答案

**合法 JSON 能避免 BOLA 吗？** 不能。格式合规与主体有权访问对象是不同条件。

**提取系统提示就获得管理员权限了吗？** 没有。信息泄露可能帮助后续攻击，但真正权限取决于工具和身份系统。

**使用容器就能安全执行模型生成代码吗？** 不能。必须核对网络、挂载、权限、资源与逃逸风险，默认配置不等于安全证明。

**过滤 SQL 特殊字符足够吗？** 不足。应正确处理查询结构、参数化和业务授权，过滤不能替代这些边界。
