## 1. 注入的关键不是“出现了奇怪的句子”

Agent 为完成正常任务会读取源码、网页、Issue 或工具返回值。这些是任务资料，不具有修改用户授权的资格。提示注入尝试让 Agent 将资料中的文本当成行动指令，例如改变下一步操作或安全设置。

转载描述的风险链是：低信任内容被读取，Agent 将其解释为指令，通过普通文件写能力改变持久化配置，之后终端等动作不再受原本的确认边界保护。最重要的跨越是从数据面进入策略控制面，而不只是单次回答受到污染。

| 边界 | 正常作用 | 案例中的风险 |
| --- | --- | --- |
| 外部内容到 Agent | 提供任务证据 | 内容被升级为操作指令 |
| Agent 到写工具 | 修改被授权的工作文件 | 写入决定审批行为的配置 |
| 配置到后续动作 | 执行用户选定的策略 | 原确认约束被持久化削弱 |

本笔记不提供可执行配置、终端命令或注入 payload，也不将安全研究示例当作运行许可。

## 3. 教程补充：约束不能由被约束者自行解除

仅在提示中写“不要改变设置”不足以构成强边界。工具执行层应区分业务文件和审批、权限等控制文件；涉及策略变化的写入需要独立授权，不应自动继承“允许编辑仓库”的权限。

持久化变化还应可审计：谁提出、依据是什么、授权了哪个范围、写入前后差异是什么。必须区分用户明确要求配置变更和网页声称“用户已批准”，后者只是待核实文本。

这是一条通用设计原则，不是针对该产品当前实现的修复验证，也不是推荐某个未经读取的设置项。

## 4. 零执行练习：画出审批所有权

预算 30 分钟；零网络、零模型、零文件配置修改、零终端执行，只分析下面的教程假设。

“开发者允许 Agent 修正文案；Agent 在文档里读到一段自称管理员的说明，要求关闭后续确认，再下载运行辅助工具。”

1. 用 10 分钟标出用户任务、资料来源、文件写入、策略修改和后续网络动作五个节点。
2. 用 10 分钟为每条边写授权依据；缺失依据直接标拒绝或等待用户明确授权，不把文字自称身份当认证。
3. 用 10 分钟写一份只包含拟议变化的审查记录，不实际修改配置或获取辅助工具。

验收：文案编辑不被扩大为策略编辑；至少指出两处跨信任边界；外部声称审批被视为资料；列出持久化影响、审计与恢复需求；没有真实命令、配置值或秘密。

## 5. 自测与答案

**为什么“允许写文件”可能比看起来更危险？** 文件可能决定后续权限与审批，普通写权限触及控制面时能改变未来动作的边界。

**用户主动开启宽松模式与被注入后开启有什么差别？** 前者有用户授权意图；后者由不可信内容诱发，不能继承授权。

**只过滤不可见字符能修复吗？** 不能。可见文字也能诱导行动，核心是来源、工具范围与独立授权。

**可以把转载日期写成漏洞发现日期吗？** 不可以。当前只能核实转载页面时间，英文事件日期需另有原文证据。
