### 参数化查询与搜索契约

SQL 注入的根因是输入被解释成 SQL 结构，绑定参数让它保持数据角色；不是删除引号。当前 `.contains(q)`仍使用 LIKE 语义，没有指定通配符自动转义，所以 `%`、`_`可以影响匹配范围，但不因此变成 SQL 语法执行。要区分 SQL 注入和字面搜索契约；SQLite 全 Unicode 大小写行为未验证。

笔记查询 q 最长 200、skip 非负、limit 1–200；sort 最长 32，从 id/title/时间列白名单中选，未知值回退 created_at，多个前导 `-`也会被 lstrip 去掉。行动项有类似过滤和排序，未添加同值时 ID 次序。白名单避免任意列表达式，不证明错误排序值被严格拒绝或分页在数据变化时稳定。条数上限不等于响应字节、查询时间或数据库总量预算。

[schemas.py](../../../../_assignments/2025%20fall/week6/backend/app/schemas.py)限制标题 1–200、正文 1–20,000、行动项描述 1–2,000；未做 trim，空白字符串仍可能满足长度。Patch 的 None 表示不修改，未知额外字段没有显式 forbid。类型/长度是部分输入约束，不等于完整业务规则或 HTTP 请求体的执行层字节上限。当前八项业务操作没有用户身份与资源归属绑定；本地单用户快照不能因使用 ORM 就直接作为公开多用户服务。

### 文本 DOM、CSP 与浏览器回归

`textContent`和`createTextNode`在这些位置不把用户笔记当 HTML；静态节点与数据分离是主要根因防护，`replaceChildren()`本身只是清空节点。HTML 将样式移到外部 CSS、脚本 defer，当前 CSP 限制 self 来源并禁止 object/frame 等；self 不代表所有同源脚本可信，CSP 也不替代安全输出、授权或富文本净化。

原报告描述通配 CORS 加凭据时“任意站点跨域调用”，实际需分清浏览器响应可读性与请求可发送性，不能脱离浏览器规则直接断言所有带凭据响应可读。即使无允许来源头，某些简单请求仍可送达并产生副作用；非浏览器客户端不受 CORS 约束。允许列表不是认证、对象授权或完整 CSRF 机制。

前端 fetchJSON 抛错后没有用户可见恢复或按钮锁，加载前清空列表，失败可留下空界面；交叠响应可追加过期结果。创建成功后 reset 并重新加载会丢当前筛选；初始行动项无过滤，勾选后只看完成，取消则只看未完成，创建后又无过滤。安全 sink 改正不证明功能、失败恢复和筛选体验未回归。CSS 仅 flex 布局，未见窄屏换行策略；浏览器、移动端、键盘与可访问性均未运行验证。

### 配置、防护层与部署条件

CORS 配置显式拒绝独立 `*`项；ALLOWED_HOSTS 列表则没有同样的通配拒绝，环境配置仍可扩大 Host 范围。TrustedHost 检查 Host，不检查当前用户，也不代替网络访问控制。限流 key 是 get_remote_address，真实代理如何传递/信任地址、SlowAPI 的实际覆盖、共享存储和多进程一致性本批未读 SDK 或运行验证；源码 `60/minute`只证明配置默认意图，不证明整个服务已经达到该限额或防住分布式资源耗尽。

安全响应头在 call_next 返回后添加；当前四项头测试不证明框架异常、静态资源和限流响应全部覆盖。HSTS 仅 request.url.scheme 为 HTTPS 时设置，不启用 TLS；代理协议识别须按实际部署验证。includeSubDomains 的适用范围也需部署方确认，不能照搬到不支持 HTTPS 的全部子域。

源码移除秘密不撤销历史凭据；真实泄漏应授权吊销/轮换、调查历史和访问、修复渠道。本批没有读取或公开历史令牌。MD5 风险还取决于原用途，普通摘要、密码存储、签名认证不可混为同一威胁；由于旧接口实现未取得，不能仅报告名字重建可利用性。依赖升级需公告、实际解析版本、调用可达性与回归，不把旧或新版本“明显”如何当实证。

## 3. 启动、数据与提取边界

main 导入时创建相对 data 目录、挂载相对 frontend；db 导入时 load_dotenv 并选择 DATABASE_PATH 与全局 engine。startup 先 create_all，再分别检查 notes/action_items 是否为空，各自为空就补两条演示行。与第 5 周“两表同时为空才 seed”不同，本周只清空其中一表，重启也可能重新填充该表。自定义数据库父目录没有创建保证，直接 make seed 先查询表，未初始化数据库不保证可用。create_all 不是数据库迁移。

get_db/get_session 成功 commit、异常 rollback、最终 close；路由 flush/refresh 不等于最终提交。实际响应与提交时序依 FastAPI 版本及退出路径，未运行。两表没有用户归属或笔记与行动项关联，不把其他周的 Tag、批量操作、关联级联带入这个快照。[seed.sql](../../../../_assignments/2025%20fall/week6/data/seed.sql)只有固定建表与演示值；文本含 SQL 或使用 text() 本身不充分证明用户输入注入，当前启动也没有加载此文件。

纯规则提取按 splitlines 后 `.strip('- ')`去两端指定字符，再认大小写不敏感 TODO:/ACTION: 或末尾 `!`，无模型、无去重。它不只是移除一个 Markdown 前缀，会改变末尾空格/连字符；重复 TODO 仍重复，空 checkbox 本身不识别，完成 checkbox 末尾 `!`仍可能被选。当前路由没有提取端点，所以通过该函数测试不证明 HTTP 提取、保存或模型安全；不要把第 5 周的 apply/幂等功能当成本周实现。

## 4. 测试证明多少

四份测试模块共有七个测试函数，另有 conftest fixture。笔记和行动项各一函数检查部分 CRUD/筛选；提取一函数检查三个包含断言，没有严格断言全集。四个安全函数检查一条 SQL 元字符查询、一页的部分安全头、一种不可信来源预检，以及五个 debug 路径的 GET 404。静态断言有价值，但本批没有实际通过结果、覆盖率、改前失败或浏览器证据。

[conftest.py](../../../../_assignments/2025%20fall/week6/backend/tests/conftest.py)先导入真实 app，后建临时请求库并 override get_db；TestClient 上下文仍运行 app startup 的原 engine 和 seed，因此请求隔离不等于启动隔离，原应用数据库可能被创建或写入。cleanup 没有 finally 保障、override 恢复或 engine.dispose，Windows 文件句柄行为未验证；全局 limiter 状态也没有显式重置。运行原测试前必须在获准副本建立导入、启动、环境文件、存储和限流隔离，不能先执行再确认。

缺失项包括长度/空白/额外字段、LIKE 通配契约、正常与可信 CORS、简单请求副作用、非法 Host、429/窗口恢复、代理/多进程配置、HTTPS/HSTS与异常头、真正浏览器文本显示、旧功能兼容、迁移/提交失败、历史秘密处置和真实依赖公告。五个 GET 404 不覆盖全部方法或整个代码库；没有原始扫描和旧快照，不能说扫描确认了这些七个测试对应的全部修复。

## 5. 获准复现的顺序与离线替代

1. 先冻结个人练习副本基线、假数据、配置、扫描政策与依赖方案；禁止生产凭据和公共监听，先核对测试启动隔离。工具/规则下载、云端扫描、AI 调用与运行需独立授权。
2. 取得实际扫描记录后逐条追踪 source、sink、可达条件与资产，分确认漏洞、误报、加固建议、待验证，按根因去重。工具退出、规则未启用或范围变化导致“消失”不能填成已修复。
3. 每项保留改前证据、最小改动、AI 实际角色、改后同条件复扫及正常/对抗回归；依赖补公告与解析版本，秘密补撤销状态。没有三项真实扫描问题就如实记录，不能用当前报告或纸面推测凑原作业成果。

教程扩展：50 分钟，零网络、安装、规则下载、扫描、模型/Agent、测试、服务和数据库写入，仅纸面假数据，不编辑原作业。

1. 10 分钟填三张证据卡：绑定 q、文本 DOM、CORS 预检拒绝；分别写源码定位、已知机制、报告自述、尚缺扫描与运行证据。
2. 10 分钟手算三条提取输入：`- TODO: ship -`、重复两行 `TODO: ship`、`- [x] done!`。写精确预期和它与业务需求的区别，不执行函数。
3. 15 分钟为假 SQL 元字符/`%`、字面标签笔记、跨源简单 POST 各写正常与风险回归计划，区分绑定、匹配、显示、响应可读和状态写入；不含可执行攻击或真实秘密。
4. 15 分钟画导入→临时请求 override→真实 startup 的两条数据库路径，再列三项扫描修复应留的规则/版本/范围/前后差异/复测/公告或撤销证据。未知、未运行照实填写。

验收为三张证据卡、提取预期、回归计划与双数据库路径图。三组提取预期分别是 `TODO: ship`、两个 `TODO: ship`、`[x] done!`；这是静态手算，不是实测。至少指出通配搜索不是 SQL 结构注入、CORS 拒绝读响应不保证阻止写入、override 不隔离 startup。纸面成果不满足原作业的真实扫描、AI 修复和测试要求，也不证明系统安全。

## 6. 自测与关联

**问：固定 SQL 种子被规则标记就一定有注入吗？** 不一定，需读外部输入到 SQL 结构的数据流；规则审计提醒与确认漏洞分开。将固定种子改 ORM 可以统一实现，不反证旧种子必可利用。

**问：CORS 不返回允许来源头，攻击请求就绝对没到服务吗？** 不能这样推断，浏览器预检、简单请求、响应读取与服务副作用是不同阶段，非浏览器客户端也不受 CORS 限制。

**问：requirements 精确锁定就能写“已消除漏洞并完全可复现”吗？** 不能，尚需传递解析/锁定、平台制品、安全公告和回归；核对日也没有重新扫描这些版本。

**问：临时请求数据库加七个测试足以证明三项修复吗？** 不足，startup 仍可写原库，断言范围有限，也未提供扫描、改前失败与实际执行证据。
