## 1. 来源与精选范围

原文：*AI-Assisted Assessment of Coding Practices in Modern Code Review*，Manushree Vijayvergiya、Małgorzata Salawa、Ivan Budiselić、Dan Zheng、Pascal Lamblin、Marko Ivanković、Juanjo Carin、Mateusz Lewko、Jovan Andonov、Goran Petrović、Daniel Tarlow、Petros Maniatis、René Just。研究主要在 Google 开展，Just 的署名机构为 University of Washington，页面注明工作在 Google 完成。

实际精选：摘要、第 1–6、8 节的正文及第 3.1 节 Go 输入/输出例。第 7 节仅核对相关工作讨论，不展开底层文献；致谢、参考文献未逐条精读。图 1–6 只读图题及正文明确说明，图片未视觉核验，图中未写入正文的值、布局和界面细节不计已读。没有读取内部数据、源码或复现训练、部署与 A/B 实验。这是中文教学解读，不是官方译文或论文全文/图示完整核验。

目标是分清“学习实践规则”“确认功能正确”“实际减少审查工作”三个问题。AutoCommenter 针对编码最佳实践，而不是覆盖全部需求、授权、业务逻辑或生产故障的通用裁判。

## 2. 第 1–3 节：预测位置与规则，不是自由写评论

作者将格式、命名、文档、语言特性和惯用法列为编码实践。确定性格式适合 lint/formatter；带例外的规则、注释是否清楚等仍需要判断。系统希望及时提供这部分反馈，让人工更多关注整体功能，不取代同伴批准。

模型是基于 T5、T5X 的多任务 text-to-text 系统。正文报告总训练语料超过 30 亿例，实践分析约 80 万例；这些是作者历史报告，不是本教程训练量或当前商业模型参数。训练任务还包括 span denoising、评论解决、下一步编辑、变量重命名与构建错误修复。

输入是固定任务说明加一个文件源码，超上下文会截断；目标是代码字节位置及违反实践的 URL，无违规时可为空。模型另外输出 0–1 置信分数。自然语言评论由规则文档摘要等服务层组织，不应误读为模型只需凭感觉给一段建议。

原 Go 案例的函数名是 `Add`，注释却以“Return a sum”开始。输出形如 `INSERT 153 COMMENT https://go.dev/doc/comment#func`，153 是该输入对应的字节偏移，规则要求函数注释通常以函数名开始。这个数字不能复制到另一个文件；Unicode、前置任务说明、编码或源码版本改变都会影响定位。该例不是函数求和逻辑错误的证明。

训练数据从真实人工评论中筛出包含实践 URL 的条目，再收集对应源码、位置与创建时间。昂贵的大规模预处理与按需样例构造分开，便于改变表示时不重做全量抽取。按时间划分训练与评测，避免未来快照泄漏；但人工评论不是违规全集：遗漏 URL、只评论一处、知识和关注点差异都会造成标签缺失。

因此“预测未匹配人工评论”不一定是误报，匹配也不是完整业务正确性。历史评测除了位置/URL 匹配，还离线统计整份变更可能产生的评论量，不向旧 PR 真正发帖。学习指标与开发者实际承受的噪声必须分别评估。

## 3. 第 3.4–4.2 节：服务层、阈值、变更范围和规则失效

中心分析服务构造模型输入、查询模型、执行过滤，再向 IDE 或审查系统返回发现。IDE 要求低延迟；审查系统在新快照后运行。正文说明人工仍可要求处理某条评论，模型发出发现不直接获得合并权。界面按钮仅按文字说明理解，未查看图像或使用内部工具。

首次推广用高阈值 `0.98` 保护信任，但人工抽样发现阈值以下仍有很多正确项；语言级阈值也不足以表达不同规则 URL 的分布，后来改为按 URL 校准。分数不天然是各语言、规则共享的正确概率。校准目标应同时考虑正确、可行动、噪声和遗漏，不能照搬历史阈值。

原文的解码对照有重要范围：greedy 加规则阈值在 6% 变更文件发现违规，但约 80% 评论落在未改动行；过滤这些行后比例降至 1.3%。beam search 生成四个候选，比例增至 3.9%，前十个 URL 集中度从 80% 降至 41%；中位延迟约两秒，于是审查系统用 beam，IDE 保留 greedy。这里比较的是作者部署中的发帖频率、规则多样性和延迟，不是证明“四个 Agent 召回率提高三倍”。

规则也有生命周期。Python 3.9 类型名称的规范来源发生变化，旧训练评论仍影响新预测。团队没有等待重训才处理，而是条件过滤特定规则预测，以源码正则实现细粒度抑制。动态抑制可以迅速止损，但不能证明模型已学会新规则，恢复前仍需评测。

教程补充：行动项项目的旧规则若要求“所有失败都返回错误”，而新契约允许明确规则降级，就需版本范围、例外和废弃记录；不能靠 Agent 高信心把旧规范重新强加到现行代码。确定的安全违规不因“不在 diff 中”消失，是否另立修复任务由项目风险政策决定，这不是作者的自动过滤规则所能裁决。

## 4. 第 4.3–5 节：有用、正确、解决与节省不是同一指标

早期反馈有用率约 54%。团队邀请 15 位其他团队开发者，对约 370 条有反馈评论作独立评价，不展示原用户反馈；该评价约 60%，仍低于推广目标 80%。样本已按“收到反馈”选择，不能代表所有评论或全部用户。

原失败案例包括：一个 URL 含多条规则，摘要未说明具体违反哪条；库设计本来依赖 flags 却被建议禁止；把 `push_back`/`emplace_back` 的建议套到适用例外或无关类型；注释少句号虽形式正确，却不值得一次上下文切换。团队抑制 17 个不可行动 URL、再抑制五个类似 URL，并人工更新常见摘要，才达到下一阶段的有用率目标。核心机制是规则与服务层校准，不是“用户点赞后模型自动在线学习”。

2023-07 的开发者级随机 A/B 对照没有检测到审查总时长、实际审查投入、评论往返轮次的统计显著改变；观察到轻微编码速度改善，减少文档切换只是作者解释假设。不能把摘要的“正面影响”译成“审查耗时已显著下降”。总体部署从 2022-07 早期采用到 2023-10 广泛开放，绝对数量因保密未披露。

| 原指标/结果 | 真正的分母和边界 |
| --- | --- |
| 有用率超过 80% | 有正/负反馈的评论集合，不是所有评论的正确率 |
| 显式反馈约 10% / 2% | 审查评论 / IDE diagnostics 分别的反馈覆盖率，不是解决率 |
| 估计解决率约 40% | 6000 快照对中约半数评论消失，再对其中 40 对人工抽样，约 80% 是直接解决；两阶段估计，不把消失全算修复 |
| 330 个规则 URL，覆盖 68% | 这些 URL 覆盖历史带规则链接的人工评论，不是全部 bug 的召回率 |
| 33/50 规则超出传统静态分析范围 | 高频前 50 URL 的专家分类，不是所有规则、所有漏洞或所有现代工具能力 |

第 6、8 节强调补充传统分析、离线与线上评测可能背离、信任与反馈的重要性。接受或抑制一条规则是可行动性治理，不直接等于安全性或业务价值验证；私有数据及单一组织的结论也限制可迁移性。

## 5. 有预算的零执行练习

教程扩展：40 分钟、零网络/模型/训练/PR/程序执行，只做纸面记录。不访问 Google 内部系统，不执行原代码。

1. 0–10 分钟：为“函数注释不以函数名开头”“类型规范已废弃”“跨用户更新缺身份检查”“未改动行少句号”四条假发现写位置标签、规则版本、适用条件、行动价值与人工职责。将前三类区别于确定性格式；高风险身份问题不能归成命名建议。
2. 10–20 分钟：设计按规则版本过滤的决定表，包含输出、抑制、待确认和停止。规则 URL 无法确认或源码位置过期时不自动发布评论；写明抑制不等于修复。
3. 20–30 分钟：给十条假评论标注两条点赞、一条反对、七条无反馈。有用率是 `2/3`，反馈覆盖率是 `3/10`；真实正确率未知。另给二十条中十条消失、抽查消失的五条中四条直接解决，计算教学估计 `10/20 * 4/5 = 40%`，保留小样本和抽样局限。
4. 30–40 分钟：预写 IDE 与异步审查的延迟、评论量、误报、遗漏、人工投入及停止条件空表，设计同基线对照，不填收益。不得同时改变模型、阈值、输入和人工流程后归因单个因素。

验收：四条分类记录、版本过滤表、两个反馈分母及解决估计、未运行指标表。只验证概念与计划，不能据此声明训练效果、规则过滤安全或节省时间已实测。

## 6. 自测与章节关联

**问：68% 是系统发现全部代码缺陷的召回率吗？** 不是，它是已使用规则 URL 对历史带链接人工评论的覆盖；完整缺陷集合未知。

**问：评论在最终快照消失，能算已修复吗？** 不能直接算，位置变动或无关代码修改也会使模型不再预测，需要映射和人工确认。

**问：正确意见都应发给作者吗？** 不一定，适用例外、改动范围、摘要和行动成本影响价值；但严重风险不应为了高接受率而被隐藏。

**问：A/B 证明审查过程更快了吗？** 文中没有检测到相关审查指标的显著变化，不能作该结论。
