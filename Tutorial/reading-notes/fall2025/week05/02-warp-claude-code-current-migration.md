## 1. 先区分运行环境与 Agent

官方页首先说明 Claude Code 是可以运行在终端中的 CLI Agent，不是终端模拟器；Warp 则是带终端、编辑、审查与协作的开发环境。因此不是只能二选一，而是两条路径：在 Warp 终端继续运行 Claude Code，或改用 Warp 内建 Agent Mode。

这个区分避免“换了终端就换了模型”的误判。使用同一 CLI 时，Agent 身份、认证与请求链仍由该 CLI 负责；改用内建 Agent 时，则需要核对另一套规则发现、模型选择、工具与权限。环境提供更好的展示，不能自动提高同一 Agent 的正确率。

## 2. 路径 A：继续用 Claude Code

源页列富输入、通知、内联审查、带状态的垂直标签页、远程控制和布局保存。通知要求一次性插件安装，其他功能也链接进一步说明；本文仅取得功能说明，不读插件代码、不核验默认权限，也不自动安装。

源页提醒在 terminal mode 而非 Agent Mode 输入 CLI；提供多行输入与 bracketed paste 说明。这体现输入通道决定如何解释按键和粘贴，但本次没有键盘或平台验证，不把快捷键写成所有版本一致的操作契约。

关键恢复边界是“恢复标签页/面板”不等于“恢复运行进程”。官方页明确 Warp 重启保留布局，但关闭 Warp 会结束 CLI 会话，继续对话需使用 Claude Code 自己的恢复能力。布局状态、对话状态、进程状态和业务副作用是四个不同层。

认证段声称 Claude Code 自行处理 API key/Anthropic 账户，Warp 不代理或修改其网络请求。它仍只是该官方页的说明，不是本次网络测量。原页建议通过 Warp Drive 环境变量配置 key；本教程不复制秘密、不默认同步凭据，也未取得该功能的数据政策，团队使用前须另审查可见范围和存储方式。

## 3. 路径 B：改用 Warp Agent

源页描述自然语言任务后读取仓库、运行命令与改文件，并列上下文来源：Git 跟踪文件索引、全局/项目规则、Warp Drive 保存对象、固定文件/笔记本、MCP 外部工具与数据。

索引 Git 跟踪文件不是所有文件都已进入上下文，保存对象“可作为上下文”也不证明全部已读。MCP 接入提供能力入口，不自动具有所有资源权限。终端环境和历史可能包含敏感信息，丰富上下文也扩大了必须审查的数据范围。

源页说根 `AGENTS.md`/`WARP.md` 是规则入口，并建议将 `CLAUDE.md` 改名或复制为规则。迁移时不能机械执行：原规则可能包含 Claude 专用命令、发现路径、Hook、历史快捷键和假设；名称映射不能证明语义等价。需保留权威原文件、逐条核对和独立验证，不覆盖仍使用 Claude Code 的团队规则。

源页进一步要求重新配置 MCP、选择模型和 profiles/permissions；这说明自动读取文本不等于自动迁移可执行集成。旧批准、OAuth 授权和模型预算不能默认为新 Agent 有效，本次不进行这些操作。

## 4. 功能对应不是可执行兼容

| 官方页对应关系 | 可学到的职责 | 本文保留的验证问题 |
| --- | --- | --- |
| `CLAUDE.md` 到 `AGENTS.md`/`WARP.md` | 规则需要符合目标客户端入口 | 发现、覆盖顺序、旧专有指令是否等价？ |
| 斜杠命令到 Warp 命令/保存提示 | 可复用触发与任务模板 | 参数替换、触发、权限和失败传播如何验证？ |
| Tool definitions 到 MCP | 能力需要真实工具契约 | 原本非 MCP 工具能否直接迁移，schema/认证是否相同？ |
| `.claude/skills/` 到支持的 Skills 目录 | 页面声称可以发现既有目录 | frontmatter、脚本执行环境与运行时能力是否匹配？ |
| `.claude/agents/` 到云编排/factory agents | 专业角色可在另一层实现 | 文件格式、嵌套、消息和预算不因此兼容 |
| 恢复对话到标签页持久状态 | 对话与布局各有存储 | 是否恢复进程、未提交差异和外部操作？ |

尤其 Subagent 映射到云编排并不是“本地文件不改即可运行”的证明。源页说同时运行多个标签页各有自身状态，但没有给每个任务的文件、端口、数据库和账户隔离机制。不能从 UI 分离推断并发写安全。

## 5. 源情境与教程补例

原页面的具体情境是使用者在两条迁移路径间选择、处理多行输入/通知/重启，以及将已有规则、MCP 与技能概念映射到目标环境；没有给独立项目的性能比较或测试结果。内建审查面板、终端集成和云编排是产品定位，不是“Warp 必然胜过 Claude Code”的研究结论。

教程补例为开发者控制中心：A 路径在同一假仓库使用 Claude Code，仅改变终端呈现；B 路径使用 Warp Agent，必须重新核对读取范围、工具、规则与输出契约。两条路径都先只读假路由摘要，要求返回可定位依据，不运行数据库。比较固定目标、相同输入与全部失败记录，不用快捷键多少代替质量。

## 6. 零执行练习与验收

教程扩展，35 分钟，零网络、安装、模型、费用，仅纸面走查，不改规则名、不创建配置/工作区、不启动产品、插件、云任务或数据库。

1. 10 分钟写 A、B 两张路径卡，分别列终端、实际 Agent、认证主体、规则来源、可用能力与仍未验证部分。
2. 10 分钟审查三条假旧规则：“用专有斜杠命令同步文档”“不读真实凭据”“后端入口路径”。区分需重新配置、需执行层落实、可保留但需核对的条目。
3. 10 分钟走查“恢复标签页但进程已结束”“两个标签页同写 schema”“旧 MCP 身份没有迁移授权”，分别置为待恢复、冲突阻塞、未授权。
4. 5 分钟写迁移验收表：规则发现、同输入只读输出、错误分支、共享资源和凭据范围都写未运行，不伪填通过。

验收交付是两张路径卡、三条规则审计、三路阻塞状态和未运行矩阵。必须能指出“运行在 Warp 里的 Claude Code”与“Warp Agent”不等同，布局不恢复进程，规则改名不证明权限与执行兼容。

## 7. 自测与答案

**问：历史课程入口返回概览，是否完成原对比阅读？** 否，本文只完成当前官方迁移指南的补充解读。

**问：换终端意味着 Claude Code 的认证由 Warp 负责？** 按此官方页，不意味着；实际链路仍需独立核验。

**问：改名 `CLAUDE.md` 即可证明全部行为迁移？** 不可，文件发现与语义、命令、工具、权限须分别核对。

**问：多标签页具有独立状态是否足够避免并发冲突？** 不足，文件、接口、端口、数据库、全局设置和账户仍可能共享。

**问：有恢复布局就可以说后台任务继续运行？** 不可，源页明确布局与 CLI 进程不同；还需确认运行状态与副作用。
