## 1. 来源与范围

来源为 DAIR.AI 维护的 [英文技术入口](https://www.promptingguide.ai/techniques)及[中文入口](https://www.promptingguide.ai/zh/techniques)，核对日期 2026-11-05。这是教学指南的中文解读，不是原论文译文。

本批完整读取下表六个技术子页的英文与中文正文，包括文字示例、结果解说与局限。未读取其余技术页、论文、notebook、SDK 或全站；图片未视觉核验。页面未提供本批可核验的逐页发布日期或个人署名，不把页脚年份当实验日期。一个指南仍计一个指定阅读条目，完成状态仅指下列精选范围。

## 2. Few-shot：示例约束任务，不等于训练权重

原页先用虚构词解释一次示范如何给后续回答提供任务格式：展示一个新词的定义和用法，再要求另一个新词的用法。这是上下文中的条件信息，不是立即更新底层权重；单个展示输出不证明模型稳定学会了规则。

原页转引 Min 等研究，强调标签空间、输入分布和格式，即使部分标签随机也可能产生帮助。原研究未读，不能推出“业务标注随便填也没关系”。用于行动项提取时，应选准确的正反例，涵盖已完成、否定执行、明确未来任务等边界；不把留出集放入提示。

原案例要求判断 `15, 32, 5, 13, 82, 7, 1` 中的奇数之和是否为偶数。页中失败输出说总和是 107 且是偶数。独立算术核对为 `15 + 5 + 13 + 7 + 1 = 41`，107 也不是偶数。因此这段有“计算错误”和“奇偶判断错误”两类失败，不应只看最后标签。

## 3. CoT：最终标签正确，中间结果仍可能错

CoT 页将少样本示例扩展为“选出奇数、求和、判断奇偶”的可读步骤；零样本部分用苹果增减演示增加逐步处理提示；Auto-CoT 部分描述先聚类问题，再选代表问题自动产生示例。

苹果题可独立核对为 `10 - 2 - 2 + 5 - 1 = 10`，原页未加逐步提示的展示输出为 11，加入后为 10。这是一个可检查的对照示例，不是总体效果评测；原研究、自动聚类实现和图示没有复核。

对目标奇数题，CoT 输出给出 41 和 False，算术与标签都正确；指南称该展示得到“完美结果”，只支持这条展示输出，不支持所有题或现代模型必然改善。可读解释不是内部计算的忠实日志，也不是形式证明。自动生成示例若未经验证，会把错误变成下一轮的学习条件；页中 60 tokens、5 步是转引的启发式，不是通用预算标准。

## 4. Self-consistency：聚合答案，不制造独立证据

原页用年龄题比较三个输出：叙述者 6 岁时妹妹 3 岁，叙述者现在 70 岁；两个输出给 67，一个错误地继续按一半年龄给 35。按年龄差保持 3 岁的条件，答案为 67。

页面只是用少数输出说明多数答案如何出现，没有给本批可复现的采样配置、总体成功率或完整聚合实现。实际评测需预先规定采样数、答案规范化、平票和无效输出处理；三次同源生成不是三个独立事实来源，增加样本也可能放大共同错误。行动项列表尤其不能对整段文字直接投票，改写后仍可能表示同一任务。

## 5. RAG：知识库更新与模型训练分开

RAG 页把检索器、外部索引和生成器连接起来：按问题找支持文档，将文档与问题放入上下文，再生成回答。原文同时介绍历史 seq2seq 与 Wikipedia 密集索引方案，并转引基准效果；不代表今天所有 RAG 都采用同一训练或索引实现。

更新外部文档可以改变模型本轮能访问的证据，不等于训练权重已更新，也不保证检索结果最新、权威或足以回答。用于项目 API 时，需核对依赖版本和文档支持范围；没有答案就保留未知，不能借引用样式掩盖编造。

中文版与英文主要机制对应，但中文版没有英文的论文标题生成 notebook 小节及新增参考列表，改为链接 LangChain 问答例子。本批未读这些实现，不能据此填入当前 SDK 操作或称双语所有扩展一致。

## 6. ReAct：行动与观察形成闭环

原页的机制是交错生成任务分析和动作，动作从环境取得观察，再据此决定下一步。原文字案例先搜索科罗拉多造山带，随后定位东部延伸区域，发现 High Plains 有歧义后补充美国限定，再取得海拔信息。这里的价值是根据观察修正检索目标，不是给每个步骤强制写长解释。

页面报告 ReAct 在 FEVER 优于 CoT、在 HotpotQA 落后，并指出无信息搜索结果可能使它难以恢复。这与“ReAct 一定优于其他技术”不同；原论文和结果图片未读，不转录图中分数。环境观察也可能含错误或注入，执行端仍须限制路径、网络与副作用。

末尾 LangChain 示例使用 `text-davinci-003` 和旧导入形式，包含安装升级与密钥设置。本批仅阅读，不执行、不照搬成现行步骤；名人关系与年龄也是历史示例，不当当前事实。中文把 LangChain 译成“长链”，这里保留库名，避免把它误解为长推理方法。

## 7. Reflexion：反馈记忆不是在线微调

原页按三种职责解释流程：Actor 产生行动轨迹，Evaluator 给出评价，Self-Reflection 将评价、轨迹和过去记忆整理成下一轮可用的语言反馈。评价可以来自模型、规则或环境，不是三个模型服务必须各用独立账号的部署要求。

原页明确无需微调底层模型。这里“学习”主要指反馈进入后续上下文或记忆；不要与权重训练混淆。错误评价同样会留下错误记忆，例如测试仅验证格式，却反思成“业务正确”，下一轮可能沿用错误结论。

正文提到 ALFWorld 的 130/134 等结果，本批未核验论文、图表和完整试验预算，不作为本教程准确率。中文版把 “traditional RL methods are impractical” 写成“传统的强化学习方法失效”，含义更强；本文按英文理解为某些场景不适于采用，而非强化学习已经无效。中文“人物”等文字错误不搬入机制解释。

## 8. 离线练习与验收

以下为教程扩展，预算 45 分钟、零网络和模型调用，只使用纸面假数据，不安装框架或修改原作业。

1. 为“今天发布完成”“明天请检查日志”“不要创建发布任务”写三个准确示例，并另留一条未参与提示设计的输入。
2. 独立复核奇数题的集合、总和与标签；为三个假答案 `41/False`、`107/True`、`41/False` 写聚合规则，并说明多数意见能证明什么。
3. 对假 API 问题准备两条不同版本的文档描述，写选证据和表达未知的条件，不生成不存在的引用。
4. 画出最多两次只读检索的动作/观察记录；首次无信息时允许修正一次，仍不足则停止。
5. 把“仅 JSON 格式通过，业务未测”变成下一轮反馈，保留独立验收未运行状态。

验收是一张“机制/输入证据/失败类别/额外预算/停止条件”表及算术核对，不填写模型准确率、实际调用成功或权重已更新。该练习验证理解，不能证明哪种技术最优。

## 9. 自测与关联

**问：随机标签示例有时有效，能省掉准确标注吗？** 不能，转引研究范围不等于业务标注政策；仍需独立数据与验收。

**问：三个答案一致是否等于三份事实证据？** 不是，它们可能共享模型、上下文与错误假设。

**问：Reflexion 的长期记忆是否自动保证跨会话可用？** 不保证，需要具体持久化和加载实现，本批未验证。
