## 1. 目标、环境与原评分

本周通过六个小任务观察“提示、生成、解析、验证”的链路。重点不是记住某个模型的固定答案，而是辨认提示提供了什么信息、执行器实际做了什么、通过条件证明了多少。

[assignment.md](../../../../_assignments/2025%20fall/week1/assignment.md)原要求是完成 TODO 提示位置，不调整模型，迭代直至脚本通过，保存每种技术最终提示及输出，提交六个文件的完整代码。六种技术各 10 分，共 60 分。当前六个脚本已包含实现，不能假定仍有 TODO，更不能清空现有代码以重做。

[根安装说明](../../../../_assignments/2025%20fall/README.md)建议 Python 3.12、Conda 与 Poetry；[pyproject.toml](../../../../_assignments/2025%20fall/pyproject.toml)声明 Python `>=3.10,<4.0` 和 Ollama Python 包 `^0.5.3`。建议版本与依赖允许范围是不同概念，不证明所有允许版本都实际兼容。依赖根是 `_assignments/2025 fall/`，不是整个中文课程仓库根目录。

原作业通过 Ollama 本地运行 `mistral-nemo:12b` 与 `llama3.1:8b`。首次获取模型需要网络、磁盘与下载授权，本地推理仍有计算资源成本；模型名称不锁定模型文件摘要。这里没有核验当前下载入口、硬件需求或现行客户端行为，不复制安装脚本作为已验证操作步骤。实际复现前应按第 00 章记录版本、模型身份、资源预算和访问条件。

### 少样本：格式匹配与泛化分开

系统提示用 cat、hello、prompt、OpenAI 演示字符逆序，用户输入固定为 `httpstatus`。例子教操作与输出契约，精确匹配适合这个确定性小任务，但只覆盖一个目标单词。若五次中一次通过，脚本报告成功，不代表五次均正确，也不代表能处理 Unicode、空输入或多词句子。

教程扩展应在独立项目选未用于提示的字符串，并预先确定字符、大小写和空白规则。不要在原作业中改变固定模型后仍声称遵循原要求。

### 思维链：提示已经给出解法和答案

当前系统提示直接写出 `3^20 ≡ 1 (mod 100)`、`12345 mod 20 = 5`、结果 43 及最终答案标签。可独立核对 `3^10 mod 100 = 49`，所以 `3^20 mod 100 = 1`；本题因此约为 `3^5 mod 100 = 43`。这解释本题计算，不把提示中的断言当作证明，也不需要先证明 20 是最小周期才能约减。

答案提取器查找最后一个答案标签，并从其内容取第一个数字。例如教程构造输出 `Answer: 43 or 99` 可被规范化为 `Answer: 43`。因此通过检查不仅不能证明独立推理，还不能证明严格遵守“最终行恰好只有一个答案”的格式。长解释不是内部思考的忠实日志；应另核验中间事实及无泄漏新题。

### 工具调用：模型提议与 AST 读取分开

系统提示已经给出完整 JSON 调用；模型返回文本，`extract_tool_call` 解析 JSON，`execute_tool_call` 通过注册表找函数并执行。这是文本 JSON 的教学链路，不是已使用原生 function calling 或 MCP 协议的证据。

工具只遍历 `tree.body` 中的 `ast.FunctionDef` 并读取返回注解，不执行被分析文件，也不推断函数真正返回值。嵌套函数、类方法与 `AsyncFunctionDef` 不在当前选择范围；缺少注解会显示字符串 `None`，不能据此认定函数运行时只返回 None。

执行器验证工具名和 args 对象，但不构成完整 schema 校验：合法 JSON 可能是数组；多余参数可导致调用异常；绝对路径与上级路径没有沙箱限制。函数名白名单不能代替文件读取授权。预期与实际使用同一实现，适合核对调用是否接通，却可能共同遗漏异步函数等需求。

### 自洽性：最高频不等于严格多数

停车点原题为第一次在 20 英里，第二次在 `60-15=45` 英里处，相隔 25 英里。系统提示已经包含这些步骤和 `Answer: 25`，不能用输出一致性证明多数采样改善未知题推理。

`Counter(answers).most_common(1)`选众数；没有要求计数超过一半。教程构造分布 `[25, 25, 30, 30, 40]` 中 25 只有 2/5，仍可能被选中；并列最高频时当前 Counter 保留首次遇见的先后顺序。这是实现的聚合规则，不是可靠性定律。独立练习应预先规定并列、无多数和解析失败时弃权，而不是看见结果后调整规则。

### RAG：文件选择、生成与业务验证分开

本地 [api_docs.txt](../../../../_assignments/2025%20fall/week1/data/api_docs.txt)给出示例基础 URL `https://api.example.com/v1`、GET `/users/{id}`、X-API-Key 和 200 JSON 的 id/name 字段。这是教学文档，不是授权访问某个真实用户 API；其中未定义完整错误响应和超时策略。

`YOUR_CONTEXT_PROVIDER`按关键词命中选择整份文档，没有向量检索、片段排名或输出长度预算。加载失败或缺文件时产生标记字符串并被过滤，当前实现没有注释所称的“内联片段回退”；空上下文仍继续请求模型。

`make_user_prompt`追加非 200 时 `raise_for_status()` 等要求，但 REQUIRED_SNIPPETS 只含函数名、`requests.get`、`/users/`、`X-API-Key`、`return`。基础 URL、错误处理、name 字段、返回类型和可执行性不在检查中。把五个词写进注释或字符串也可能通过；这不是正确 API 实现的证据。若真的依赖 Requests，当前直接依赖列表没有声明它，不能假设环境必然可导入。

### 反思：反馈有用，但测试与隔离不足

链路是初次生成、`exec` 装载、运行四例；失败后将旧代码与反馈加入修正上下文，最多修正一次。初次提示只给函数签名与简洁要求，修正提示才完整列出长度、大小写、数字、特殊字符与禁止空白规则。即使修正后更好，也不能把差异完全归因于“反思”：第二阶段还获得了更多规格和一次额外生成机会。

当前四例覆盖一个合法密码及缺大写、数字、特殊字符三种情况，没有分别覆盖缺小写、长度边界或空白。诊断会计算这些规则，但只有已存在用例的输出不符时才产生反馈；计算了诊断不等于拥有完整测试覆盖。评价还调用 `bool(func(pw))`，所以真值相同的非布尔返回可能被接受。

`exec(code_str, namespace)`在当前进程执行模型生成代码，空 namespace 不是隔离沙箱，注释称“受控”也不证明网络、文件或进程权限被限制。加载错误没有统一恢复路径。本批只阅读，不执行此流程；完整复现须先在自己有授权的无秘密隔离环境建立执行边界，否则选下面的纸面替代。

## 3. 复现与改进的建议顺序

1. 静态建立表格：输入、提示已知信息、解析方式、验证条件、重试或投票、失败路径。记录当前文件快照，不把已有提示当作自己的实验成果。
2. 按原作业复现时，仅在个人练习副本及获准环境中进行，保留指定模型和原限制。先确认服务、模型、依赖与资源；本导读不自动授予安装、下载、生成代码执行或提交权限。
3. 保留全部尝试，区分首次通过、至少一次通过、投票通过、修正后通过与异常中止。记录原始输出和规范化后结果，不能只截取 SUCCESS。
4. 原作业复现与教程改进分开归档。在独立实验移除目标答案泄漏，添加未见问题、独立预期、失败和边界样例；改变测试或执行器应明确为自学扩展，不伪装成只改提示。
5. 对反思设置“首次就给完整规则”的比较条件，分开比较额外信息、额外调用和测试反馈。对 RAG 先用假 HTTP 响应验收契约，再另行决定是否进行授权的服务测试。

提交要求以原 assignment 为准；本页不新增官方分数或指定远程提交渠道。脚本主入口调用返回布尔值的测试函数但不据此设置失败退出码，所以进程退出 0 不自动表示测试通过；实际复现须保留测试结果及异常证据。

## 4. 离线替代与验收

教程扩展，限制 45 分钟、零网络、零模型调用、零生成代码执行；仅纸面分析假数据，不修改原作业，不使用真实密码或 API key。

1. 用 10 分钟填写六行链路表，标记 CoT 和自洽性的答案泄漏、RAG 的字符串检查及反思的执行权限。
2. 用 10 分钟分析虚构自洽性分布 `[25, 25, 30, 30, 40]`，分别计算众数计数与是否过半，设计并列弃权策略；不要填写真实模型准确率。
3. 用 10 分钟把五个 RAG 必需词放入一段“不含可调用函数”的假文本，说明为什么可命中但不满足业务契约，再列独立验收：基础 URL、认证、name 字段、异常、返回类型与超时策略。
4. 用 15 分钟按反思完整规则标注六个虚构输入：`Aa1!xyz`、`Aa1!xyzQ`、`AA1!XYZQ`、`aa1!xyzq`、`Aa1!xy z`、`Aa1!xyzQ\t`；区分边界覆盖与运行证据，并为工具补“缺注解、异步函数、越界路径”三个测试需求。

验收交付为链路表、投票规则、RAG 误通过反例和边界矩阵。六个密码预期依次为假、真、假、假、假、假，最后一项的 `\t` 在本题表示制表符，不是两个字面字符。矩阵只证明你理解约定，不能证明真实生成函数正确或执行权限已被阻断。

## 5. 自测与答案

**问：五次里一次通过能写 100% 准确率吗？** 不能。它是有限重试中的至少一次成功；需记录五次实际结果、是否提前停止和测试范围。

**问：众数是 2/5 时能称多数投票成功吗？** 按本地脚本可能报告成功，但没有严格多数。应说明实现口径，不用成功标签掩盖并列或弃权条件。

**问：AST 工具显示 `None` 就证明函数不返回值吗？** 不能。当前代码将缺注解也编码为 `None`，且没有运行函数或分析全部返回路径。

**问：反思后四例通过是否证明完整密码规格实现？** 不能。缺少边界与规则覆盖，返回类型被真值转换放宽，且没有执行隔离保证。

**问：原脚本退出 0 能作为验收吗？** 不能单独使用。入口忽略返回布尔值；还要核对实际测试结果、失败日志及覆盖范围。
