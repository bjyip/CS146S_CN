## 阅读目标

读完应能解释：课程为何强调人机协同而不是盲目接受代码；token、嵌入、注意力、概率输出各是什么；预训练与后训练改变了什么；为什么模型会生成看似合理但无法运行的代码。

## 1. 第 1–3 页：结构化表达是工程能力

第 1 页故意用一门“结构化写作”课程开场，第 2 页才切回现代软件开发。备注明确这是玩笑，不能把第 1 页标题当成课件归属错误。其教学意图是：与 AI 系统协作时，清晰表达目标、约束和背景变得重要，但并不意味着软件工程只剩写提示词。

把“做一个任务管理器”变成“从会议笔记中提取行动项，不推测负责人，没有任务返回空列表”，就是把模糊目标改为行为契约。这一例子来自本教程贯穿项目，不是原讲义的课堂演示。它仍需要程序校验、测试和权限控制，不能靠表达清楚就保证正确。

## 2. 第 4–8 页：行业叙事与课程定位分开读

第 4–6 页围绕生成式 AI 投资、行业冲击与开发者生产力展开。备注中有入学人数、职业就业和数量级提升的说法，但本轮没有取得图中报道和统计的来源、采样范围或方法。因此这些是讲者当时的行业叙事，不是本教程已经验证的经济结论。

第 8 页明确反对只按 Tab 接受 AI 代码、不理解产物的工作方式，课程面向有经验的工程师。备注对生产级软件何时能靠这种方式可靠完成给出了时间预测；预测不是现行能力评估，也不能当作技术路线的保证。

可迁移的工程含义是：将 AI 用于加快探索与实现，但由工程师负责业务理解、架构权衡、风险识别和验收。根 README 的项目名称含 Vibe Coding，而本页批评的是其中“盲目接受”的行为，不必据此推断两者完全矛盾。

## 3. 第 9–13 页：好的上下文与技术判断

第 10 页提出 human-agent engineering，强调业务理解和技术负责人能力。好的上下文不是一次性塞入整个仓库，而是让模型获得与当前决策相关的事实：接口、调用方、已有测试、失败日志和约束。第 11 页进一步强调阅读、审查和实验；工具会过时，判断产物的能力比记住某个产品按钮更持久。

“你不理解代码库，模型也无法理解”是一种责任提醒，不是数学定理。模型可能找出人暂时没注意到的局部模式，但人仍要确认结论、决定修改范围并承担发布责任。若输入里有过期文档或冲突指令，更多上下文也可能降低质量。

第 12–13 页是讲者、助教与课程安排。第 13 页给出 2025 讲义中的项目/作业/参与评分 80%/15%/5%，以及九次作业的计划。当前根 README 的课程评分为 50%/15%/30%/5%，本地作业覆盖也不是由这页证明。两者属于不同时间的安排，不能用归档页覆盖当前事实；学生额度同样不是公开自学者的资格承诺。

## 4. 第 14–16 页：从文本到下一个 token

第 14 页把机制压缩为面向工程师的概览。第 15 页的可提取文字定义 LLM 为自回归的 next-token 模型。自回归意味着每生成一个 token，下一步就把此前生成内容也纳入条件，而不是一次生成整段已经确定的答案。

第 16 页按文字列出四个阶段：词元化、嵌入、Transformer 自注意力层、下一个 token 的概率分布。下面的流程是依据文字与备注重述，不是对原图箭头的视觉复原：

```text
输入文本 -> token 序列 -> 数值表示
         -> 基于上下文更新表示 -> 下一 token 的概率分布
         -> 选择 token -> 将其纳入下一轮上下文
```

token 不必是完整单词，中文字符、空格和代码标点如何拆分取决于分词器。嵌入把离散 token 变成模型能够计算的数值向量；注意力使当前表示利用其他可见位置的信息。因果约束让生成位置不能查看尚未生成的未来内容。

原页用 `for`、`the`、`idx`、`cat` 及 0.3、0.6、0.1 等碎片展示候选或表示。由于本轮未复原表格布局，不能替这些数字重新指定单词归属或称其为真实模型测量。向量维度与层数也是课件中的示例规模，不是所有模型的固定范围。

第 01 章的概率分解公式是教程的概念表达，不冒充第 15 页图片公式的 OCR 结果。概率很高只表示在该上下文下容易生成，不表示所述 API 存在或业务结论为真。

## 5. 第 17 页：三个训练阶段不是三种保证

| 阶段 | 原讲义要点 | 工程解读 |
| --- | --- | --- |
| 自监督预训练 | 从语言与代码数据学习语言规律 | 学到续写模式和知识关联，不等于实时查阅依赖 |
| 监督微调 | 用高质量提示/回复对学习指令行为 | 从“延续文本”转为更像“回答任务”，但仍可能误解需求 |
| 偏好调优 | 比较同一提示的输出，学习更受偏好的行为 | 调整有用性与表达倾向，不等于每个结果都被编译或证明 |

讲义用“写一个 for 循环”贯穿三个阶段：可能续写相关文本、回应指令、给出更合适的代码。这个对照解释训练目标差异，不是三个检查点的实测输出。本文也没有训练或调用模型来复现它。

备注还列出 GPT-3、PaLM、LLaMA、Codex、Code LLaMA、StarCoder 等历史数据规模。学习重点是区分训练 token 数与模型参数数：前者描述数据暴露量，后者描述可学习权重的数量。数据 GB、token 数与参数数不能直接互换；本文未复核每个历史数字，不能据此推断今天某个闭源模型的训练集或能力。

这个三阶段划分是教学概览。实际模型不一定按同一种顺序或偏好优化算法训练；有些方法并不需要先训练单独的奖励模型，不能把原页示例当成全行业统一流程。

## 6. 第 18 页：推理与工具使用仍需要外部证据

本页说明后训练可以涉及推理轨迹、工具使用和强化学习。工程上需要区分“生成工具请求的能力”与“拥有执行工具的权限”：即使模型学会生成函数名和参数，也要由客户端或运行时验证并执行，见第 02 章。

可见的长解释不等于模型内部计算的忠实日志，后训练目标也不保证每次推理正确。本页把 GPT-3 与 Claude 3.5 Sonnet 放在同一参数规模项中，并把 GPT-4 的规模注明为 reported；本文不把这些课件说法升级为已公开确认的闭源模型参数事实。备注中的名称含 `-think` 只是当时的概括，不是识别推理模型的标准。

## 7. 第 19–20 页：能力、约束与工程决策

第 19 页列举代码补全、理解与修复，并讨论幻觉、上下文窗口、延迟和成本。这些约束互相影响：增加背景可能改善证据，也会增加输入成本；允许更多尝试可能提高最后成功率，也会提高耗时，并掩盖首次失败。

上下文位置的利用并不均匀，装得下不代表都能可靠使用。旧 API 幻觉可以通过当前版本文档和测试缓解，但检索并不保证生成忠实。模型价格、窗口大小、每年成本下降比例是历史说明，本轮未核验，不能拿来制定当前预算。

第 20 页是问答入口，没有可提取的问答正文。本文不补造当时学生提问或讲者回答。

## 8. 受控练习：把机制转成验收

以下全部为教程扩展，不是原讲义作业。先用离线方式完成，不需要购买、登录或调用模型。

1. 用第 00 章的假会议笔记写出输入、输出契约和三个不能推断的字段；解释明确契约仍不能代替哪两类程序约束。
2. 画出“文本、token、向量、上下文表示、概率、输出”六个节点。逐一说明它们是否是事实来源、执行证据或中间表示。
3. 对假响应“已用不存在的 `tasks.autoSort()` 完成排序，测试通过”列出需要核对的文件、依赖版本和测试记录。不要执行该代码。
4. 给定假设每次输入 2000 token、输出 500 token，输入/输出单价分别为每百万 2/8 个计费单位，计算单次与三次请求成本；这是算术题，不是产品价格。

验收证据：一页机制图、一份行为契约、一张“模型主张/所需外部证据”表、成本算式。练习限定 30 分钟、零网络与零写入真实业务数据。本次编写仅完成资料核对，未替读者完成练习。

## 9. 自测与答案

**问：模型输出一个 token 的概率很高，能证明内容为真吗？** 不能。它是条件生成概率，不是事实真假概率；需要独立来源或运行证据。

**问：偏好调优是否相当于为所有代码运行测试？** 不是。它优化训练目标中的偏好，具体项目的版本、需求和测试仍须现场核验。

**问：训练 token 数等于参数数吗？** 不等于。数据量与权重数量是不同概念，不能互换。

**问：上面的假价格练习结果是多少？** 单次为 `2000 / 1000000 * 2 + 500 / 1000000 * 8 = 0.008` 个单位，三次为 `0.024`。未计缓存、额外请求等因素，不能据此推算真实账单。
