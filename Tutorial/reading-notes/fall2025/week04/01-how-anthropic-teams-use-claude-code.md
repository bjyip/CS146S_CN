## 阅读目标

把“让 Agent 自主做事”拆成任务适配、上下文、能力边界和验收四个问题。理解自动化为什么适合重复、可反馈的工作，同时保留需要领域专家与人类批准的部分。

## 1. 先导航，再实施

英文的 Codebase navigation and understanding 描述两类工作：数据基础设施新人用规则文件和代码理解管道依赖；产品工程把 Claude Code 当任务的第一站，先定位应该检查的文件。中文进一步列财务纯文本工作流、会话结束后改进说明、跨仓库多实例等场景，这些细节在当前英文短文中未全部出现。

机制不是“知道整个公司”，而是把任务转成可检索的入口和依赖关系。对数据仪表盘，关键不是名字相似的文件，而是哪个上游数据源流入哪个转换和展示节点。导航摘要可以节省研究时间，但摘要中的路径、因果和版本仍应回到实际文件确认。

中文建议写详细 `Claude.md`，产品工程又建议从最少信息开始；二者并非必然冲突。重复工作需要维护稳定的项目入口和模式，单次提问则不必复制所有材料。文件名写法来自译述，不能作为当前客户端大小写、发现路径和加载优先级的保证。

## 2. 自主性随任务风险变化

英文 Prototyping and feature development 描述自主循环：生成、测试、迭代，再由人审查润色；视觉与错误状态探索用于提前发现边界。中文产品开发明确区分外围功能/原型的异步处理与核心业务逻辑的同步监督，并以 Vim 快捷键为例，自述约 70% 代码来自自主工作。

该比例描述一个项目的代码来源，不是正确率、任务成功率或整个团队提速。中文 RL 工程又自述首次成功大约三分之一，说明同一报告内部也包含失败和额外指导，不能只取成功故事。中文数据科学的“老虎机”比喻强调尝试后接受或重新开始；它不是无限重试策略，也不授予删除当前工作或他人修改的权限。

自主循环成立需要有可观察反馈。编写测试、读测试失败、改代码能形成循环，但测试与实现可能共享误解，循环也可能稳定朝错误规格优化。人类必须明确核心契约、停止条件和审查位置；历史自动接受快捷键与检查点提交仅作为来源经验，本次不启用、不提交、不回滚。

## 3. 测试、审查与事故调查

英文 Testing and code review 描述安全团队从粗糙实现转向伪代码与测试驱动，推理团队让工具把同一测试意图转成 Rust 等语言。翻译代码减少语法劳动，但类型、整数边界、并发与运行时语义仍需验证；生成了测试也不等于全面覆盖。

两版本都讲 Kubernetes 无法调度 pod 的故事：输入仪表盘截图，经 Google Cloud 菜单找到了 pod IP 耗尽，得到增加 IP 池的命令。它能说明视觉证据与系统状态帮助定位，不证明模型仅凭截图可可靠处理所有集群问题。截图、集群配置、命令和成功日志本次均未读取，不能给读者填具体修复命令。

中文安全工程列 Terraform 计划审查、Markdown 操作手册和 `dependant` 项目；当前英文短文主要覆盖栈追踪、文档和控制流。Terraform 计划是待执行差异，模型解释是风险候选，不替代安全审批。压缩操作手册应保留来源与版本，否则会将错误或过期指导传播到后续事故。

英文把 10–15 分钟扫描概括为约三倍加速，中文写约五分钟；这些是访谈经验，缺少任务样本、失败分母和测量方法，不把它们当教程预期耗时。

## 4. 专业子任务与跨职能原案例

| 原团队与案例 | 本次可读取的机制 | 证据边界 |
| --- | --- | --- |
| 增长营销：CSV 广告变体 | 两个专门子 Agent 分别处理标题与描述，明确格式约束 | 中文给标题 30、描述 90 字符，英文只说严格字符限制；没有计数规则或发布评测 |
| 增长营销：Figma 插件 | 按框架替换文案批量生成素材 | 英文与中文均述最多 100 变体、半秒级批次；未见实际实现/计时，产出量不等于营销效果 |
| 数据科学：React 可视化 | 相对少上下文的仪表盘减少对大仓库背景的依赖 | 中文述 5000 行 TypeScript；行数不能证明生产质量 |
| 产品设计：错误状态与交互原型 | 把静态视觉意图转成可讨论行为，提前列错误流程 | 英文与中文均支持；设计稿、原型与浏览器未验收 |
| 法务：电话树 | 先用原型帮助联系合适律师，再验证方案 | 两版本共同支持；不证明法务判断被自动化 |
| 法务：沟通辅助工具 | 中文描述语音输入、预测文本与朗读，并向专家展示 | 仅中文详细版载有；不是医疗有效性或无障碍合规证明 |

子 Agent 的意义是聚焦不同输出契约，不是增加角色名字就产生独立智慧。广告案例可分别检查标题和描述长度，再检查组合是否表达一致意图；单项合格不保证组合合格。财务、法务与营销涉及真实敏感数据，非技术用户也仍需要工程设置、权限控制和专家复核。

中文数据基础设施建议用 MCP 而非 BigQuery CLI 控制敏感数据访问，这只能理解为其团队的接口选择：MCP 服务器可以实现授权、日志与窄工具，协议本身不保证这些机制存在；CLI 同样可以被受限运行。不要把“用了 MCP”变成安全证明。

## 5. 教程补例：行动项提取器

以下不是 Anthropic 原案例。假需求为“负责人未明确时保留空值”：只读研究者定位字段和失败条件；实现者在批准后改隔离副本；测试设计者按规格列缺失负责人、明确负责人和歧义负责人；审查者读取实际差异与检查证据。真实任务同步、生产数据和发布全部禁止。

重复步骤可编码成工作流，但一次失败教训是否进入长期规则，要看它是否可复用。临时任务进度应进入交接记录，不能把每次聊天都追加到规则文件；会话摘要说“已完成”不能代替命令、断言、差异与未验证项。

## 6. 零执行练习与验收

教程扩展，45 分钟，零网络、零安装、零模型、零费用，只在纸面处理假资料，不运行测试、脚本、产品、数据库、Git 写入或云系统。

1. 10 分钟把“定位未知错误”“生成受限格式文本”“核心认证修改”分成只读研究、有限异步、同步批准三类，给每类一个停止条件。
2. 10 分钟为上述提取器假需求写输入/输出、允许范围、非目标和五个验收场景，不生成实现。
3. 10 分钟模拟标题 Agent 输出满足长度、描述 Agent 输出也满足长度，但二者截止日期相矛盾，记录组合验收失败。
4. 10 分钟分析三次虚构尝试：一次正确、一次超时、一次需人工重写。记录全部尝试与人工成本，不能删除后两次或套用原文效率数字。
5. 5 分钟检查假交接“已解决 Kubernetes，准备执行扩容”，在没有环境身份、配置、批准与回滚证据时置为待批准，不补造命令。

验收交付是风险表、委派合同、组合反例、三次尝试账本和缺证据暂停表。答案要能指出“格式通过但组合失败”“完成主张不等于执行证据”；所有真实运行字段写未运行，本次未代读者完成练习。

## 7. 自测与答案

**问：70% 代码由 Agent 编写等于 70% 需求正确吗？** 不等于，来源比例没有给需求覆盖和缺陷分母。

**问：官方短文与宝玉译述可拼成 PDF 的完整译文吗？** 不可。实际 PDF 未取得，中文载有英文当前页没有的细节，版本对应与逐句忠实度未核验。

**问：两个专业 Agent 分别通过格式检查就可以发布吗？** 不可，还要组合一致性、业务/安全检查和独立发布授权。

**问：MCP 比 CLI 一定安全？** 不一定，取决于具体身份、权限、数据限制与审计，不取决于接口标签。

**问：从最少信息开始是否意味着不给验收与权限？** 否，可以减少无关背景，但目标、关键约束和停止条件不可缺失。
