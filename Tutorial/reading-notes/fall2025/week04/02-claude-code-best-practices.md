## 1. 配置是上下文，权限是另一层

Whaty 的核心设置策略列 Bash 命令、风格、测试和项目流程，建议把它们放入 `CLAUDE.md`，并概括父目录、子目录、主目录的层级位置。这给学习者一个入口，但未详细定义各目录何时发现、覆盖顺序和不同启动目录的效果，不能推成通用加载标准。

可迁移机制是减少重复猜测：工作目录、测试入口、维护中的规范和禁止范围有明确位置。当前返回页强调只写模型不能从仓库发现、或需要反复研究的信息，保持规则短，并将路径局部规则和长流程分开。历史“写入必要设置”与当前“减少冗余”可以共同解释为信息有用性与维护成本，不是越长越可靠。

中文列交互提示、权限命令、JSON 和 CLI 选项管理白名单，以及 `gh`、MCP、自定义命令集成。集成入口不等于访问获准，配置文件也不保证语义。当前已见段落明确区分模型决定是否遵循的提示/规则与执行器应用的 Hook、deny、沙箱、组织设置；模型 Hook 本身仍是非确定性判断。

即使执行器每次触发某检查，也只保证触发机制，不保证检查覆盖全部业务风险。实际 shell、失败退出、路径规范化、异常与超时如何处理，仍需独立核验。当前页也提到工具级拒绝与脚本内部读取存在边界，不能只凭拒绝某个 Read 调用宣称全系统秘密不可读。

## 2. 三种工作流对准三种不确定性

| 中文页工作流 | 原页可见内容 | 适合解决的问题 | 不应偷换的结论 |
| --- | --- | --- | --- |
| 探索、计划、编码、提交 | 先读文件不编码，再制定详细计划，实施和审查提交 | 根因、入口和设计尚不明确 | 看过计划不等于方案已批准；最后一步不授予本次提交权限 |
| 测试驱动 | 先写测试，确认失败，再实现并迭代 | 外部行为能够明确描述 | 依赖缺失或夹具错误不是合理的行为红灯 |
| 视觉引导 | 给设计稿/截图，实现后根据视觉反馈迭代 | 视觉要求难以仅用文本表达 | 截图相似不证明键盘、错误路径、响应式和持久化正确 |

中文将探索循环称为最有效模式，这属于译述中的推荐，不是对所有任务的比较实验。固定简单改动可能不需要长规划，高风险修改即使有失败测试也仍需人工批准。第 05 章已有工作流职责，不再创建另一套通用阶段系统。

历史译述把 `think`、`think hard`、`think harder`、`ultrathink` 列成等级；当前返回页明确前三类只是普通提示文本，主要控制来自 effort，并单列 `ultrathink` 的当前行为。这是版本差异，不能将历史词表作为当前 API、推理预算或性能保证，也不从当前文档反证历史文章究竟如何描述。

## 3. 具体输入、早纠正与状态清单

中文优化技巧包括具体指令、图片、早期中断、任务间清理上下文和 Markdown 清单。机制分别是降低歧义、提供不可从源码推断的视觉要求、缩短偏离距离、减少无关上下文、让步骤状态可审计。

具体并不是大量重复文本，而是可观察的完成条件。例如“修复登录”没有触发条件和预期，“会话过期后刷新 token 失败时应回到登录状态，保留错误证据”才可以形成测试。此登录例为教程补充，不是 Whaty 原页的具体源案例。

清单只记录工作状态，不保证动作实际执行；`/clear`、中断与撤销的产品行为均未运行。删除对话不恢复磁盘，当前已见文档也限制检查点覆盖范围，不能把它当 Git、数据库或外部服务的全量回滚。保留他人的已有修改比“获得干净状态”更优先。

## 4. 无头模式与并行仍需要合同

Whaty 原页给 bug 分类、安全审查、日志监控、CSV 管道和文件引用等示意，并列 worktree、独立检出、独立实例。原页只提供简短命令，没有日志敏感数据处理、输出 schema、超时、取消、预算或失败传播实现；本文不复制或执行它们。

无头调用减少人工交互，也减少临场拦截机会，必须事先限定输入、工具、输出、整体预算和审查者。连续日志输入不保证无限流可消费，也不证明 Slack 已接通。自然语言返回“OK”不能代替退出码与目标契约。

worktree 提供不同文件目录，但仍可能共享端口、全局配置、云账户和数据库。两个实例基于不同版本、一个改 schema 另一个写旧契约测试，会制造集成返工。当前文档增加了自动并行及 worktree 产品功能等内容，本文不把它们补成 2025 译述的原始实现，也不按当前页面直接创建目录或账户。

## 5. 源模板与教程补例

Whaty 页的原模板分别是“按安全、性能、可读性、最佳实践审查”“保持行为的重构，先写测试”“读代码、提出假设、日志/断点验证、修复、回归”。这些模板给注意点，但没有项目上下文、严重性、文件范围和发布审批，不能独自构成完整工作流。

教程补例为开发者控制中心的 API 文档核对：输入是同版本路由摘要和假 OpenAPI；只标注不一致，不启动服务或修改接口。需要区分 schema 一致、业务行为正确、真实运行成功三个状态。若要同步文档，另行批准文件范围；“没有差异”只有声明范围内意义。

## 6. 零执行练习与验收

教程扩展，40 分钟、零网络/安装/模型/费用；只写纸面假任务，不创建配置、worktree、测试、数据库、账户或 commit。

1. 10 分钟把四条要求分类：“用单引号”“不读真实凭据”“最多研究两个来源”“必须验收负责人空值”。写出提示指导、执行层限制、预算、验收各自责任。
2. 10 分钟为未知根因、已知输出契约、UI 排布三任务选工作流，说明为什么不是同一序列。
3. 10 分钟模拟“测试失败因为依赖不存在”“测试因行为缺失失败”“截图正常但删除请求失败”，分别记录阻塞、可继续实现、未通过完整验收。
4. 10 分钟为两个假并行任务固定共同 schema 版本、文件所有权、数据库禁用、输出证据和集成顺序。再引入旧版本测试，必须暂停同步。

验收为职责分类、工作流选择、三路失败辨析和并行合同。禁止写“已生效”或“全部测试通过”；所有产品、权限和执行字段为未运行。检查失败的原因必须能够影响下一步，不是打印警告后照常推进。

## 7. 自测与答案

**问：中文页名含“官方”就可以当官方出版？** 不可，实际是社区翻译页面，历史英文及授权未核验。

**问：历史入口返回当前文档就说明历史全文已读？** 否，是不同版本来源，不能互相冒充。

**问：`CLAUDE.md` 的禁止语句是操作系统安全隔离？** 不是，提示与运行时限制分层；后者仍需核验实际边界。

**问：先写测试且失败，下一步一定改产品实现？** 否，要确认失败来自目标行为而非环境、测试或夹具错误。

**问：两个独立窗口就是独立实验？** 不是，可能共享数据、环境、模型偏差和上下文，需明确隔离与同预算比较。
