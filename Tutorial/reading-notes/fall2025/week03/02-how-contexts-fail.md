# 长上下文如何失效：错误传播、分心、混淆与冲突

## 2. Context Poisoning：错误被当成后续事实

作者引用 Pokémon Agent 的例子：错误游戏状态进入目标或摘要后，被反复引用，导致追求不可达目标。关键不只是一轮出现幻觉，而是幻觉进入可持续的上下文，后续推理继承它。

教程补充：交接写“授权测试全部通过”，实际只有 mock。下一会话据此删掉验证步骤，就把未经证实的状态传播成事实。修复应重读真实测试范围、替换错误总结，并检查由它产生的计划，不能只在末尾追加一句“可能没测”。

## 3. Context Distraction：历史动作挤压新策略

作者描述长历史中重复旧动作而不再形成新计划，并转述某些模型/任务在特定长度后退化。100k、32k 等数字对应文章引用的不同研究与观察，不是统一压缩阈值；检索、总结与长程任务的有效长度也不能混为一谈。

教程补充：工具已连续拒绝同一个过期 token，Agent 仍照抄旧重试。应识别不可原样重试的错误，独立恢复授权，而非无限加长历史或只换模型。

## 4. Context Confusion：无关信息也参与选择

无关工具和内容可能影响回答。作者用工具选择基准和 46／19 工具的个案说明：上下文未满，模型也可能选错。这个个案不证明 19 是最佳数量；应按任务检索必要能力，并测试“不需调用工具”的负例。

教程补充：笔记分页任务引入大量部署和支付工具，模型可能做越界操作。裁剪目录降低干扰，但最终阻止执行仍靠权限层；工具说明不是安全沙箱。

## 5. Context Clash：早期假设与后来信息冲突

作者转述将完整需求拆成多轮消息的实验，早期不完整回答留在历史中，影响最终解答。文中在这个小节也使用 Context Confusion 解释现象，说明分类并不严格互斥；应关注具体传播机制，不把四个名称当唯一诊断标准。

“平均下降 39%”和 o3 分数变化属于引用研究的特定设置，未在本教程验证，也不能推出所有澄清对话有害。澄清本身必要，问题是旧假设未被明确撤销。

## 6. 教程补充：怎样进行来源感知的恢复

第 03 章已有缺失、污染、冲突、过载分类，是工程走查视角，不与本文四类逐项等同。恢复顺序可以是：定位错误来源，区分事实与猜测，重读权威材料，明确替换过时决定，再制作保留理由与验证范围的交接。

例如最初假定分页按 ID，后来确认按创建时间并以 ID 打破同时间排序。新规格应明确撤销旧排序决定，并绑定测试；仅保留两个互相矛盾的消息让模型自行选是不可靠交接。

## 7. 受控练习与验收

预算 25 分钟、零网络、零模型调用。制作四条虚构交接片段：未运行却称测试通过、过期 token 重试、无关工具建议、两种排序并存。为每条记录失败机制、原证据、撤销或恢复动作和仍未知的事实。

验收交付修正版交接和差异表，必须保留未运行状态，不隐藏失败。没有模型实验时只能说明交接一致性，不能宣称质量或成本提高。压缩可能丢失信息，重开会话也不自动恢复真相。

## 8. 自测与答案

**问：上下文未满是否不会失败？** 不是，无关信息、错误和冲突都可在窗口上限之前造成失败。

**问：把旧假设留着再写新结论足够吗？** 不一定，应明确权威版本、替代关系与待验证项。

**问：本文分类与教程四类一样吗？** 不一样，分别关注模型现象与工程来源问题，有重叠但不一一对应。

第 03 章吸收错误传播与恢复练习；本文没有提供已验证通用阈值或读取未取得的修复续篇。
