## 2. AI-assisted 与 AI-native 的区别

引言对照支付服务开发与延迟调查：生成代码可借助代码库上下文，但排障仍需人在指标、日志与部署历史间切换。作者认为问题不只是模型能力，还在工作流架构。

“What is AI-native engineering?” 把 AI-assisted 描述为人主导工具、关联与行动，AI-native 则由工程师表达目标，AI 系统组织调查并给响应或动作。例如不是仅要求分析指定日志，而是让系统围绕 checkout 故障生成竞争假设、跨源取证、迭代调查。

这是一种职责分配定义，不是人类退出决策的标准。状态化 Agent 可以保存事故目标、当前假设和查询结果；持久状态还要治理版本、错误修正、保存期限和敏感信息。持续运行也不等于可靠运行。

## 3. 作者为何主张多 Agent

“Why are multi-agent systems essential” 用 API 延迟突然上升的情境，列举微服务 trace、慢查询和连接池、部署变化、认证日志、扩容与客户影响等调查方向。专业分工有助于限制每个分支的上下文，并行检查可减少等待。

| 原文比较层级 | 作者指出的瓶颈 | 教程辨析 |
| --- | --- | --- |
| LLM | 单次生成缺少反馈和系统集成 | 这是使用方式，不证明所有 LLM 应用都没有状态 |
| LLM + Tools | 人仍负责关联，跨交互缺少持久状态 | 工具增强系统也可设计外部状态，不能按标签断言不能持久化 |
| Single Agent | 顺序调查、错误假设与协调瓶颈 | 单个协调者可以调度并发工具和反馈，不必然只能顺序执行 |
| Multi-Agent | 需正式通信与冲突处理 | 多分支增加并行机会，也增加成本、共享证据误判和协调故障 |

作者将多 Agent 的必要性表述得很强，但没有给同数据、同工具、同预算的单 Agent 对照。生产系统复杂不证明任何任务都必须多 Agent；小事故、强确定性 runbook 或低预算场景可能适合更简单结构。判断依据应是任务依赖、实际等待时间、正确性与协调成本，而不是 Agent 数量。

## 4. Building multi-agent systems is a hard engineering problem

作者把难点拆成生产领域知识与 AI 协调能力。领域知识决定连接池、日志、指标等分支该怎样检查；AI 工程负责信息流、并发协议、上下文传递和避免竞争、死锁。文章强调现成框架不能单独解决这些问题，但未提供实现代码或协议。

“有向无环信息流”可以描述一轮任务依赖，事故调查本身却可能多次修正假设。教程采用带版本的调查轮次：本轮输入固定，结果有结构；新证据进入下一轮，不能把循环推理与调度依赖环混为一谈。这是补充设计，不是 Resolve 已披露架构。

每个分支至少返回事故 ID、假设、查询范围、证据 ID、观察时刻、支持、反证、未知与状态。协调者处理冲突而不是投票定根因。两个分支引用同一条日志不是独立确认；工具拒绝与超时也应作为结果返回，不能为了统一故事删除。

写入资源由执行端统一授权。多 Agent 不能各自独立重启同一服务，也不能因一个分支获准查询就让其他分支继承部署权限。总预算、有限重试、取消、迟到结果和过期版本都需要控制；这些要求不由“团队协作”四个字自动实现。

## 5. 原案例与教程扩展

文章的支付服务和 API 延迟例子是架构说明，没有给出完整事故证据。以下将思想映射到行动项提取器，不复原文章图片，也不测 Resolve 产品。

预算 40 分钟、零网络、零费用、零模型和生产操作，本轮未运行。设假事故 `incident-demo`：模型路径慢，规则路径正常，近期发布 v2；模型分支引用证据 E1“调用超时”，队列分支也引用 E1，却声称队列必然满；配额分支访问被拒绝；迟到结果来自上一轮 v1 的时间窗。

1. 固定当前时间窗与轮次 v2，最多三个分支、每分支两项假只读查询，总计不超过六项。
2. 为分支填写结构化结果，标记队列假设缺少队列长度证据；拒绝访问保留未知。
3. 协调者合并同源 E1，列出仍需的反证，隔离旧轮次结果，不以三票或多数意见确认根因。
4. 比较一个协调者顺序处理与三个分支并行的计划，计入等待、重复查询、协调时间与总调用数，不编造实际加速比。

验收：预算有限，同源证据去重，冲突有处理理由，旧版本不覆盖当前结论，失败有交接，修复写入未执行。此练习只评估设计，不证明真实并发、持久化、取消或模型可靠性。

## 6. 自测与答案

**问：多 Agent 一定比单 Agent 快吗？** 不一定。任务依赖、工具限流、重复查询与协调开销可能抵消并行收益，需同条件实测。

**问：单 Agent 是否必然不能使用并发工具或外部状态？** 不是。文章比较表是作者对典型架构的概括，不能当能力限制定理。

**问：两个分支都支持一个结论就是双重证实吗？** 不是。先检查证据来源是否独立、范围是否一致，以及反证是否仍存在。

**问：反馈循环与 DAG 是否矛盾？** 不必然。可以按轮次安排无环依赖，再将新证据作为下一轮输入；真实实现仍需版本和终止条件。
