## 2. 研究不是提前设计

原演示是一个简化 Mint 记账应用：假消费数据、CSV 上传、预算和分类视图，没有信用卡集成；目标新增按类别随时间变化的趋势线。讲者坦言不是该前端代码作者，因此先用 research codebase Skill 建立自己与 Agent 都能用的心智模型。

研究提示明确“只记录已有行为，不建议改善”。它把原始代码浓缩成结构、契约与引用，供后续提案使用。教程补充：事实应有文件位置，文档缺口和推断分开；研究阶段仍可能出错，关键调用链不能因为摘要流畅就免于抽查。

讲者说明自己的 prompt 经过一年以上定性迭代与团队使用，但未做每次修改的严格对照实验。不能把这转述成已证明所有仓库有效的 A/B 测试结果。

## 3. 提案、计划与人类决策

原演示给出服务端与客户端两种趋势线方案；讲者为降低现场演示改后端的风险选择客户端方案。该选择的上下文是演示，不能由此推导生产系统都应前端聚合。

讲者想要两种“不同区域”的方案，用 PCA 的正交方向作比喻；两个是经验起点而不是最佳方案数定理。用户应在需求、架构、限制和权衡处投入判断，而不是在模型已经实施后才提出隐藏偏好。

plan 文档包括当前状态、功能/非功能要求、设计取舍、文件与行定位、测试、观测、安全、rollout 和未来考虑。特别明确本轮不做什么，避免“顺手优化”范围漂移。讲者也承认内置 plan mode 可能足够，自写流程主要带来统一产物和习惯。

## 4. 测试与审查不是一项指标

演示中 Cursor 主动打开浏览器、生成假 CSV、上传并观察趋势线。讲者把这归为行为契约检查，另用 code-review Skill 检查性能、安全、风格、一致性与边界。

教程补充：可视图表出现不能证明月份分组、时区、空数据和负值都正确。行为测试和代码审查互补；一个 Agent 写代码又替自己验证可能产生共同盲点，需要独立样例及真实测试输出。

讲者介绍按安全、性能等领域分工的审查 Agent，但本页没有读取其实际多 Agent 输出；不要把这个行业工作流介绍记成已验证的本演示实现。

## 5. 清空与压缩的条件

讲者指出现场在选择方案后没有清空上下文，但日常会倾向保留已选方案的产物并重开会话，以减少未采纳方案干扰。这里的重点不是机械清空，而是让当前上下文只包含仍有效的决定。

课堂转述一篇 compaction 研究，提到约 250,000–450,000 token 与模型差异；本页只读该转写，没有独立核对研究方法或原始数据，不将这个区间设成统一阈值。早期强模型、后期轻模型的建议也是讲者经验，实施与测试仍可能需要复杂推理。

最后按复杂度分层：文案或小修可简单提示，多文件小功能适合计划，大重构或迁移适合研究、提案、分阶段会话和 subagents。流程成本与风险一起考虑，不能为一行文案固定写五份长文。

## 6. 原案例与教程练习

以下使用贯穿教程的“行动项提取器分页”，不是讲者 Mint 应用的原代码或实测结果。预算零付费、30 分钟，限定本地阅读与纸面设计，不安装、不启动应用、不调用模型、不写真实业务数据。

1. 0–8 分钟：读第 03 章已有分页规格，列当前事实、假设和未确定需求；引用本地章节位置，不凭空补数据库行为。
2. 8–16 分钟：给出偏移分页与游标分页两个方案，比较排序稳定性、并发增删、接口影响和成本；人工选一个并写理由。
3. 16–24 分钟：写短计划，明确不更换框架、不改旧字段、不做第三方同步，列目标文件类型和测试条件；这只是计划，实施标“未执行”。
4. 24–30 分钟：写清空后的交接：仅留已选方案、来源、限制和待验证项；保留未选方案的决策记录位置，不将它继续当实施目标。

验收证据：研究事实表、两方案对照、批准决定、计划及验收案例。至少包括空列表、非法参数、相同时间戳排序的预期。没有实现与测试输出时不能标成五阶段端到端完成。

## 7. 局限与自测答案

课堂是现场单应用演示，不能推广为大仓库成功率；关于“研究压缩已经很好”和人类角色未来变化是讲者判断。Superpowers 的 stars、商业估值与窗口容量为口头/当时背景，本页不作为当前事实引用。原文中的文档复用建议带有前提：先确认文档准确维护，否则过期说明会污染理解。

**问：有 README 是否可以免研究？** 不能仅凭存在判断。准确维护的文档可作起点，关键内容仍需与当前代码核验。

**问：清空后只说“用方案二”够吗？** 不够。新会话需要方案二的具体产物、决定理由、约束与来源，不能依赖已清空的编号。

**问：本页证明哪个分页方案最优吗？** 没有。离线对照用于辨析取舍，具体选择要由真实需求与实现证据决定。
