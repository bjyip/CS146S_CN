## 1. 目标与前提

重点不是“API 能通”，而是 Agent ergonomics：模型只凭 schema 与描述就能选对工具、提供合规参数、组合输出并理解失败。另一目标是长期运行服务的真实 OAuth 授权码获取、缓存和到期刷新。

前提包括 Python/类型约束、测试、stdio 协议、OAuth 基础及合法 API 访问权。先读第 04 章，明确两个认证边界：Server 访问第三方 API，与远程 Client 访问 Server，不是一回事；本作业聚焦前者并要求 stdio 启动。

## 3. 从能力核验到真实演示

1. 先选自己熟悉且获授权的 API，再核对当前应用类型能否完成授权码交换与要求的刷新路线。若不支持，不要手工粘贴 bearer token 假装 OAuth，改选合适 API 或报告阻塞。
2. 明确专用测试资源、最小 scopes、允许写入字段及清理方法。每个 scope 写出对应工具与用途；只读范围之外的授权必须有真实写工具需求。
3. 先画工具图：`search_notes(query)` 返回 `note_id`，`get_note(note_id)` 读取正文，`create_task(note_id, dry_run)` 预览或写入。这里是教程示例，名称不是原作业固定 API，也不代表已有实现。
4. 将枚举、范围、必填和额外字段规则放进真实导出 schema。输出只保留 ID、必要内容、分页/截断信息和状态，不直接透传供应商庞大 JSON。
5. 设计错误表：坏 ID 不原样重试；限流给出可等待时间；权限不足与认证撤销停止相关操作；网络失败只允许有预算的重试。核对当前 SDK 的工具错误与协议错误表示，不把所有业务错误伪装成功。
6. 实现只读工具及协议测试后，再加入写工具刹车。`readOnlyHint` 是注解不是强制权限；`dry_run` 或预览/提交要能证明预览无业务写入。
7. 在独立授权步骤验证 `state`，按供应商能力使用 PKCE 等保护；缓存存于受限且被 Git 忽略的位置。长运行服务需协调刷新，避免并发覆盖 token。以上保护细化属于教程安全增强。
8. 工具调用期间 token 无法恢复时返回可行动错误，不突然启动浏览器；用户在独立流程重新授权后再重试。不能把所有 401 都归为可刷新，区分撤销、scope 与过期。
9. 记录解释器、SDK、客户端、协议版本和工作目录，用一个确切命令启动 stdio Server。stdout 只用于协议，诊断写 stderr。
10. 在合法隔离账户中接入 Claude Code 或 Cursor，执行真实 prompt，使至少两个工具的 ID 实际串联；再触发坏 ID 或安全的认证失败，记录模型后续行动。
11. 在 writeup 中把每项设计指向实际 `file:line`，记录看见工具误用后做过的改动，并复测，而不是只说“描述更清晰”。

## 4. 测试不能只测函数

原要求至少一项测试通过 MCP 协议。合理证据链是 Client 启动真实子进程，完成初始化和能力协商，执行列工具与工具调用，并检查返回或错误；具体消息/测试 API 必须按所用协议与 SDK 版本核对。

直接调用 Python 函数能测试业务逻辑，但无法发现 stdout 污染、导出 schema 不正确、序列化错误或客户端无法握手。两层测试互补，不可用单元测试替代协议证明。

教程建议还测坏参数、坏 ID、分页、限流、到期刷新、撤销、dry-run、写入审批及响应丢失重试。写超时不代表未写入，应用幂等键或读取后置状态判断，不能盲目重复创建。这些测试扩展不是新增课程分值。

## 6. 安全、清理与离线替代

真实写入仅限获授权的专用测试资源，人工确认对象与差异后实施。不要把教学需求解释为给 Agent 全账户权限。原文将移除 Server、删除缓存及撤销应用列为可选清理；自学者应把验证撤销与资源回滚列为实验收尾，不能忘记仍有效的访问权。

30 分钟、零付费离线替代：10 分钟为假笔记/任务画出三工具图，10 分钟写 schema 约束和错误表，10 分钟手推“搜索 ID→读取→dry-run”和“token 撤销→停止”两条时间线。仅纸面或本地文本，不安装、不登录、不调用服务。

验收证据是工具契约、错误分类、权限边界和预览差异。它没有真实 OAuth、刷新、真实写入、Agent transcript 或协议层运行，不等价于原作业完成。即使未来用 mock 跑通协议，也只能证明协议与模拟分支，不能证明供应商授权成功。

## 7. 自测与答案

**问：readOnlyHint 能保证不写入吗？** 不能。还需实现、供应商权限及测试保证无写入。

**问：只演示一次 OAuth 登录足够吗？** 不够。原要求还包含缓存、静默刷新与调用中失效路线。

**问：错误写成 JSON 就一定可恢复吗？** 不一定。需符合 SDK 错误语义，信息足够区分重试、等待、修正参数与重新授权，且 Agent 实际处理要有证据。
