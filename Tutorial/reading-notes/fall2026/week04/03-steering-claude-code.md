# Claude Code 的七种定制机制

[本周目录](README.md) | [全部材料](../../README.md)

## 来源与阅读范围

原文：[Steering Claude Code: when to use CLAUDE.md, skills, hooks, and subagents](https://claude.com/resources/articles/steering-claude-code-skills-hooks-rules-subagents-and-more)，Anthropic 官方产品文章，作者 Michael Segner，发布日期 2026-06-18，正文核对日期 2026-11-04。读取比较表、七种机制说明和选择建议，未核验所有链接文档、实际配置或客户端行为。本笔记不是官方译文。

## 阅读目标

从“把要求全写进提示”转为按上下文、流程、委派、自动化与权限分层设计。重点理解加载时机、上下文占用和执行约束的区别。

## 核心观点

文章以三项差异比较机制：何时进入上下文、长会话压缩后如何处理、占用与影响范围。并不是文件越多控制越强；选择最贴近目的且范围最小的机制。

## 按原文解读

| 原文机制 | 主要用途 | 需要警惕 |
| --- | --- | --- |
| 根 CLAUDE.md | 项目结构、常用命令与团队约定 | 无关条目常驻，持续消耗上下文 |
| 子目录 CLAUDE.md | 特定目录的约定 | 按需发现与压缩行为不能等同根文件 |
| Rules | 特定约束，可按路径作用域加载 | 文本规则不等于强制权限控制 |
| Skills | 发布、审查等可复用流程 | 按需正文有预算，触发不等于可靠执行 |
| Subagents | 独立上下文中的侧任务 | 主线程通常只收到摘要，可能丢失关键证据 |
| Hooks | 生命周期事件上的自动化 | 事件确定触发不等于模型判断确定 |
| Output styles / 追加系统提示 | 全局角色、输出或一次性约定 | 影响范围大，可能改变默认工程行为 |

表格将根和子目录分开，但文章按 CLAUDE.md 作为一类，因此共七种方法。

### CLAUDE.md files / Rules

文章建议根指南像仓库地图，局部约定放到子目录或路径规则，程序化长流程移到 Skill。规则的 `paths` 适合跨多个目录出现的文件模式，例如 API handlers。

原文报告根文件、局部文件和规则的重新注入方式不同。实际压缩行为须按客户端版本确认；本笔记不把页面机制移植成其他 Agent 的规范。文章建议控制根文件行数是维护经验，不是通用质量阈值。

### Skills / Subagents

Skill 的名称和描述用于识别任务，正文按需加载；它让流程留在当前协作线程中。Subagent 把深度搜索或日志分析移到独立上下文，只返回必要结果，减少主线程中间材料。

隔离也有代价：摘要可能遗漏失败或证据。委派时应明确任务、可读范围、输出证据及不允许的操作。文章报告的嵌套层数和大规模编排能力属于产品描述，本笔记未实测，也不建议初学者直接复制复杂架构。

### Hooks

原文区分 command、HTTP、mcp_tool、prompt 和 agent 等 Hook 类型。生命周期事件决定何时触发；其中基于模型的 Hook 使用模型判断决定输出。所以“Hook 自动触发”不等于“检查结果每次一样”。

确定性程序同样可能调用外部服务或失败，不能仅由类型推断所有副作用可预测。可靠门禁应有明确输入、退出条件、失败处理与权限；不能把向外发送消息或备份原始会话当无风险动作。

### Output styles / Appending the system prompt

文章提醒自定义输出风格可能替换默认工程指导，进而影响范围控制和验证习惯。追加系统提示则只影响该次启动，是加法而非同样的替换机制。产品具体参数在使用时需核对官方文档，不凭本文摘要配置。

### When to use each method

原文将“每次事件都做某事”放到 Hook，将长程序放到 Skill，将 API 特定规则缩到匹配路径。绝不能发生的操作需要真实权限和执行拦截，不能只写一句“禁止”。

## 补充案例与实践

以下为笔记补充案例：文档更新流程中，根指南说明教程目录；Skill 解释读取来源、更新笔记和验收；校验脚本检查本地链接；运行时权限限制写入范围。若希望每次编辑自动运行脚本，则需要真实配置 Hook，而不是在 Skill 中写命令就声称已自动化。

离线练习：将“记住目录”“按 API 路径验证参数”“发布前走清单”“分析长日志”“禁止生产写入”分别选机制，说明由模型选择还是执行层强制。验收是各要求的加载与执行位置清楚，生产写入有真正权限边界。无需改客户端配置，本轮未运行练习。

## 局限

这是特定版本的官方产品说明，不是统一 Agent 标准。上下文预算、压缩处理和可用 Hook 类型可能变化。机制被发现不代表遵守，文档阅读不等于运行验证；原文章中的性能与规模描述未在这里复现。

## 自测与答案

**问：加载 Skill 是否自动运行脚本？** 不是。Skill 提供流程说明，Agent 仍需调用执行工具；实际 Hook 才是单独配置的触发机制。

**问：prompt Hook 是否完全确定性？** 事件触发可确定，但模型判断不保证确定。

**问：禁止生产写入放哪？** 文本可说明政策，强制执行必须依赖权限、凭据隔离、审批和拦截。
