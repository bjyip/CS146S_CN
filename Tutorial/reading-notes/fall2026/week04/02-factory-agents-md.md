## 来源与阅读范围

原文：[AGENTS.md](https://docs.factory.com/harness/agents-md)，Factory 官方产品文档。页面未显示发布日期，正文核对日期为 2026-11-04。读取主要正文、模板和发现机制；抓取结果只展示 Troubleshooting 折叠问题标题，不声称已读其中答案。未读取所有链接页面，未运行 Droid。本文是中文笔记，不是官方译文。

## 阅读目标

学会把“认真工作”改成明确的命令、范围和完成证据；分清可迁移的写作原则与 Droid 特定的发现行为。

## 核心观点

AGENTS.md 给 Droid 持久的项目说明：如何运行、修改、验证及保持边界。文件应短、具体、容易核验。先写一个根文件，只有子项目确有差异时才添加局部文件，长流程放到按需加载的 Skill。

## 按原文解读

### Create your first AGENTS.md / What to include

文档建议把命令放前面，写明安装、开发、测试、类型检查和格式检查的真实入口。目录地图帮助定位，生成文件规则说明改哪个权威源，安全规则约束秘密与生产操作，完成条件给出必要证据。

“运行测试”仍可能含糊：不同包的命令、过滤参数和工作目录可能不同。指南应引用仓库实际定义，不照抄页面中的 pnpm 示例。本项目并非该示例项目，阅读不授权安装依赖或构建。

### Choose the right instruction surface

AGENTS.md 是持久指导；DESIGN.md 是设计指导；SKILL.md 保存按需流程；自定义命令是用户主动调用的快捷入口；settings.json 是程序解析的配置。自然语言说明和可执行配置不是同一层。

页面提醒不要把长运行手册塞入 AGENTS.md。原因是常驻上下文会持续占用预算，且无关条目增加干扰。短索引指向权威文档，比复制长正文更易维护。

### Discovery and precedence / Nested instructions

文档描述 Droid 从当前工作目录向 Git 根查找，并检查 `.factory/`、`.agents/`、`.agent/` 等目录和个人目录。用户请求、局部项目规则、项目与个人规则有各自适用关系。这是该产品的工作模型，不是所有客户端的标准。

文档还说明：Droid 的文件读取、编辑、列举和搜索可触发动态发现，但通过 Execute 运行 shell 命令不触发同样发现。因而“终端在某个目录运行”不能直接证明该目录的局部指导已加载。需在实际客户端版本中验证。

### Compatible filenames / Context budget

兼容文件名是为了读取已有指南，不是要求新建每一种变体。多个同义文件容易造成重复或冲突。页面给出初始和动态加载的字符上限，强调它们是上限而非推荐目标；本笔记不把数字固定为长期规则。

### What to avoid

避免秘密、私有主机名、重复长文、过期目录清单、与项目冲突的个人偏好和临时任务记录。不为了方便让 Agent 跳过验证；若确需例外，应有狭窄范围与解释。

## 补充案例与实践

以下为笔记补充案例：某仓库有生成的 API 客户端。差的规则是“保持代码整洁”；好的说明指出客户端来自哪个 schema、生成命令的工作目录、禁止手改的范围，以及改动后应检查的契约测试。Agent 知道去改权威源，但生成文件的保护仍需检查或权限控制。

离线练习：从自己允许修改的练习仓库中找一条测试命令、一项生成物和一项敏感操作，设计三条可核验规则。再分类哪些放根指南、哪些放局部文件、哪些应由执行层限制。验收是路径与命令真实，规则不重复，未执行的检查明确写“未运行”。本轮没有创建任何 AGENTS.md 或运行 Droid。

## 局限

页面是产品行为说明，不是关于规则有效性的控制实验。发现和优先级可能随版本变更；本项目客户端的 `.agents/` 支持不能仅从这篇 Factory 文档推断。即便指南被加载，模型也可能误解，程序化安全边界不能只靠文本。

## 自测与答案

**问：为什么不新建全部兼容文件名？** 它们是兼容入口，不是清单；重复指令浪费上下文并增加漂移。

**问：何时添加局部指南？** 子树确有不同命令、生成物、所有权或权限边界时，而非重复根规则时。

**问：说明“不能提交秘密”足够吗？** 不够。还要限制访问、脱敏日志、检测泄漏，并按实际权限审批。
