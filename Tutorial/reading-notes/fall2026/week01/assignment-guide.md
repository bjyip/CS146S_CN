## 1. 学习目标与前提

目标不是再造一个 Agent，而是从生产系统的请求中解释设计：系统说明买到了什么行为、工具 schema 防止什么误用、失败怎样回到循环、计划与上下文如何随轮次变化。

读者应能阅读 JSON、工具定义、测试输出和多文件项目。先读第 02 章；准备自己拥有权限的临时项目，不能使用本课程仓库或含工作秘密的仓库。原作业假定有合法 Claude Code 访问权，并要求记录 `claude --version`；Stanford 的 SUNet 访问安排是课程条件，不代表公众自学者有同样资格。

真实实验另需客户端、mitmproxy、网络与账户抓包授权以及明确模型预算。推荐先设最大时长、请求数与费用上限，达到任一上限停止。这些预算和权限检查是教程安全增强，不是原评分新增项。

## 3. 建议执行顺序

1. 建立基线：记录客户端和代理版本、认证渠道名称、临时项目位置与允许数据类型；先确认不经代理的正常会话可用。
2. 准备可控任务：例如在个人测试项目重命名一个被两个模块引用的函数，再要求恢复导入和测试。记录事前基线；只制造无害的夹具或断言失败，不破坏真实项目。
3. 按原文建立本机 reverse proxy，将捕获文件放在任何 Git 仓库外；只监听回环地址。第 02 章给出原命令的 PowerShell 单行形式，本页不另造安装流程。
4. 只在临时项目设置中加入 `ANTHROPIC_BASE_URL` 和原文的 `ENABLE_TOOL_SEARCH`。不要修改全局设置，不覆盖已有其他字段。新会话出现 `POST /v1/messages` 才算验证代理链路。
5. 执行一次满足四条件的会话。保留足够请求正文支持后续分析，而不是只保存最终成功画面；记录每个请求的稳定编号。
6. 按请求清点工具，写明互斥分类规则。若某工具同时在目录可搜索又已载入，解释是否计为一次以及变化原因，避免重复求和。未看见发现过程时只记录载荷差异，不断言触发机制。
7. 选一个文件工具和一个编排或特殊失败契约工具。摘录必要 schema，解释必填、可选、未暴露能力以及描述中针对的具体错误行为。
8. 从失败的工具调用 ID 出发，对齐错误结果、下一行动与复测。先定义恢复“轮次”的口径，再统计，不混用模型请求数与工具次数。
9. 对照 writeup 的每个栏目补证据，完成最多一页反思。删除自己本轮加入的代理字段、停止代理，验证恢复后正常调用不再依赖代理。

## 4. 注释而非摘要

弱答案是“系统提示包含安全规则”。强答案是“该句要求在删除文件前确认范围，旨在避免模型把模糊请求解释为不可逆清理；执行权限是否真的限制删除，本 trace 未证明”。前半句可以是观察，最后的设计动机通常是推断。

`<system-reminder>` 的标签名不意味着实际消息角色是 `system`。应引用它在请求的 `system` 字段、具体消息内容或两处的位置，并分别证明两种用途，例如重新声明约束与注入当前任务状态。不要拿课堂演示代替自己的会话。

工具请求是模型提出动作的证据，工具结果是运行时返回的证据，最终测试输出才帮助判断业务是否完成。HTTP trace 看不到模型全部内部处理或训练动机。

## 6. 安全与离线替代

请求头可能有 `authorization`、`x-api-key`；请求正文也可能重放 `.env`、私有源代码、路径和终端输出。不得提交原始 flows、头部或未经逐段检查的 JSON。使用可见的 `[REDACTED: token]` 等标记；脱敏会破坏含义时重新在无秘密项目捕获。秘密已经暴露时先吊销或轮换，删文件不能撤回泄漏。

没有访问或抓包授权时，做 30 分钟、零付费的离线改编：10 分钟阅读第 02 章引用的本地课堂循环代码，10 分钟人工画出跨两文件修复的消息/工具时间线，10 分钟对一个自拟错误返回和工具定义写注释。只使用假路径与假凭据，不安装、不联网调用模型。

离线交付是机制图、两工具分析与明确标为“教程构造”的恢复时间线。验收是角色与调用关联正确、权限在运行时拦截、能区别失败类型。它不能获得本人真实请求、动态工具数量或实际恢复结果，因此不等价于原作业完成。

## 7. 自测与答案

**问：能否把 system-reminder 出现当作实际权限门禁？** 不能。它是载荷中的指令文本，权限是否强制需要运行时证据。

**问：没有调用子 Agent 是否可以填写这一题？** 可以按原文标 `[INFERRED]`，引用工具定义解释可推断内容，同时注明未触发；不能伪造返回。

**问：清理时应删除整个已有设置文件吗？** 不应。原作业的清理目标是去除实验代理设置，教程建议只移除本人新增字段，保留既有配置并复核正常链路。
