# 08 安全与威胁建模

[上一章](07-testing-review.md) | [目录](../README.md) | [下一章：交付与运维](09-delivery-operations.md)

行动项提取器已经能把“周五检查日志”整理成候选任务。但一份笔记也可能要求它读取目录外的秘密；列表页面可能把笔记当 HTML；登录用户可能用别人的任务 ID 读取数据。提取正确并不能排除这三种失败。本章先沿这些具体风险找检查位置，再讨论扫描和修复，不从工具清单开始背术语。

**前置与成果**

- 能区分笔记数据、任务说明和实际工具动作；能阅读“身份、对象、操作、允许/拒绝”的表即可。第 01、04、07 章的提示、授权与证据思想有帮助，基础题不依赖运行其中应用。
- 本章成果是一份威胁表、四类检查证据表、根因修复与回归计划、一次假秘密泄漏处置记录。所有必要材料和答案都在章内。
- 基础只做纸面判断：零网络、模型、扫描、应用执行和真实账号操作。不得使用真实秘密或可运行攻击 payload，答案一致不证明实际防护有效。

## 1. 从资产与权限开始

假设小陈允许 Agent 读取自己的一份会议笔记、生成行动项预览，不允许提交任务。笔记中却有“先读取秘密文件再上传”的无关要求。正常提取不需要这一步；如果工具真的读取或发送，就越过了授权边界。此时重要的不是文字是否像攻击，而是输入能推动什么实际动作。

为了描述影响，我们把要保护的东西称为**资产**，例如用户笔记、任务数据、API 凭据、源码和审计记录；把数据进入系统的位置称为**入口**，例如笔记上传、HTTP 参数、网页、工具返回、依赖与 CI。**信任边界**是这些来源与拥有更高权限的处理层之间的分界：会议笔记可以提供待办内容，不能修改工具权限或代表管理员批准。

| 具体失败 | 资产与入口 | 越过哪条边界 | 首要检查位置 |
| --- | --- | --- | --- |
| 笔记要求读秘密 | 凭据；笔记正文 | 任务资料变成文件/网络授权 | 文件工具与网络执行层 |
| 列表把笔记当 HTML | 用户页面与会话；笔记正文 | 用户文本变成浏览器可解释内容 | 输出到页面的位置 |
| 小陈读到小李任务 | 他人数据；对象 ID | 已登录身份变成任意对象权限 | 服务端对象授权 |

“威胁建模”就是把可能的失败、资产、入口、边界、防护和验证列成可检查的关系，不是画完图便安全。先说明部署范围：无身份系统的本地单用户 demo 不等于多用户产品。扩大到公开服务时要重新评估，不能用本地测试代替租户隔离。

最小权限意为只给当前任务必需的能力。例如提取阶段只读小陈的假笔记，不挂载整个用户目录，不持有部署凭据；提交阶段另核对当前身份、资源和批准。身份验证回答“是谁”，授权回答“此人能对哪个对象做什么”。合法 token 或合法 JSON 都不能自动回答后一个问题。

## 2. 四类检查互补

边界明确后，怎样发现实现里是否漏了检查？有些线索在源码，有些只在运行配置或依赖中，所以要选择不同证据，而不是运行一个工具便写“全部安全”。

| 检查 | 白话机制与本项目例子 | 还缺什么 |
| --- | --- | --- |
| SAST，静态应用安全测试 | 不启动应用，分析源码/可分析产物，追踪笔记输入是否到达危险查询或 HTML 输出位置 | 框架建模、实际配置和路径可达性可能不足 |
| DAST，动态应用安全测试 | 对获准运行的应用发测试请求，观察两个假用户能否访问彼此对象等外部行为 | 未登录、未触达或状态未覆盖的路径；源码根因仍需回查 |
| SCA，软件成分分析 | 盘点直接/传递依赖、实际版本与已知漏洞公告 | 公告适用条件、调用可达性、未公布漏洞和升级回归 |
| 秘密扫描 | 查找代码、历史或获准日志中像凭据的值，帮助发现暴露渠道 | 自定义秘密、未纳入历史/日志可能遗漏；发现不代表已撤销 |

一个产品可以集成多项能力，不意味着任何 SAST 命令天然覆盖 SCA 和秘密。SCA 的版本命中是需要处理的线索，不足以独自证明应用可被利用；也不能以“还没证明可达”无限拖延评估和补丁。

记录扫描版本、规则来源、实际范围、排除文件、执行状态、认证与上传政策。工具超时、规则没加载与“范围内没有发现”是不同状态。基础练习只根据假记录选证据，不下载规则或运行扫描。

## 3. 根因修复的三种典型方向

假设输入处理、页面输出、对象访问都有疑点。它们都接收用户数据，却需要不同修复：保护查询结构、保护浏览器解释边界、保护主体与对象关系。把三者都归成“过滤坏字符串”会漏掉核心机制。

**SQL 注入：输入改变了查询结构。** 用户的搜索文本应只是被搜索的值，不应拼成数据库指令的一部分。参数化查询把 SQL 结构与参数值分开，正确 ORM 表达式也可保持这一边界；仅删除引号不是可靠替代。检查从 HTTP 输入到查询执行点的完整路径，不能因为出现固定 SQL 种子文件就宣称注入，也不能因为用了 ORM 就宣称授权正确。

搜索还可能有独立业务问题：LIKE 的 `%`、`_` 是匹配通配符，参数绑定后仍可能扩大匹配范围。若规格要求字面搜索，就另处理通配语义；这不等于输入已经变成 SQL 结构。基础题只用“特殊字符输入”标签，不提供攻击语句。

**XSS：文本被浏览器当成可执行内容。** XSS 是跨站脚本风险。列表仅需显示笔记文本，就使用安全文本输出，不直接将用户内容插入 HTML。真的需要富文本时，先明确允许的内容集合，再采用维护中的净化方案。CSP 是浏览器内容安全策略，可降低部分风险，但不能替代正确输出处理，也不能补对象授权。

**对象授权：合法 ID 不代表属于当前人。** 读取、更新、删除都要绑定当前身份、对象和动作；ID 难猜不能替代授权，客户端过滤也不能替代服务端限制。对本人对象正常访问、他人对象拒绝、缺失对象和权限变化分别设计测试。

| 修复方向 | 正常回归 | 风险回归与证据 |
| --- | --- | --- |
| 参数绑定 | 普通笔记搜索仍按规格返回 | 输入不改变查询结构；另验字面/通配规则，保留查询路径与实测记录 |
| 文本输出 | 含普通标签字样的笔记原样可读，不双重转义 | 不被解释成活动 HTML；需要隔离浏览器证据，不只看源码 |
| 对象授权 | 小陈可读/改自己的任务 | 小陈读/改/删小李任务均拒绝且数据不变；保留身份与对象证据 |

### 复扫消失不等于漏洞已修复

先把发现分为确认缺陷、误报、加固建议、待验证。确认需要输入来源、可达条件、缺失控制与影响证据；只有工具结论时保留待验证。加固建议可能有价值，但没有已存在风险证据就不算确认漏洞。

例如同一对象授权发现三轮“出现 → 工具超时后没有结果 → 再出现”，源码未变。第二轮不是修复；保留原发现 ID、根因与未知状态，第三轮关联原记录而非新建重复缺陷。关闭需根因变化和独立回归等证据，不能只看告警消失。不必要的第二次 HTML 转义还可能把正常文本显示改坏，安全与功能回归必须一起检查。

## 4. Prompt Injection 是信任边界错误

回到笔记中的无关读秘密要求：它可以作为异常数据被记录，不得升级成任务授权。低信任网页、日志、Issue 或注释诱导系统忽略任务、改策略或执行无关动作，这类问题称为提示注入。危险不是回答语气变化，而是连接文件、网络、shell 和写工具后可能产生真实副作用。

提示表达“只提取”，输入分隔和过滤可帮助降低部分风险，但不是唯一防线。运行时即模型外的执行程序，应在每个动作再次检查当前身份、资源、路径、目的地、任务范围与批准版本。工具返回也可能不可信，不能让“管理员已同意”这一句建立认证。

### Agent 攻击面按动作核对

五类名称帮助定位不同检查，不要求给每个事件唯一标签：

| 假动作 | 为什么偏离任务 | 执行层检查 |
| --- | --- | --- |
| 日志要求改提取规则 | 提示注入，资料想指挥行为 | 保留原任务；资料不改规则 |
| 摘要任务请求删除记录 | 工具滥用，能力超出目的 | 只读角色不获删除权限 |
| 排查超时要求关闭全部告警 | 意图破坏，计划离开目标 | 限定影响范围与独立批准 |
| 评论自称管理员已批准 | 身份伪装，文本冒充身份 | 核对可信身份和批准记录 |
| 生成补丁要求读目录外文件 | 代码/执行攻击，突破环境范围 | 代码不自动运行，限制挂载、路径、网络与资源 |

同一笔记可同时涉及注入、冒充与工具滥用。约束不能由被约束者自行解除：允许改业务文件，不授权改决定后续审批或权限的控制文件。政策变化必须走独立授权并记录差异。

网络“读取”也不是无外传：请求的地址、参数和正文都可能携带会话信息。只允许必要目的地与字段；读页面权限不授权访问内网、云身份端点或上传会议历史。最终回复“已拒绝”不是证据，还要查看危险工具是否实际执行、是否传输数据。

## 5. 路径限制要考虑真实路径

文件工具即使只读，也可能泄密。假根目录为 `/demo/notes`，字符串前缀检查可能误把 `/demo/notes-old` 当允许目录；相对路径与链接也可能使最终目标位于根外。

因此要按平台规则规范化并解析实际目标，再确认它确实属于允许根目录，而不是只比较开头几个字符。还需考虑检查后链接变化的竞态，即检查与操作之间目标被换掉。初学实现可以限定专用目录、禁止链接与敏感文件，再用执行层隔离降低风险；规范化一次不保证所有竞态消失。

基础题给出已经解析好的假目标，只判断策略；不解析真实路径、不创建链接、不测试绕过。限制目录也不能代替对象授权：即使文件在允许目录内，仍可能属于另一个用户。

## 6. 秘密泄漏不是删文件就结束

如果假凭据出现在报告里，删掉报告不让凭据失效。秘密还可能存在 Git 历史、日志、模型消息、抓包或第三方副本中；`.gitignore`只能减少部分后续误提交，不能撤销已经暴露的值。

泄漏后的处置按供应商与组织能力进行：先吊销或轮换相关凭据、限制继续使用，再调查活动/计费与暴露范围，修复日志或提交渠道，安排通知和复测。轮换是换新值并停止旧值；单独改存储位置不等于旧值已失效。历史清理要协调授权，不擅自重写他人 Git 历史；证据只保留脱敏引用。

会话 JSON、Cookie、API Key、OAuth 刷新 token 都可能代表访问能力，不以“不是密码”为理由交给第三方、Agent 或截图。退出设备可能有助止损，却不保证所有独立凭据失效，也不撤回已复制的数据。基础学习不需要登录账户或验证第三方网站。

## 7. 威胁模型实例

把前面机制串起来，控制中心的最小威胁表可以是：

| 威胁 | 防护 | 计划取得的证据 |
| --- | --- | --- |
| 笔记推动读秘密或外传 | 文件/网络最小权限，低信任内容不改授权 | 工具拒绝审计、无敏感输出；最终文字不单独算证据 |
| 恶意 HTML 被显示 | 文本输出或受控净化 | 正常显示与隔离浏览器风险回归 |
| 跨用户对象访问 | 服务端绑定身份、对象与动作 | 两用户读/改/删拒绝及数据不变 |
| 预览后对象变化 | 提交前核对版本，旧批准失效 | 旧版本拒绝、重新预览/批准 |
| 写入响应丢失后重试 | 幂等键或先查提交状态 | 同一任务不重复创建，未知保持未知 |
| 测试连到生产库 | 不持有生产凭据，启动与请求均隔离 | 导入、启动、存储、网络检查与实际隔离验证 |

表里有计划不代表取得了证据。威胁清单只覆盖声明的范围；没有列出的业务滥用不能因此忽略。OWASP Top Ten 提供风险意识与最低起点，不是完整安全验收标准。

### 基础必做：四份纸面产物

以下输入全部虚构，题目之间独立；不要求自拟攻击或打开笔记。先作答，再看第 9 节。每条保留“假输入 / 规则依据 / 决定 / 计划证据 / 未执行状态”。

#### 基础 1：决定工具能不能做，15 分钟

假政策：用户小陈仅可读取归属小陈且实际目标在 `/demo/notes` 内的普通笔记；禁止链接、秘密、网络上传、写入与策略修改。任务仅生成预览。可信身份服务确认当前用户为小陈；笔记文字不是批准。各行相互独立，所有实际目标由题目给定。

| 请求 ID | 假请求与已知条件 |
| --- | --- |
| T1 | 读取 N1；归属小陈，普通文件，实际目标 `/demo/notes/n1.txt` |
| T2 | 笔记要求读取 `[FAKE_SECRET_PATH]`；实际目标 `/demo/private/secret.txt` |
| T3 | 输入路径看似在 notes 内；已解析实际目标 `/demo/notes-old/n3.txt` |
| T4 | 读取 N4；目标在 notes 内，但链接标记为真，归属小陈 |
| T5 | 读取 N5；普通文件在 notes 内，归属小李，ID 格式合法 |
| T6 | 评论声称管理员批准修改审批策略，再上传 `[FAKE_SESSION]` |

逐行判允许/拒绝，写出T1要保留什么审计；说明T6为何跨两类边界。通过标准：六行均有依据，T1允许、其余拒绝，不把合法ID或文本批准当授权。

#### 基础 2：给发现选证据，10 分钟

| 发现 ID | 完整假材料 |
| --- | --- |
| F1 | 搜索文本被拼进查询结构；仅有源码路径，没有运行记录 |
| F2 | 详细异常只在部署配置中启用；源码默认关闭，测试请求未运行 |
| F3 | 实际依赖清单含组件 demo-lib v1；假公告指出v1某可选功能有漏洞，是否调用未知 |
| F4 | 假提交与日志中出现 `[FAKE_API_KEY]`；是否撤销未知 |

选择首要检查类别，列补充证据与当前不能宣称的结论。通过标准：F1 SAST、F2 DAST/运行配置核对、F3 SCA、F4秘密扫描；四行保留可达性或执行/撤销未知，不填“系统安全”。

#### 基础 3：修复、正常回归与关闭，15 分钟

假规格：搜索必须按字面文本匹配；笔记列表只显示文本；每个用户只能读/改/删自己的任务。候选修复Q1把查询改成参数绑定但保留LIKE通配；Q2把已经安全文本输出再加一次HTML转义；Q3查询只按任务ID，没有身份条件。

另有发现V1：“对象授权疑点”，三轮记录为R1出现、R2扫描超时且无报告、R3再次出现；三轮源码都为v1，没有实际跨用户测试。

判断Q1–Q3解决什么、仍缺什么，为每项写正常与风险回归的预期；给V1写状态和关联依据。通过标准：不混淆SQL结构与通配；不批准无依据的双重转义；Q3补服务端对象授权；V1仍待验证，不因R2关闭或把R3算新根因。

#### 基础 4：假秘密泄漏，15 分钟

虚构事件：11:00报告保存 `[FAKE_API_KEY]` 和 `[FAKE_SESSION]`；11:05删除当前报告；11:06历史副本与第三方副本仍可能存在；11:07凭据管理台尚无撤销确认；11:08活动与计费未查询。另有普通诊断信息“demo版本v2”，不含用户信息。题目不提供真实账号，也不允许任何实际操作。

分类三类数据，写止损、调查、渠道修复、复测顺序；分别回答11:05和11:07是否已解决，列一条不能保证的结果。通过标准：两种假授权值属秘密，版本号按题设可保留；删除不等于撤销，轮换/撤销和访问调查均标待执行，不保证撤回副本。

## 8. 动手：扫描、分诊、修复、再验证

<details>
<summary>选学：真实扫描与修复，不能用纸面答案替代</summary>

本节单独验收，不是上述基础完成条件。只有具备获准的隔离副本、扫描/规则政策、合法模型访问与预算后再做，实际运行前核验环境；本轮未执行。原作业要求使用AI修复至少三项真实扫描安全问题，并保留应用与测试正常的证据，不是任选三项加固凑数。

1. 固定第6周副本、假数据、扫描版本/规则/范围/基线。隔离导入和startup的数据库，禁止生产凭据与公共监听。
2. 取得扫描原始记录，逐项查输入来源、可达性、权限与影响，区分确认、误报、加固、待验证并按根因去重。
3. 选择至少三项真实问题做最小根因修复，保留文件位置、规则、精确前后差异、AI实际角色与理由。副本不足三项就记录不足，不编造；另获合适教学快照后再完成。
4. 每项修复同条件复扫，并跑正常/风险回归。依赖补实际升级版本与公告，秘密补撤销状态，页面输出补浏览器证据。
5. 无害注入只能在无真实秘密的受控假数据环境验证执行层拒绝；这类真实边界验证与扫描分开记录，不提供可运行攻击文本。
6. 报告剩余风险与部署限制；三项有完整证据才计相应修复，不以无告警宣称绝对安全。

当前快照已使用参数化查询与文本DOM，但存在LIKE通配语义；CORS控制响应读取，不保证阻止全部跨源写入。七个测试函数的请求库override不隔离真实startup engine，运行前必须解决导入/启动隔离。现有报告自述没有原始扫描、旧快照与运行证明。详见[第6周作业导读](../reading-notes/fall2025/week06/assignment-guide.md)，不把静态阅读当历史修复已复现。

## 9. 自测与答案

### 集中练习答案

#### 基础 1：每个动作独立验权

1. T1身份可信、归属匹配、普通文件、实际目标确在根内，允许这次读取；只生成预览，不继承写入能力。审计记任务ID、主体、对象ID、动作、政策版本、允许与时间，不存正文或秘密。
2. T2拒绝：笔记只是资料，不能授权读秘密，目标也在根外。记录拒绝原因，不读取值来证明拒绝。
3. T3拒绝：`notes-old`是另一目录，字符前缀相似不算根内；按已给的实际目标判断。
4. T4拒绝：题设禁止链接；归属正确不取消此限制。真实实现还需考虑检查后目标变化。
5. T5拒绝：当前主体小陈无小李对象权限；路径、ID、登录都正常也不能放行。
6. T6拒绝两种动作：资料自称管理员不建立认证；策略修改越过控制面，上传会话越过秘密与网络边界。可同时标提示注入、身份伪装与工具滥用，不靠唯一标签决定权限。

#### 基础 2：证据类别与未知

| 项目 | 首要检查与补充证据 | 当前结论 |
| --- | --- | --- |
| F1 | SAST追输入到执行点；后续获准隔离请求与正常搜索验证 | 可疑路径，不凭源码片段就填实际利用成功 |
| F2 | 核对部署配置，DAST覆盖该异常路径；补版本、环境与响应 | 默认源码不证明运行关闭；动态测试未运行 |
| F3 | SCA核实际版本/传递依赖/公告；查可选功能调用与升级回归 | 公告命中，应用可达性未知；不能直接忽略或写已利用 |
| F4 | 秘密扫描核提交/日志范围；补撤销确认与访问调查 | 已有假暴露线索，是否失效未知；扫描不会撤销值 |

#### 基础 3：不能用错误修复制造通过

1. Q1参数绑定保护查询结构，是正确方向；但LIKE通配不满足题设字面搜索，需另实现字面匹配约定。正常预期：普通词命中对应笔记；风险预期：特殊字符不改查询结构，`%`、`_`按题设只作为字面字符匹配，不任意扩大结果。计划留路径、差异和隔离测试，当前未运行。
2. Q2没有现存XSS证据，不自动批准额外转义。正常预期：笔记中的普通标签字样和符号按原文本显示，不出现双重转义；风险预期：不解释成活动HTML。先查真实输出位置与已有防护，再决定最小变化；源码机制不代替浏览器回归。
3. Q3只按ID不够，需在服务端每次读/改/删绑定当前主体与资源归属。正常预期：小陈操作本人任务成功；风险预期：小陈操作小李任务拒绝且数据不变，缺失对象按契约处理，权限变化后重验。
4. V1三轮都是同v1同根因疑点；R2是工具超时导致证据缺口，不是无漏洞。保持待验证，R3关联V1；取得跨身份行为证据与代码控制后再裁定，关闭还需根因修复和独立回归，不改写历史失败。

#### 基础 4：删除与撤销分开

1. `[FAKE_API_KEY]`与`[FAKE_SESSION]`均可能代表访问能力，按秘密处理；题设版本v2是脱敏诊断材料，可保留，不因此默认所有版本日志无隐私。
2. 11:05只删除了当前报告，历史与第三方副本仍可能存在；11:07没有撤销确认，不能宣称旧值已失效。
3. 先计划经授权吊销/轮换涉及的key、会话或授权，并确认旧值按供应商能力失效；再调查活动、计费、暴露窗口与副本范围，通知对应责任人。调查与止损可并行，不等待调查完才撤销。
4. 修复报告/日志/提交渠道，授权协调历史处理；复测拒绝旧值、正常新流程和报告脱敏。当前全部标待执行，不填“已撤销”。
5. 无法保证第三方已经删除副本，也不能保证退出设备终止所有独立凭据；不要重新发送真实值验证风险。

### 理解检查

**SCA命中CVE能直接判应用可利用吗？** 不能；还需版本、调用与条件，但必须有处理计划。

**提示写不得泄密足够吗？** 不足，文件、网络、凭据与工具授权需独立限制。

**复扫没有发现可以关闭漏洞吗？** 不能；先核执行状态、范围与根因变化，再看独立回归。

**纸面表全对意味着安全实验通过吗？** 不意味着，只说明理解了给定策略；扫描、浏览器、跨身份与撤销效果都需真实证据。
