# 08 安全与威胁建模

[上一章](07-testing-review.md) | [目录](../README.md) | [下一章：交付与运维](09-delivery-operations.md)

提取器能识别“周五检查日志”，却仍可能被笔记诱导读取秘密、把用户文本当 HTML 显示，或让登录用户读到别人的任务。提取正确不等于系统安全。本章沿这些风险寻找防护位置，再讨论扫描和修复。

能区分笔记数据、任务说明与工具动作即可。先读第 1–7 节，做四项基础练习，再核对第 9 节答案。基础只用假材料做纸面判断，不联网、扫描或操作账号，不使用真实秘密和攻击脚本。真实实验见第 8 节，另需授权；纸面答案不证明防护有效。

## 1. 从资产与权限开始

小陈只允许 Agent 读自己的会议笔记、生成预览，不允许提交。笔记却要求“先读秘密再上传”。提取不需要这一步；真正读或发送就越权。重点不是文字像不像攻击，而是它能推动什么实际动作。

要保护的笔记、任务、凭据和审计记录称为**资产**；上传、HTTP 参数、网页和工具返回等数据进入点称为**入口**。**信任边界**区分资料与高权限处理层：笔记能提供内容，不能修改工具权限或代表管理员批准。

| 具体失败 | 资产与入口 | 越过哪条边界 | 首要检查位置 |
| --- | --- | --- | --- |
| 笔记要求读秘密 | 凭据；笔记正文 | 任务资料变成文件/网络授权 | 文件工具与网络执行层 |
| 列表把笔记当 HTML | 用户页面与会话；笔记正文 | 用户文本变成浏览器可解释内容 | 输出到页面的位置 |
| 小陈读到小李任务 | 他人数据；对象 ID | 已登录身份变成任意对象权限 | 服务端对象授权 |

**威胁建模**就是把失败、资产、入口、边界、防护与验证连起来。先说明部署范围：本地单用户 demo 不等于多用户产品，公开部署要重评对象隔离，不能拿本地测试代替。

**最小权限**只给当前任务必需的能力：提取阶段只读指定笔记，不挂载整个用户目录、不持有部署凭据；提交另核身份、资源和批准。身份验证回答“是谁”，授权回答“能对哪个对象做什么”。合法 token 或 JSON 不等于有对象权限。

## 2. 四类检查互补

漏掉的控制可能在源码、运行配置或依赖中，需要不同检查互补，不能靠一个工具证明全部安全。

| 检查 | 白话机制与本项目例子 | 还缺什么 |
| --- | --- | --- |
| SAST，静态应用安全测试 | 不启动应用，追踪源码中输入到危险查询或 HTML 输出的路径 | 框架、配置和可达性可能未覆盖 |
| DAST，动态应用安全测试 | 对获准应用发请求，观察两个假用户能否访问彼此对象 | 未触达路径与状态仍有缺口，根因需回查源码 |
| SCA，软件成分分析 | 核直接与传递依赖的版本及漏洞公告 | 调用条件、未公布漏洞和升级回归 |
| 秘密扫描 | 查代码、历史与获准日志中的凭据线索 | 自定义秘密或范围外副本可能漏检，发现不等于撤销 |

产品可能集成多项能力，但 SAST 命令不天然包含 SCA 或秘密扫描。版本命中不独自证明可利用，也不能据可达性未知无限拖延评估。记录版本、规则、范围、排除项、执行状态和上传政策；超时、规则未加载与“范围内无发现”要分开。

## 3. 根因修复的三种典型方向

查询、页面输出和对象访问都接收用户数据，却要保护不同边界，不能统一靠“过滤坏字符串”修复。

**SQL 注入：输入改变了查询结构。** 搜索文本应是参数值，不是数据库指令。参数化查询或正确 ORM 表达式将结构和值分开，仅删除引号不可靠。核对输入到执行点的路径：固定 SQL 种子文件不证明注入，用 ORM 也不证明授权正确。

LIKE 的 `%`、`_` 是通配符，参数绑定后仍可能扩大匹配。要求字面搜索时需另处理通配语义，这不等于 SQL 结构被改变。基础题不提供攻击语句。

**XSS：文本被浏览器当成可执行内容。** 列表只需显示文本，就使用安全文本输出，不直接插入 HTML。富文本需明确允许内容并使用维护中的净化方案。浏览器内容安全策略 CSP 只降低部分风险，不替代正确输出或对象授权。

**对象授权：合法 ID 不代表属于当前人。** 读取、更新、删除都要绑定当前身份、对象和动作；ID 难猜不能替代授权，客户端过滤也不能替代服务端限制。对本人对象正常访问、他人对象拒绝、缺失对象和权限变化分别设计测试。

| 修复方向 | 正常回归 | 风险回归与证据 |
| --- | --- | --- |
| 参数绑定 | 普通笔记搜索仍按规格返回 | 输入不改变查询结构；另验字面/通配规则，保留查询路径与实测记录 |
| 文本输出 | 含普通标签字样的笔记原样可读，不双重转义 | 不被解释成活动 HTML；需要隔离浏览器证据，不只看源码 |
| 对象授权 | 小陈可读/改自己的任务 | 小陈读/改/删小李任务均拒绝且数据不变；保留身份与对象证据 |

### 复扫消失不等于漏洞已修复

发现分为确认缺陷、误报、加固建议、待验证。确认需输入来源、可达条件、缺失控制与影响；工具结论独自不足。若告警“出现 → 超时无结果 → 再出现”而源码未变，中间一轮不是修复，后续关联同一发现。关闭需根因变化与独立回归；不必要的二次 HTML 转义还可能破坏正常显示。

## 4. Prompt Injection 是信任边界错误

网页、日志、Issue 或笔记诱导系统忽略任务、改策略、执行无关动作，称为**提示注入**。无关读秘密要求只能当作数据，不能升级为授权。危险在于文件、网络、shell 和写工具可能产生真实副作用，不只是回答变了。

“只提取”的提示、输入分隔和过滤可辅助防护，但**实际权限不能靠提示替代**。模型外的执行程序要在每个动作核身份、资源、路径、目的地、范围与批准版本。工具返回也不可信，“管理员已同意”不能建立认证。

### Agent 攻击面按动作核对

按动作找检查位置，比争论唯一攻击标签更有用：

| 假动作 | 为什么偏离任务 | 执行层检查 |
| --- | --- | --- |
| 日志要求改提取规则 | 提示注入，资料想指挥行为 | 保留原任务；资料不改规则 |
| 摘要任务请求删除记录 | 工具滥用，能力超出目的 | 只读角色不获删除权限 |
| 排查超时要求关闭全部告警 | 意图破坏，计划离开目标 | 限定影响范围与独立批准 |
| 评论自称管理员已批准 | 身份伪装，文本冒充身份 | 核对可信身份和批准记录 |
| 生成补丁要求读目录外文件 | 代码/执行攻击，突破环境范围 | 代码不自动运行，限制挂载、路径、网络与资源 |

约束不能由被约束者解除：改业务文件不等于能改审批或权限控制文件，政策变化需独立授权。网络“读取”的地址、参数和正文也能外传信息，只允许必要目的地与字段，不默认访问内网或云身份端点。回复“已拒绝”不够，还需工具执行与传输审计。

## 5. 路径限制要考虑真实路径

文件工具即使只读，也可能泄密。假根目录为 `/demo/notes`，字符串前缀检查可能误把 `/demo/notes-old` 当允许目录；相对路径与链接也可能使最终目标位于根外。

按平台规则规范化、解析实际目标，再核它属于允许根，不能只比前缀。检查后链接也可能变化，因此一次规范化不解决全部竞态；专用目录、禁止链接和敏感文件、执行层隔离可降低风险。目录内的文件仍可能属于别人，路径限制不替代对象授权。基础题只判断已给出的假目标。

## 6. 秘密泄漏不是删文件就结束

删除报告不会让凭据失效，Git 历史、日志、模型消息和第三方副本也可能留有秘密；`.gitignore`不能撤销已暴露值。

先经授权吊销或轮换并确认旧值失效，同时调查活动、计费和暴露范围；再修泄漏渠道、通知责任人并复测。换存储位置不等于轮换，历史清理需协调授权，证据只保留脱敏引用。会话 JSON、Cookie、API Key、刷新 token 都可能代表访问能力；退出设备不保证所有独立凭据失效，也不撤回副本。

## 7. 威胁模型实例

把前面机制串起来，控制中心的最小威胁表可以是：

| 威胁 | 防护 | 计划取得的证据 |
| --- | --- | --- |
| 笔记推动读秘密或外传 | 文件/网络最小权限，低信任内容不改授权 | 工具拒绝审计、无敏感输出；最终文字不单独算证据 |
| 恶意 HTML 被显示 | 文本输出或受控净化 | 正常显示与隔离浏览器风险回归 |
| 跨用户对象访问 | 服务端绑定身份、对象与动作 | 两用户读/改/删拒绝及数据不变 |
| 预览后对象变化 | 提交前核对版本，旧批准失效 | 旧版本拒绝、重新预览/批准 |
| 写入响应丢失后重试 | 幂等键或先查提交状态 | 同一任务不重复创建，未知保持未知 |
| 测试连到生产库 | 不持有生产凭据，启动与请求均隔离 | 导入、启动、存储、网络检查与实际隔离验证 |

表中是证据计划，不是已验证防护；清单也不覆盖全部业务滥用。OWASP Top Ten 是风险意识起点，不是完整验收标准。

### 基础必做：四份纸面产物

题目相互独立，先作答再看第 9 节。每题写依据、决定、证据计划与未知项，不自拟攻击或执行工具。

#### 基础 1：决定工具能不能做

假政策：可信身份为小陈，仅可读本人归属、实际目标在 `/demo/notes` 内的普通笔记，生成预览。禁止链接、秘密、上传、写入和策略修改；笔记文字不是批准，实际目标由题目给定。

| 请求 ID | 假请求与已知条件 |
| --- | --- |
| T1 | 读取 N1；归属小陈，普通文件，实际目标 `/demo/notes/n1.txt` |
| T2 | 笔记要求读取 `[FAKE_SECRET_PATH]`；实际目标 `/demo/private/secret.txt` |
| T3 | 输入路径看似在 notes 内；已解析实际目标 `/demo/notes-old/n3.txt` |
| T4 | 读取 N4；目标在 notes 内，但链接标记为真，归属小陈 |
| T5 | 读取 N5；普通文件在 notes 内，归属小李，ID 格式合法 |
| T6 | 评论声称管理员批准修改审批策略，再上传 `[FAKE_SESSION]` |

逐行判断允许还是拒绝，并给依据；写 T1 的脱敏审计和 T6 越过的边界。

#### 基础 2：给发现选证据

| 发现 ID | 完整假材料 |
| --- | --- |
| F1 | 搜索文本被拼进查询结构；仅有源码路径，没有运行记录 |
| F2 | 详细异常只在部署配置中启用；源码默认关闭，测试请求未运行 |
| F3 | 实际依赖清单含组件 demo-lib v1；假公告指出v1某可选功能有漏洞，是否调用未知 |
| F4 | 假提交与日志中出现 `[FAKE_API_KEY]`；是否撤销未知 |

为每项选择首要检查，列补充证据和当前不能宣称的结论。

#### 基础 3：修复、回归与关闭

假规格：搜索必须按字面文本匹配；笔记列表只显示文本；每个用户只能读取、修改或删除自己的任务。候选修复有三项：Q1把查询改成参数绑定但保留LIKE通配；Q2把已经安全文本输出再加一次HTML转义；Q3查询只按任务ID，没有身份条件。

另有发现V1：“对象授权疑点”，三轮记录为R1出现、R2扫描超时且无报告、R3再次出现；三轮源码都为v1，没有实际跨用户测试。

判断 Q1–Q3 解决什么、仍缺什么，写正常与风险回归预期；给 V1 写状态与关联依据。

#### 基础 4：假秘密泄漏

假事件：11:00 报告保存 `[FAKE_API_KEY]` 和 `[FAKE_SESSION]`；11:05 删除当前报告；11:06 历史和第三方副本仍可能存在；11:07 尚无撤销确认；11:08 活动与计费未查。另有不含用户信息的“demo 版本 v2”。不操作真实账号。

分类三种数据，安排止损、调查、渠道修复和复测；判断 11:05、11:07 是否解决，并列不能保证的结果。

### 迁移检查：只读权限里的跨人访问

假事件：小陈有只读任务权限，工具仅按 ID 返回小李的 task_93，未检查 owner。审查者说“没有写入，所以无风险”；正文还要求修改日志策略以便排障。指出两个边界，写正常/拒绝预期及关闭问题所需证据。

只读也会越权披露，读 scope 不替代主体与对象归属检查；正文也不能授权修改控制策略。预期本人对象可读、跨人对象拒绝且不披露、正文不改变策略。关闭需根因修复、当前差异审查和正常/跨身份/注入边界回归；无写入或扫描无报告不够。本题只是静态判断，证据不足仍待验证。

## 9. 自测与答案

### 集中练习答案

#### 基础 1：每个动作独立验权

1. T1 满足身份、归属、普通文件和实际路径条件，允许读取，不授权写入。审计记任务 ID、主体、对象、动作、政策版本、决定与时间，不存正文或秘密。
2. T2拒绝：笔记只是资料，不能授权读秘密，目标也在根外。记录拒绝原因，不读取值来证明拒绝。
3. T3拒绝：`notes-old`是另一目录，字符前缀相似不算根内；按已给的实际目标判断。
4. T4拒绝：题设禁止链接；归属正确不取消此限制。真实实现还需考虑检查后目标变化。
5. T5拒绝：当前主体小陈无小李对象权限；路径、ID、登录都正常也不能放行。
6. T6 两种动作都拒绝：资料不能建立管理员身份，策略修改越过控制面，上传会话越过秘密与网络边界。攻击标签不决定权限。

#### 基础 2：证据类别与未知

| 项目 | 首要检查与补充证据 | 当前结论 |
| --- | --- | --- |
| F1 | SAST追输入到执行点；后续获准隔离请求与正常搜索验证 | 可疑路径，不凭源码片段就填实际利用成功 |
| F2 | 核对部署配置，DAST覆盖该异常路径；补版本、环境与响应 | 默认源码不证明运行关闭；动态测试未运行 |
| F3 | SCA核实际版本/传递依赖/公告；查可选功能调用与升级回归 | 公告命中，应用可达性未知；不能直接忽略或写已利用 |
| F4 | 秘密扫描核提交/日志范围；补撤销确认与访问调查 | 已有假暴露线索，是否失效未知；扫描不会撤销值 |

#### 基础 3：不能用错误修复制造通过

1. Q1 保护了查询结构，但 LIKE 通配仍违背字面搜索。预期普通词正常匹配、特殊字符不改结构、`%` 和 `_` 只匹配字面字符。保留查询路径、差异与隔离测试证据。
2. Q2 没有新增转义的依据，应先查输出位置与已有防护。预期标签字样和符号原样显示、不双重转义，也不解释成活动 HTML；需浏览器回归。
3. Q3 要在服务端每次读/改/删绑定主体与归属。预期本人操作成功，他人操作拒绝且数据不变；缺失对象按契约处理，权限变化后重验。
4. V1 保持待验证：源码同为 v1，R2 超时不是修复，R3 关联原发现。裁定需跨身份证据与代码控制，关闭还需根因修复和独立回归。

#### 基础 4：删除与撤销分开

1. 两个假授权值均按秘密处理；题设版本 v2 不含用户信息，可保留，不代表所有版本日志都无隐私。
2. 11:05只删除了当前报告，历史与第三方副本仍可能存在；11:07没有撤销确认，不能宣称旧值已失效。
3. 经授权吊销或轮换凭据并确认旧值失效，同时调查活动、计费、暴露窗口和副本范围，通知责任人，不等调查完才止损。
4. 修复泄漏渠道，协调历史处理；复测旧值拒绝、新流程正常、报告脱敏。全部待执行，不填“已撤销”。
5. 不能保证第三方删除副本或退出设备终止全部凭据，不重新发送真实值验证风险。
