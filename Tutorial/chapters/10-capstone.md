## 1. 从个人工具到组织系统

控制中心能为自己的笔记生成预览，团队接入后却有了新问题：同一Issue被重复触发，小陈的Agent请求小李的笔记，改过的补丁沿用旧审批。个人使用成功，不代表多人重复运行仍可靠。本章把权限、预算、检查和批准连成可验证的交付流程。

**前置与成果**

- 能区分候选结果、检查、批准和执行，会读事件表与加法即可；本章基础材料完整给出。
- 完成双网关职责图、任务预算决定、门禁失败记录和交付缺口表。
- 基础题只分析虚构材料，不联网、调用模型或实际写入。真实项目另行交付。

### 章内路线

| 路线 | 阅读与行动 | 估计预算 |
| --- | --- | --- |
| 多人调用谁的能力 | 第1–2节，基础1–2 | 阅读20–25分钟，练习25分钟 |
| 流水线什么时候必须停 | 第3–4节，基础3–4 | 阅读20–30分钟，练习35分钟 |
| 从学习到实际交付 | 第5–10节、基础5与对应答案 | 阅读15–20分钟，练习10分钟，核对15分钟 |
| 按需扩展 | 折叠厂商材料、真实综合项目与开源贡献 | 不计基础预算，另设执行条件与预算 |

基础阅读约55–75分钟，五题约70分钟，建议分两次，时间仅供规划。先设计能拒绝错误的最小流程，不必搭网关或十个服务。本章按2026团队与软件工厂主题组织；阶段机制和练习是教程扩展，不补写未取得的第7–10周课堂正文或后续作业。

### 两种网关不能互相代替

跨人访问和模型费用需要不同的检查。**网关**是在集中入口执行策略的服务：MCP工具网关检查“谁用哪个工具、对什么对象做什么”，LLM模型网关检查“哪些材料可交给哪个模型、花多少预算”。门户帮助发现工具，但看得到不等于有权执行。

```text
小陈 / 任务T -> 工具客户端 -> MCP工具网关 -> 笔记服务 -> 小陈对象
                         -> LLM模型网关 -> 获准模型供应商
两个链路共享任务ID便于关联，工具授权与模型预算各自强制检查
```

小陈只能读本人笔记并生成预览。工具端须检查身份、能力范围（scope）、对象和动作，不能在只读入口背后共享无限权限的管理员账号。短期凭据仍需最小权限、撤销和审计。工具读取获准，也不代表私有材料可发给任意模型。

集中入口方便统一治理，也会聚合权限、成为故障点；失败时不能绕过。写入与部署权限应分开，每次核对当前政策和批准版本。

## 2. 模型路由与成本

轻量模型单次便宜，却可能修三次才通过；权限代码只改一行，也可能影响所有用户。**路由**应按风险、质量、延迟、数据政策和预算选路径，不能只看行数、单价或模型自信。

给整个任务设费用、次数和时间上限，每次行动前预留下一步费用上界，包括工具与人工核验。每次0.3单位，调用三次就超过一次0.8单位的费用；并行和长上下文也会增加用量。缓存不等于免费，token总数也不直接等于账单。

最小策略是：独立验证过的低风险格式化走轻量路径；权限、迁移或未知依赖转严格审查。失败后在剩余预算内有限修复，仍失败就交人工。撤权、坏凭据和数据政策问题不能靠换模型绕过；切换后也要重验输出与拒绝规则。

预算用尽就停止、保留失败和现有证据。新增预算须外部授权，反馈不能自行扩大资源范围。

## 3. Software Factory 的可操作定义

为避免重复发布、检查超时被当通过、旧审批继续有效，需要一条绑定身份、版本、证据和停止条件的流水线。本教程称它为Software Factory（软件工厂），不意味着模型无限自改或无人负责。

```text
需求或 Issue
  -> 研究与规格
  -> 计划与风险分级
  -> 隔离环境实现
  -> 测试、评测、安全检查
  -> 独立审查与批准
  -> 受控发布
  -> 观测与反馈
  -> 下一个受控改进任务
```

**门禁**由执行层阻止不合格产物进入下一阶段，不是表格写“已检查”。重复触发关联同一幂等任务ID；规格、差异、测试和批准绑定版本，变更后旧批准失效。撤权或预算不足时阻止新副作用、保留成果；取消任务不代表已发生的动作全部撤回。

| 阶段 | 小项目产物 | 出口检查与负责人职责 |
| --- | --- | --- |
| 规格 | 排序规则、非目标、假输入与预期 | 需求负责人确认验收可独立判定，模糊处先澄清 |
| 计划 | 只改范围、风险、身份与预算 | 协调者核权限、依赖与停止条件，不扩大原任务 |
| 实现 | 隔离候选差异与版本 | 实现者保存原始失败，不改检查器来凑通过 |
| 检查 | 单元与集成测试、语义评测、安全检查的证据与覆盖 | 检查失败或超时标不完整，不视为无缺陷 |
| 独立审查与批准 | 当前差异的审查、可信批准者记录 | 不是实现者自评；批准绑定任务、对象、版本与有效期 |
| 受控发布 | 获准版本与执行审计 | 发布者重验当前授权、预算、版本；批准不等于已经发布 |
| 观测与反馈 | 运行、降级、恢复证据与下一任务 | 运维负责人核结果，反馈先形成新受控任务 |

真实门禁须实测失败、重复、超时、撤销和版本变化确实被阻断，纸面推演只验证理解。

## 4. 自动改进也需要评测隔离

模型看过答案后同题通过，可能只是记住了答案。开发集用于修改提示和实现；留出验收集在方案冻结后由独立评价者判定。按原场景分组，不能把同一笔记的改写分别放进两边。根据验收失败改过方案后，该题转为开发资料，下次须换新留出题。

生产反馈应带症状、版本、证据和期望，形成新受控任务，而非直接修改生产的授权。评测还要检查流程：失败不进批准、旧批准不进发布、重复不重复写入、撤权阻止后续动作。独立缺陷发现不能提前看到答案、修复提交或事后wiki。

### 动手：纸面工厂也必须能拒绝失败

先用假记录检查：证据失败、批准过期或撤权时，流程知道在哪里停吗？

### 基础必做：五项集中练习

各题独立，仅分析给定虚构材料。记录“事实、规则与证据、决定、未知、停止与交接”五项，第10节给出答案。

#### 基础 1：双网关，10分钟

题设：可信身份为小陈；任务T只允许读归属小陈的N1、生成预览，禁止提交；私有笔记仅可发模型A，B未获数据许可。MCP网关工具端有对象授权；LLM网关核供应商和模型预算。四个独立假请求：G1读N1、G2读小李N2、G3把N1发B、G4模型A生成合法JSON后提交预览。

画两条链，逐项判断允许或拒绝，并标出检查位置。

#### 基础 2：总任务预算，15分钟

虚构低风险格式化任务U只处理公开假文本。已通过独立质量题的轻量路线L每次费用上界0.3单位，较强路线H每次0.8，人工核验预留0.2；整个任务模型+核验限1.0单位、最多2次模型调用、最多1次修复，限时10分钟。首轮L花0.3且测试失败；工具费用题设为0，时间尚余6分钟，无政策改变。

计算下一轮L或H连同核验的总额，判断能否启动。另一高风险权限任务V只有L的格式化评测，缺授权回归；Agent声称自信，能否因“少于三行”放行？

#### 基础 3：稳定排序候选，15分钟

本题局部规格S1为时间升序、同时间ID升序，只排序，不增删或改标题；不改变第02–03章主线的降序约定。输入：`[(id=2,time=09:00,title=核对日志),(id=1,time=09:00,title=检查备份),(id=3,time=10:00,title=更新说明)]`，预期ID为`[1,2,3]`。

三个假候选：C1差异d1输出[1,2,3]、标题不变，检查和独立审查通过；C2差异d2输出[2,1,3]，测试失败；C3的d3a曾获批准，改成d3b后测试通过，但无新审查或批准。

判断各候选处于“等待当前批准、待发布或失败”哪种状态，说明原因和缺口。

#### 基础 4：完整门禁事件，20分钟

以下独立任务均在 10:03 时判断：重复事件关联原任务，最多修复两次；发布前核当前差异、批准有效期、权限、预算与检查。发布上界0.2，预留后总额须≤1.0；只有可信审核者R可批准，评论不证明身份。以后执行时仍须重新检查。

| 任务 | 完整假事件输入 |
| --- | --- |
| J1 | 10:00触发键K1、创建J1；10:01同K1重复；10:02 d1检查/独立审查通过；10:03 R批准J1/d1有效至10:10；已用0.5；尚无发布执行 |
| J2 | 10:00检查失败；10:01修复1仍失败；10:02修复2仍失败；10:03提出修复3，已用0.6 |
| J3 | 10:00 d3a检查/审查通过且R批准至10:10；10:02改成d3b，测试通过但无新审查；10:03用旧批准请求发布 |
| J4 | 当前d4检查/审查通过，R批准有效；已用0.9；提出发布，需0.2 |
| J5 | d5检查/审查通过，10:00 R批准有效至10:10；10:02可信身份服务撤销任务写权；10:03提出发布，已用0.5，尚无执行 |
| J6 | d6检查/审查通过，R批准仅至10:02；10:03提出发布；评论声称“管理员延长批准”，没有可信记录，已用0.5 |

逐行写状态、拒绝或待发布原因、下一合法步骤与应保留的证据；没有执行记录，不得写“已发布”。

#### 基础 5：反馈与交付缺口，10分钟

假材料：D开发场景含已完成/否定任务，模型见答案后同题通过；H是D的同义改写却被标“隐藏”；Z是真正未用于开发的新场景，提示冻结后由评价者核对；Z失败后开发者再调整提示。项目P仅有规格、上述纸面门禁与mock截图，没有CRUD/重启、真实LLM评测、工具拒绝或恢复运行记录。

判断D/H/Z能证明什么、修改后Z如何归类；将P缺口对应M2–M5，并判断能否按自学评分表满分交付。

## 5. 综合项目要求

**这是独立实际项目，不是纸面题的通过条件。** 可继续做行动项提取器/控制中心，或同等复杂度的小项目。先取得环境与模型访问授权，设隐私、费用和时间边界；条件不足就保留未完成，不用mock替代真实模型或恢复证据。

最低交付包括规格、持久化CRUD、无模型基线、真实LLM评测、错误/降级观测、单元与集成测试、安全边界、独立审查，以及可复现启动和回滚。一个可验证闭环优于十个不可运行的服务。先完成M1/M2，再为M3–M5分别设预算和停止条件。

进阶可选OAuth MCP组合与受控写入、经过触发验证的Skill、独立后台任务、网关或多模型路由；选定后需按对应原作业和真实接口独立验收，不能模拟OAuth冒充协议通过。

## 6. 五个交付里程碑

| 阶段 | 产物 | 通过条件 |
| --- | --- | --- |
| M1 定义 | 规格、非目标、风险与验收 | 他人能写出测试，不依赖口头解释 |
| M2 基线 | 最小应用与规则方案 | 新环境可运行，测试数据独立 |
| M3 AI 能力 | 模型功能、评测与错误处理 | 真实运行证据，所有失败计入 |
| M4 受控流程 | 审查、安全、自动化 | 门禁失败确实阻止后续动作 |
| M5 交付 | 运行文档、观测、回滚与复盘 | 另一位读者复现主流程与故障恢复 |

不要跳过 M2 直接优化模型。缺少可靠基线时，模型质量、程序 bug 和环境错误容易混为一谈。

### 将章节产物接到实际实现

复用前面章节的设计，再补运行证据，不重写十份报告。纸面产物可支撑M1，不能自动让M2–M5通过。

| 章节产物 | 进入阶段 | 下一步最小实现 | 必须补的验收证据 |
| --- | --- | --- | --- |
| 00环境计划、03规格与上下文 | M1 → M2 | 冻结范围，落实隔离数据配置 | 独立需求复核；版本、目录、命令、退出状态与数据路径 |
| 01标注与规则、03候选/预览 | M2 → M3 | 先做基线和CRUD，再接模型与降级 | 重启读取；真实模型输出、全部失败、成本与留出评测 |
| 02工具恢复、04契约与权限 | M3 → M4 | 实现参数、对象授权、超时及副作用限制 | 合法/拒绝调用、零写入预览、未知结果恢复；OAuth另验真实协议和双边界 |
| 05门禁、06交接、07审查、08安全回归 | M4 | 落实错误传播、当前版本审查和执行限制 | 失败/缺证据阻断、跨身份拒绝、独立审查与安全回归 |
| 09观测/恢复、10预算/批准 | M4 → M5 | 预留核验费用，关联请求与引擎，受控恢复 | 超额/旧批准拒绝；他人复现主流程与恢复，核数据完整性和兼容 |

用[模板](../reference/templates.md)记录项目版本、实现范围、命令、证据、失败与下一步。取消、幂等、后台接管和Skill自然触发等选学项需各自故障或触发验证，架构图不算完成。

### 开源贡献闭环

<details>
<summary>选学：真实协作贡献，公开发布须独立决定</summary>

开源训练重在解决真实问题，而非凑PR数量。先读目标项目的贡献指南、许可证、AI政策与测试要求，选择边界bug、有效回归测试或启动文档错误，避免无关重构。

例如同时间戳排序不稳定：先确认需求确实保证顺序并查重，在隔离环境记录版本、输入、预期和实际；写失败测试，最小修正第二排序键，再做回归与兼容说明。

用[贡献模板](../reference/templates.md)完成本地贡献包：问题依据、改前失败、最小差异、改后通过、风险和AI辅助披露。明确决定公开提交后，才按目标流程创建远程Issue/PR或推送，回应维护者并复测。无公开条件时可请他人审查，标为本地协作演练。

未回应、关闭或未合并都照实记录；本地准备不等于真实开源贡献，未被接纳也不抹去学习价值。官方权重与自学评分分别见下文来源说明。

</details>

| --- | --- | --- |
| 需求与规格 | 15 | 边界、非目标、契约与验收一致 |
| 功能与持久化 | 20 | CRUD、重启与失败路径实测 |
| 测试与语义评测 | 20 | 独立预期、隐藏样例、失败与成本记录 |

| 运维与恢复 | 10 | 降级观测、故障演练与恢复 |
| 复现与反思 | 10 | 版本、命令、局限和改进方向 |

秘密泄漏、未授权写入、编造结果或绕过检查会阻断交付，其他分数不能抵消；修复并重验后才验收。

## 8. 十五分钟答辩

1. 三分钟解释需求、用户和非目标，不展示工具品牌列表代替方案。
2. 四分钟运行一个主流程和一个边界错误，展示数据持久化与返回状态。
3. 三分钟展示对照评测，解释一个失败案例以及 mock 的边界。
4. 三分钟演练门禁拒绝或模型降级，说明恢复办法。
5. 两分钟回答最关键的剩余风险，以及扩大到多用户部署需要什么改变。

审查者可以提供一个未见输入或故障条件。项目应说明无法支持的条件，而不是编造成功输出。

## 9. 完成后如何继续

下一轮只选一个最影响用户的问题，例如误提取、长尾超时或授权缺口。先测基线，做一个小变更，再用独立评测与运行证据判断。工具变化时更新版本、接口和测试，不必重追整套品牌；可迁移的是规格、证据、权限和反馈闭环。

### 迁移检查：反馈要求超出下一轮预算

虚构任务上限1.2，已用0.7，下一模型调用上界0.3、独立核验0.3，次数尚余一次。反馈要求“再试一次，核验沿用旧版本”，但差异已改变，批准仍绑定旧版本。能否启动？下一合法步骤是什么？

<details>
<summary>作答后展开参考答案</summary>

`0.7+0.3+0.3=1.3>1.2`，启动前拒绝，不能省核验或用剩余次数抵费用上限。变更使旧批准失效，反馈不增加预算也不批准新差异。保留失败、费用和版本历史，停止交接；外部另批预算后，当前差异仍需独立检查、审查与可信批准。

</details>

## 10. 自测与答案

### 集中练习答案

#### 基础 1：两个链路四个决定

两条链为“小陈/T→MCP工具网关→笔记服务”和“小陈/T→LLM网关→A/B”。G1允许，审计记任务、主体、对象、动作与政策；G2在工具/笔记服务按对象归属拒绝；G3在模型链按数据目的地拒绝；G4在提交工具拒绝，因为T没有写权。模型成功和合法JSON都不授权提交，后端不能只靠门户隐藏工具。

#### 基础 2：行动前预留，不到超额才停

L下一轮连核验为`0.3+0.3+0.2=0.8≤1.0`，时间、次数和一次修复额度允许，可尝试；H为`0.3+0.8+0.2=1.3`，启动前拒绝。第二轮仍失败就停止，保存测试与用量，不再升级。V是权限高风险，格式化评测不涵盖它；应转独立安全回归与权限审查，行数少和自信不能放行。

#### 基础 3：当前差异的证据

C1顺序和不变量正确，检查与审查通过，但缺批准，只能等待当前批准。C2同时间ID排序错误，留在失败或受限修复，保留预期和实际，不能改答案凑通过。C3的d3a批准不适用于d3b，须对当前差异独立审查、重新批准后再核发布条件。

#### 基础 4：逐事件拒绝而非全自动成功

| 任务 | 最终纸面状态 | 下一合法步骤与证据 |
| --- | --- | --- |
| J1 | 待发布，未执行 | K1关联原任务；当前d1获批且`0.5+0.2=0.7`，保留去重、版本、批准与预算，执行时重验 |
| J2 | 失败，交人工 | 两次修复已用完，拒绝第三次；保存各轮失败与用量，新任务范围需新授权 |
| J3 | 旧批准拒绝 | 保留d3a/d3b；对d3b独立审查并向R重新申请批准 |
| J4 | 超预算阻断 | `0.9+0.2=1.1>1.0`；保留费用与批准，交接或申请新授权 |
| J5 | 撤权，停止新写入 | 旧批准不覆盖当前权限；保存撤销与已有产物，不能自行恢复权限 |
| J6 | 批准过期阻断 | 10:03已过有效期，评论不可信；向R重新批准当前d6 |

只有J1可待发布，均无实际发布记录。J5尚未执行，不能把撤权泛化成此前所有副作用已撤回。真实门禁还需故障注入验证。

#### 基础 5：公开学习题与真实交付分开

D只说明同题反馈后恢复；H是同场景改写，应与D归入开发，不能称隐藏题。Z首次在冻结方案下可独立验收，失败照记；据此修改后Z转开发，下次需新场景。

P的规格可支撑M1，纸面门禁仅是M4设计。M2缺基线、CRUD/重启和独立数据，M3缺真实模型、失败/成本与留出评测，M4缺实际拒绝、安全及独立审查证据，M5缺他人复现、观测和恢复。不能凭mock满分，也不能冒充官方贡献。

### 理解检查

**问：Software Factory 是否意味着无人工参与？** 不意味着。自治程度按风险和证据决定，发布、权限与事故等关键步骤可保留人类门禁。

**问：集中网关是否自动解决权限？** 不能。还需要身份传递、资源授权、凭据隔离和审计。

**问：什么说明你已掌握本教程？** 能在新任务上建立规格、实现最小正确变更、提供独立验证、解释失败并安全恢复，而不只是复述术语。

**问：生成十个 PR 是否就比一个有效贡献更好？** 不一定。有效性来自真实问题、正确修复、验证和协作，而不是数量；官方评分细则仍需单独核对。
