## 1. 从个人工具到组织系统

你已经能用控制中心为自己的笔记生成预览。团队接入后，同一Issue可能被两条通知重复触发，小陈的Agent可能请求小李的笔记，修改后的补丁还沿用旧审批。个人流程里一次成功，不能证明多人重复运行时仍可靠。本章先处理这些失败，再把预算、检查、批准和反馈连成可验证的软件交付流程。

**前置与成果**

- 能区分任务说明、候选结果、检查证据、批准与实际执行即可；会读简单事件表和加法。前面章节的规格、测试、权限与恢复有帮助，基础材料在本章完整给出。
- 基础成果是一张双网关职责图、一份任务预算/路由决定、一套阶段门禁与失败记录、一份评测隔离和交付缺口表。
- 基础题零网络、模型、安装、服务、远程Issue/PR/部署和真实写入；只分析假材料。真实综合项目独立交付，不能用纸面完成取代运行、模型评测、安全与恢复。

### 两种网关不能互相代替

跨人数据访问与模型账单失控需要两个不同检查位置。**网关**是在请求经过的集中入口检查策略的服务；MCP工具网关治理“调用哪个工具、以谁的身份、对什么对象做什么”，LLM模型网关治理“把哪些材料交给哪个模型、用多少预算”。门户可以帮助发现工具，发现或看得见不等于可执行。

```text
小陈 / 任务T -> 工具客户端 -> MCP工具网关 -> 笔记服务 -> 小陈对象
                         -> LLM模型网关 -> 获准模型供应商
两个链路共享任务ID便于关联，工具授权与模型预算各自强制检查
```

假用户小陈的任务只允许读取本人笔记并生成预览，工具端仍需验证主体、scope（允许能力范围）、对象与动作。即使网关只展示读工具，也不应让它背后用无限权限管理员账号访问全部资源。短期任务凭据减少长期共享风险，但仍需要最小权限、撤销与审计；模型请求成功不能证明工具安全，工具有权也不意味着私有材料可发往任意模型。

集中入口方便统一更新与记录，也会聚合权限并成为故障点。网关失败时不能自动绕过；写和部署权限分离，每次检查当前政策与批准版本。基础题只画职责和判断，不配置或部署任何产品。

## 2. 模型路由与成本

现在小陈的低风险排序任务在轻量模型上调用便宜，却修了三次才通过；授权修改一行但影响所有用户，不能只按改动行数或标价走便宜路线。**路由**是按风险、质量、延迟、数据政策与预算选择处理路径，不是模型自己决定“我很自信所以发布”。

先给整个任务设置费用/次数/时间上限，每次行动前预留下一步最坏费用，工具与人工核验也计成本。单次0.3单位修三轮，可能比一次0.8单位的路径贵；并行与长上下文会重复增加调用量。缓存改变单价，不把重复读取变为零成本；不能把token总数直接当账单。

一种最小策略是：已在独立样例上验证的低风险格式化走轻量路径；权限、迁移或未知依赖进入更严格审查；结构/测试失败时在剩余预算内最多有限修复或转人工；坏凭据、撤销、数据政策不合格不靠换模型绕过。每次切换重新检查输出、工具行为和拒绝规则，备用模型不是透明替换。

到达预算就停止并交接现有证据，不丢失败，也不为了“做完”无限升级。能否获得新预算由外部授权决定；原批准的费用和资源范围不能被反馈自动扩张。

## 3. Software Factory 的可操作定义

重复通知可能让同一补丁发布两次，检查超时可能被当“没发现问题”，改动后旧审批可能仍有效。解决这些问题需要把个人流程变成带身份、版本、证据和停止条件的阶段链。本教程把这种软件交付流水线称为Software Factory（软件工厂），不是要求模型无限自改或无人负责。

```text
需求或 Issue
  -> 研究与规格
  -> 计划与风险分级
  -> 隔离环境实现
  -> 测试、评测、安全检查
  -> 独立审查与批准
  -> 受控发布
  -> 观测与反馈
  -> 下一个受控改进任务
```

每阶段只在证据够用时退出；**门禁**是由执行层阻止不满足条件的产物进入下一阶段，不是表格写“已检查”。同一逻辑触发绑定幂等任务ID，已有任务就关联，不重新发布；规格、差异、测试、批准均绑定版本，任何变更使旧批准失效。撤销或预算不足时先阻止新副作用、保留已完成证据，不能把任务取消写成所有动作已撤回。

| 阶段 | 小项目产物 | 出口检查与负责人职责 |
| --- | --- | --- |
| 规格 | 排序规则、非目标、假输入与预期 | 需求负责人确认验收可独立判定，模糊处先澄清 |
| 计划 | 只改范围、风险、身份与预算 | 协调者核权限/依赖/停止条件，不扩大原任务 |
| 实现 | 隔离候选差异与版本 | 实现者保存原始失败，不改检查器来凑通过 |
| 检查 | 单元/集成、语义、安全证据与覆盖 | 检查失败或超时标不完整，不视为无缺陷 |
| 独立审查与批准 | 当前差异的审查、可信批准者记录 | 不是实现者自评；批准绑任务/对象/版本/有效期 |
| 受控发布 | 获准版本与执行审计 | 发布者重验当前授权、预算、版本；批准不等于已经发布 |
| 观测与反馈 | 运行/降级/恢复证据与下一任务 | 运维负责人核结果，反馈先形成新受控任务 |

真实门禁需执行层测试失败、重复、超时、撤销和版本变化确实被拒绝；基础事件演练只检查设计理解。发布、权限和事故风险按范围保留独立审批、隔离、审计和恢复。

## 4. 自动改进也需要评测隔离

如果每次失败都把答案交回模型，最后同题通过，可能只是记住答案，不能证明新任务也可靠。开发反馈集用于修改提示/实现，留出验收集只在方案冻结后由独立评价者判定；按原场景分组，避免同一笔记换措辞分别进两边。查看验收失败并据此修改后，该题成为开发资料，下一次需要新留出题。

生产反馈也不是直接修生产的授权。把症状、版本、证据与期望转成新的受控任务，再走同样门禁。评测既测产物，也测流程会不会拒绝：测试失败不进批准、旧批准不进发布、重复不重复副作用、撤销停止后续写入。答案和修复后的commit/wiki不进入独立缺陷发现输入。

### 动手：纸面工厂也必须能拒绝失败

下面不实际搭建工厂，而是先用完整假记录检查设计：证据失败、批准过期或权限撤销时，流程是否知道在哪里停。

### 基础必做：五项集中练习

全部为虚构纸面材料，零执行。各题独立，读者不用创建样例、调用模型或跳到笔记。记录“输入事实 / 规则与证据 / 决定 / 未知 / 停止与交接”，对应完整答案在第10节。

#### 基础 1：双网关，10分钟

题设：可信身份为小陈；任务T只允许读归属小陈的N1、生成预览，禁止提交；私有笔记仅可发模型A，B未获数据许可。MCP网关工具端有对象授权；LLM网关核供应商和模型预算。四个独立假请求：G1读N1、G2读小李N2、G3把N1发B、G4模型A生成合法JSON后提交预览。

画两条链并逐项判允许/拒绝与检查位置。通过标准：G1允许、G2工具端拒绝、G3模型链拒绝、G4写入拒绝；合法JSON和模型成功不授提交权限。

#### 基础 2：总任务预算，15分钟

虚构低风险格式化任务U只处理公开假文本。已通过独立质量题的轻量路线L每次费用上界0.3单位，较强路线H每次0.8，人工核验预留0.2；整个任务模型+核验限1.0单位、最多2次模型调用、最多1次修复，限时10分钟。首轮L花0.3且测试失败；工具费用题设为0，时间尚余6分钟，无政策改变。

判断下一轮L或H是否可启动，算连核验预留的总额。另一个独立高风险权限任务V只有L的格式化质量结果，缺授权回归证据；Agent声称自信。判断能否按“少于三行所以L”放行。通过标准：第二轮L可预算内尝试，总上界0.8；H会到1.3超额，拒绝；最多一次修复仍失败即停；V升级审查不自批。

#### 基础 3：稳定排序候选，15分钟

本题是独立排序练习，不是第02–03章“最新先显示”规格的变更；改用升序只为检查门禁是否依据当前题设，而非沿用记忆中的答案。局部规格S1：按时间升序，同时间按ID升序；只排序、不增删、不改标题。输入为`[(id=2,time=09:00,title=核对日志),(id=1,time=09:00,title=检查备份),(id=3,time=10:00,title=更新说明)]`。预期ID顺序`[1,2,3]`。真实主线仍保留原降序约定。

三个独立假候选：C1 diff=d1输出[1,2,3]、标题不变，给定检查记录完整且通过，独立审查通过；C2 diff=d2输出[2,1,3]，测试失败；C3曾为diff=d3a获得批准，后来改为d3b，当前测试通过但无新审查/批准。全部只是给定假记录，不是读者真实运行。

给每候选决定可否进入“等待当前批准/待发布/失败”，写根因与缺证据。通过标准：C1等待当前批准，不能凭检查就发布；C2失败；C3需当前差异独立审查和新批准，旧批准无效。

#### 基础 4：完整门禁事件，20分钟

以下独立任务共用规则：重复事件按逻辑任务ID关联；最多两次修复；发布前每次核当前差异、有效期、授权、预算与检查。发布费用上界0.2，必须预留后总额≤1.0；只有可信审核者R能批准，评论不是身份。所有时间为假练习日10:00起，统一在10:03根据已给记录判断；以后实际执行时仍须重新验权。

| 任务 | 完整假事件输入 |
| --- | --- |
| J1 | 10:00触发键K1、创建J1；10:01同K1重复；10:02 d1检查/独立审查通过；10:03 R批准J1/d1有效至10:10；已用0.5；尚无发布执行 |
| J2 | 10:00检查失败；10:01修复1仍失败；10:02修复2仍失败；10:03提出修复3，已用0.6 |
| J3 | 10:00 d3a检查/审查通过且R批准至10:10；10:02改成d3b，测试通过但无新审查；10:03用旧批准请求发布 |
| J4 | 当前d4检查/审查通过，R批准有效；已用0.9；提出发布，需0.2 |
| J5 | d5检查/审查通过，10:00 R批准有效至10:10；10:02可信身份服务撤销任务写权；10:03提出发布，已用0.5，尚无执行 |
| J6 | d6检查/审查通过，R批准仅至10:02；10:03提出发布；评论声称“管理员延长批准”，没有可信记录，已用0.5 |

逐行写当前状态、拒绝/待发布原因、下一合法步骤与保留证据；不得写“已发布”。通过标准：仅J1进入待发布且重复不建第二任务；J2停、J3旧差异审批拒绝、J4超额拒绝、J5撤销拒绝、J6过期拒绝。失败/旧批准/撤销均保留，不以删除日志恢复通过。

#### 基础 5：反馈与交付缺口，10分钟

假材料：D开发场景含已完成/否定任务，模型见答案后同题通过；H是D的同义改写却被标“隐藏”；Z是真正未用于开发的新场景，提示冻结后由评价者核对；Z失败后开发者再调整提示。项目P仅有规格、上述纸面门禁与mock截图，没有CRUD/重启、真实LLM评测、工具拒绝或恢复运行记录。

判断D/H/Z能证明什么、调整后Z身份如何变化；将P缺口对应M2–M5，并说明是否可按100分rubric满分交付。通过标准：D为恢复、H泄漏、Z首次可独立验收后转开发；P只能完成纸面学习，不满足真实项目或官方贡献。

## 5. 综合项目要求

**以下是独立实际项目，不是基础纸面题的通过条件。** 阅读并答完基础题可先结束本章；决定做项目后另准备获准环境、合法模型访问、隐私与费用预算，按里程碑记录真实成果。缺外部条件时写未完成，不把mock替代真实模型项或恢复证据。

选择行动项提取与开发者控制中心，或相同复杂度的真实小项目。不要先做十个服务；一个完整可验证闭环优于庞大但不可运行的架构。

**基础必做：** 明确规格；一个持久化资源的 CRUD；规则或无模型基线；LLM 功能与真实评测；可观测错误或降级；单元与集成测试；安全边界；独立审查；可复现启动和回滚说明。

这里“基础必做”指实际综合项目的最低交付，不指本章离线基础。建议先为M1/M2规划1–2次学习时段，再为M3–M5分别限时/限费；按项目复杂度修订，不承诺固定时间一定交付。实际费用、模型、授权或数据条件不足时停止，保留阶段状态。

**进阶可选：** OAuth MCP 组合工具与受控写入；经过触发验证的 Skill；两个独立后台任务；网关或多模型路由。选择进阶项时遵守对应原作业要求，不做未验证的模拟 OAuth。

## 6. 五个交付里程碑

| 阶段 | 产物 | 通过条件 |
| --- | --- | --- |
| M1 定义 | 规格、非目标、风险与验收 | 他人能写出测试，不依赖口头解释 |
| M2 基线 | 最小应用与规则方案 | 新环境可运行，测试数据独立 |
| M3 AI 能力 | 模型功能、评测与错误处理 | 真实运行证据，所有失败计入 |
| M4 受控流程 | 审查、安全、自动化 | 门禁失败确实阻止后续动作 |
| M5 交付 | 运行文档、观测、回滚与复盘 | 另一位读者复现主流程与故障恢复 |

不要跳过 M2 直接优化模型。缺少可靠基线时，模型质量、程序 bug 和环境错误容易混为一谈。

| 09交付/观测/恢复记录、10预算/批准/状态表 | M4 → M5 | 行动前预留核验成本，关联请求与实际引擎，落实受控恢复 | 超额/旧批准拒绝、降级和失败可见；他人复现主流程及获准故障恢复，包含数据完整性与兼容证据 |

用已有[实验与规格模板](../reference/templates.md)记录“章节产物 / 当前项目版本 / 已实现范围 / 命令与证据定位 / 失败 / 未验证 / 下一步”。没有执行证据就保留待实现或待验收；规则回退不算模型成功，设计批准不算实际发布。网关、路由、后台任务与OAuth为可选扩展，不因画过架构图自动完成；取消、幂等和原子接管各需相应故障验证。

### 开源贡献闭环

<details>
<summary>选学：真实协作贡献，公开发布须独立决定</summary>

根 README 当前开源贡献权重为 30%。自学应包含真实协作训练，而不是凑 PR 数量；这里不推断官方具体评分细则，也不修改下面的自学项目总分。

选择自己理解且允许贡献的项目，阅读贡献指南、许可证、AI 使用政策、测试和维护者期望。合适的小任务是修复可复现的边界 bug、补充能捕获错误的测试，或纠正导致启动失败的文档。大面积自动重构与无依据的风格修改通常增加审查负担。

例如项目声称稳定排序，同时间戳的任务顺序却随查询变化：先查已有 Issue；在隔离环境记录版本、输入、预期与实际行为；写失败测试；最小修正排序 tie-breaker；运行回归并解释兼容性。如果需求不保证顺序，先与维护者确认，不擅自制造“缺陷”。

按以下阶段记录，不把本地准备写成远程贡献已经完成：

1. 选题与对齐：查重、阅读政策，确认问题真实、范围合适；必要时先询问维护者。
2. 复现与规格：提供脱敏最小案例、基线提交、命令与工作目录，区分观察和推断。
3. 最小修复：只改相关权威源，增加回归，不顺手升级依赖或修无关格式；按政策披露 AI 辅助。
4. 验证与说明：提供改前失败、改后通过、兼容性和残余风险；PR 说明引用需求，方便独立复核。
5. 发布与反馈：读者明确决定后才创建远程 Issue、PR 或推送；记录维护者意见，回应并复测。未获回应、关闭或未合并照实记录，不保证被接纳。

动手：完成一个小问题的本地贡献包，使用[贡献模板](../reference/templates.md)记录。如果允许并决定公开提交，再按目标项目流程发布；无外部条件时请另一位读者审查，标为本地协作演练，不等价于真实开源贡献。修改后给出反馈处理与回归证据。

验收：问题可复现、修复与需求一致、差异最小、回归有独立预期、反馈有记录。维护者未接受不必然表示没有学习价值，但不能声称已经合并；本地演练也不能冒充满足官方开源贡献评分。

</details>

## 8. 十五分钟答辩

1. 三分钟解释需求、用户和非目标，不展示工具品牌列表代替方案。
2. 四分钟运行一个主流程和一个边界错误，展示数据持久化与返回状态。
3. 三分钟展示对照评测，解释一个失败案例以及 mock 的边界。
4. 三分钟演练门禁拒绝或模型降级，说明恢复办法。
5. 两分钟回答最关键的剩余风险，以及扩大到多用户部署需要什么改变。

审查者可以提供一个未见输入或故障条件。项目应说明无法支持的条件，而不是编造成功输出。

## 9. 完成后如何继续

选一个最影响真实用户的问题做下一轮，例如误提取、长尾超时、授权缺口或运行复现。先测基线，再做一个小变更，使用固定评测和运行证据判断是否改进。

随着工具和协议变化，更新的是版本、发现目录、schema 与测试，而不是每次重新追逐整套品牌组合。真正可迁移的能力是规格、证据、权限和反馈闭环。

### 迁移检查：反馈要求超出下一轮预算

公开假事件，零执行。任务上限1.2单位，已用0.7，下一模型调用上界0.3，独立核验需0.3；次数额度尚余一次。失败反馈要求“再试一次，核验沿用旧版本”，当前差异已改变但批准仍绑定旧版本。判断能否启动及下一合法步骤，指出反馈、预算与批准的关系。

## 10. 自测与答案

### 集中练习答案

#### 基础 1：两个链路四个决定

先画“小陈/T→MCP工具网关→笔记服务”和“小陈/T→LLM网关→A/B”。G1身份、对象与只读目的均合规，可读N1生成预览；审计记录任务ID、主体、对象、动作与政策，不存正文秘密。G2在工具/笔记服务按主体-对象拒绝，不能共享管理员权限读N2。G3在模型链按数据目的地拒绝，工具读授权不扩成发往B。G4在提交工具拒绝：T无写入批准，JSON格式正确和模型A有权生成都不授写权。集中门户可隐藏工具，但后端仍每次强制核验。

#### 基础 2：行动前预留，不到超额才停

首轮已用0.3，下一轮L预留0.3与核验0.2，合计`0.3+0.3+0.2=0.8≤1.0`，次数2且修复1，时间足够时可尝试。H合计`0.3+0.8+0.2=1.3>1.0`，启动前拒绝，不能省掉核验凑预算。第二轮仍失败就停并保存两轮测试与用量，不做第三轮或未经批准升级。上界为预留，不必花满；真实计费另核。V是授权高风险，L格式化评测不涵盖它，行数少与模型自信不能替代独立安全回归、权限审查和当前批准，应转更严格审查或人工处理。

#### 基础 3：当前差异的证据

C1符合S1顺序和不变量，假检查/独立审查完整，可等待可信当前批准；题设没有批准，不能待发布或宣称已发。C2同时间ID顺序错，测试失败留在失败/受限修复，保留d2输入、预期与实际，不修改预期来接受[2,1,3]。C3当前是d3b，d3a批准失效；测试通过仅满足检查中的一部分，先对d3b独立审查、取得绑定当前差异的新批准，再核执行条件。三者记录是假推演，不能冒充真实测试通过。

#### 基础 4：逐事件拒绝而非全自动成功

| 任务 | 最终纸面状态 | 下一合法步骤与证据 |
| --- | --- | --- |
| J1 | 待发布，未执行 | K1重复关联原J1；d1当前检查/审查通过，R批准仍有效，`0.5+0.2=0.7`可预留。保留触发/去重/版本/批准/预算，执行时重验 |
| J2 | 失败、交人工 | 修复2后仍失败，拒绝修复3；记录每轮原失败与已用0.6。未用完费用不取消次数上限；新范围/预算需新授权 |
| J3 | 旧批准拒绝，等待当前审查与批准 | 当前d3b不等于d3a；保留两差异与测试，不能用旧批准。完成d3b独立审查后由R重新批准 |
| J4 | 超预算阻断 | `0.9+0.2=1.1>1.0`；发布前拒绝，保留检查/批准与费用。可交接或请求外部新增授权，不直接花超 |
| J5 | 撤销后停止新写入 | 10:02撤权早于发布请求，旧批准不覆盖当前写权；记录撤销/停止/未执行与已有产物，不能自行恢复权限 |
| J6 | 批准过期阻断 | 10:03已过10:02；评论身份无可信延长记录。重新向R走可信批准，核当前d6与有效期，不接受评论绕门禁 |

仅J1具备进入待发布条件，题设无实际发布，不写已发布。撤销停止未来动作不证明此前全部副作用已撤回；本题J5明确尚无执行，按该事实记录。真实系统还要用重复/失败/撤销/过期故障注入验证门禁，而不是只靠事件答案。

#### 基础 5：公开学习题与真实交付分开

D看过标签再通过，只支持同题反馈后恢复；H是同一场景改写，按场景分组应跟D一起进开发，不能称隐藏泛化。Z首次未用于开发且方案冻结时可作独立验收，失败也需记录；一旦据Z改提示，Z转开发，下次需新留出场景，不能反复刷Z报提升。

P的规格可作M1材料、纸面门禁仅是M4设计，不是执行强制证据。M2缺可运行基线、CRUD/重启与独立数据；M3缺真实模型、失败/成本与留出评测；M4缺实际门禁拒绝、安全与独立审查运行证据；M5缺他人启动、降级观测与恢复。不能凭mock截图或本题答案填100分，更不能冒充官方开源贡献完成；保持各项未运行/待取得，不制造数字成绩。

### 理解检查

**问：Software Factory 是否意味着无人工参与？** 不意味着。自治程度按风险和证据决定，发布、权限与事故等关键步骤可保留人类门禁。

**问：集中网关是否自动解决权限？** 不能。还需要身份传递、资源授权、凭据隔离和审计。

**问：什么说明你已掌握本教程？** 能在新任务上建立规格、实现最小正确变更、提供独立验证、解释失败并安全恢复，而不只是复述术语。

**问：生成十个 PR 是否就比一个有效贡献更好？** 不一定。有效性来自真实问题、正确修复、验证和协作，而不是数量；官方评分细则仍需单独核对。
