# 03 上下文工程与规格驱动开发

[上一章](02-agent-loop.md) | [目录](../README.md) | [下一章：MCP 与 OAuth](04-mcp-oauth.md)

你已经知道 Agent 怎样读取、修改和检查任务列表，但它应该按哪份要求修改？用户说“最新任务先看到；模型失败要告知”，旧说明说按 ID 排序，当前实现又静默规则回退。如果把三者一起交给 Agent 而不说明关系，它可能实现旧需求，或把现状当成已经满足目标。

本章先为主线任务列表选择可信信息，再把“失败要告知”写成一份完整提取规格，最后模拟新会话交接。切换到提取降级，是因为它能暴露函数、应用接口、界面和写入的不同契约；排序仍用于检验上下文冲突。所有基础输入、预期与答案都在章内，无需模型、网络、课件或原脚本。

**学习前置与产物**

- 已理解第 01 章行动项提取规则与唯一 `action_items` JSON、第 02 章执行证据与状态；能读表格与简单 JSON。
- 做出一份最小上下文包、一份明确目标/现状的规格、四个验收案例和一份撤销旧决定的交接。
- 规格是“目标行为约定”，不是代码已实现的证明；本章不直接修改原作业或新增真实 API。

| 第一段：知道给什么材料 | 第 1–5 节；基础练习 1–2 | 阅读 25–35 分钟，练习 20 分钟 |

## 1. 为什么“帮我优化项目”经常失败

回到开场请求，“优化”没有说明最新按创建还是修改时间、失败显示什么、旧客户端能否改变。它同时缺少目标、范围和判定标准。Agent 可能改目录、换框架、升级依赖，最后无法证明你真正关心的问题被解决。模型能力再强，也无法可靠猜出未表达的业务偏好。

因此不仅要写清请求，还要选择完成它所需的材料，这就是上下文工程：选择、组织、更新和传递任务信息。提示工程关注如何表达一次请求；上下文工程还包括代码、版本化文档、需求、测试结果、权限边界与历史决定。它不是把整个仓库复制到聊天框。

## 2. 上下文的四种常见失败

| 失败 | 行动项提取项目中的例子 | 应对 |
| --- | --- | --- |
| 缺失 | 不知道默认模型和回退路径 | 先读实现与配置 |
| 污染 | 将旧端点文档当成当前契约 | 标记来源、版本、日期 |
| 冲突 | PRD 要保留原文，示例却要求自动补负责人 | 澄清优先级后再实现 |
| 过载 | 无关日志和依赖文件淹没关键测试 | 搜索定位，按需读取 |

对每条重要事实附上来源，并把事实、假设和待澄清项分开。当前代码是当前行为的证据，但不一定是正确需求；测试也可能过时。发生冲突时需要判断哪一项是已发布契约、哪一项是待改变目标。

恢复不能只在末尾追加新结论。先定位错误来源，重读权威材料，再明确撤销旧假设及其衍生计划。例如交接称“授权测试通过”，实际只有 mock，就应改为“仅 mock 已验证，真实授权未运行”，恢复对应验收步骤，并同步规格和下一份交接。

本章假来源：S1 是已确认目标“创建时间降序、同时间数字 ID 降序”；S0 是撤销的旧提案“只按 ID”；C1 是当前行为“只按 ID”；T1 是未运行的测试计划。S1 决定要改成什么，C1 证明现在是什么，T1 不能证明已通过。交接要明确 S0 被 S1 替代，撤销“无需检查创建时间”的衍生计划，保留 C1 供研究差异。

## 3. 制作最小上下文包

实现任务列表稳定分页，需要当前入口、输出字段、排序和验收，而非整个仓库。上下文包就是一份能支持本任务决策的小材料集合；“最小”指剔除无关信息，不是省掉失败与权限。

下面是完整纸面包，路径和行为均为假设，不对应真实文件运行记录：

```text
任务：任务列表第一页为最新记录，每页最多50条；本轮只设计，不执行。
目标依据 S1：created_at降序，相同时间数字id降序；page从1开始。
当前证据 C1：demo/routes/tasks.py:list_tasks，目前只按id降序，无分页。
响应证据 C2：字段 id、text、created_at，旧客户端依赖，不得改名。
测试证据 T1：demo/tests/test_tasks.py 仅计划检查ID顺序，未执行。
范围：demo/routes/tasks.py及demo/tests/test_tasks.py；其他文件需先说明必要性。
非目标：不换数据库、不做游标分页、不访问真实用户数据、不同步第三方。
已撤销 S0：只按id排序；不得再据它删除创建时间断言。
需要保留：空页、非法page、同时间排序、字段兼容性的预期；实际检查未运行。
可重读证据：上述定位；若真实继续任务必须先核对当前文件和版本。
禁止材料：假.env和假用户导出均不可发送；无关部署日志不加入。
```

记录关键定位信息，例如“读取了路由文件的这个函数，它目前无排序”；不要只说“项目用 FastAPI”。压缩时保留目标、决策理由、修改文件、失败证据和未验证项。可重新读取的长日志保留路径与必要片段，不反复内联。

清空会话可以减少干扰，却会丢失隐含决定。新会话应先读交接记录，再核对实际工作区。上下文压缩属于信息选择，不是可靠备份。

<details>
<summary>选学：产品数据路径与隐私核对，不是基础练习前置</summary>

[AI IDE 解读第 8 页](../reading-notes/fall2025/week03/lecture-ai-ide-setup.md#4-第-8-页补全与检索聊天的数据流不同)区分局部补全与代码分块检索聊天。前者取当前位置附近代码，后者通过语义索引检索相关块；相关不等于权威，索引更新也不验证契约。这里借历史文字解释概念，不保证现行产品架构。

离线练习：20 分钟、零网络与零模型预算，在独立目录用代码入口、测试、假秘密、假用户导出和规则五类虚构文件画两份信息路径表。验收标明任务所需、禁止外传、产品契约待核验项，并解释“排除索引不等于禁止附件发送”和“传输加密不等于服务端不处理”。保留来源与未验证项；纸面分析不证明真实客户端隔离有效。

</details>

## 4. RePPIT 的具体用法

此流程与 2025 AI IDE 讲义的规格要点互补：前者组织工作阶段，后者组织目标、定义、文件范围、测试、边界和非目标；阶段名称本身不授予执行权限。

README 提到 Research、Propose、Plan、Implement、Test。可以将它理解为逐步降低不确定性，而非每个小改动都必须写五份文档。

1. **Research：研究。** 找入口、调用链、测试和当前限制；运行最小基线；输出有来源的事实。
2. **Propose：提出方案。** 比较最小调整与替代方案，指出公开行为、数据和安全影响；澄清不可自行决定的事项。
3. **Plan：计划。** 把方案拆成可验收的小步，明确文件范围和每步测试。
4. **Implement：实现。** 按计划产生小差异，不顺手重构无关部分；发现假设错误时更新计划。
5. **Test：验证。** 运行对应检查，复核需求和差异，记录未覆盖风险。失败则回到相应阶段。

小型文案改动可以在一段记录里完成这个过程；身份认证或数据库迁移需要更明确的审查与发布方案。流程的价值在于证据与决定可追踪，而不是文档数量。

例如本章分页包可以在同一页写五行：研究 C1/C2 → 提出最小偏移分页 → 人工确认 S1 和兼容字段 → 计划实现与四个测试 → 当前仅设计，实施及测试未运行。不是把五行都写了就完成五阶段；只有真正到 Test 且证据满足目标，才可声明验证通过。

## 5. 将愿望转换为规格

愿望：“任务列表更好用。”可执行规格：“任务按创建时间降序展示，每页最多 50 条，相同时间按唯一 ID 降序；非法分页参数返回约定的 4xx；不得改变旧字段名称。”

还要说明边界：第一页是什么编号，零条数据返回什么，删除数据后是否允许页间漂移，客户端是否依赖原顺序。偏移分页实现简单，但并发增删可能导致重复或遗漏；游标分页更适合连续浏览，却需要额外契约。不要因为“更先进”就无条件换成游标。

功能要求描述做什么；非功能要求描述延迟、权限、容量和可观测性；非目标明确本轮不做什么。验收标准应能被观察，而不是“智能”“优雅”“体验好”。

## 6. 示例规格：可靠的 LLM 提取

现在把“模型失败要告知”落到提取器。它改变的不只是提示，还涉及响应怎样告诉界面本次是否降级。下面 S2 是完整限定教学规格，不是当前 API 已实现的声明；固定小输入域让基础验收有确定答案。

| 项目 | 本轮规定 |
| --- | --- |
| 目标与范围 | 在教程拟新增的应用预览层暴露提取结果与状态；不直接改变现有函数或HTTP响应 |
| 输入 | text必须为字符串；基础域为不超过500字符、无指代/条件/时间冲突的短笔记；非字符串记INVALID_INPUT、超长记INPUT_TOO_LONG；纯空白为合法空输入 |
| 任务定义 | 沿第01章：明确待执行、拆独立动作、保留明确时间/负责人、排除完成/否定/未决定、同任务去重；不补姓名与日期 |
| 正常模型候选 | 唯一字段action_items的字符串数组；先检查请求、完整性、解析、结构与语义，再接受，错误不清洗成空列表 |
| 应用结果 | action_items、engine、status、error_code；engine为llm/rules/none，status为ok/degraded/error；成功error_code为null |
| 空白输入 | 不调用模型，action_items=[]、engine=none、status=ok、error_code=null |
| 回退政策 | 仅模型请求超时允许一次规则回退，且输入已人工确认“每项有效任务独占待办：行，其他行无任务”；假规则取该前缀后非空文字并按第01章规则去重；不满足此子域先复核，不允许漏提后假装成功 |
| 回退成功 | engine=rules、status=degraded、error_code=MODEL_TIMEOUT；即使列表空也保留降级，不称模型成功 |
| 其他失败 | 结构/语义失败不自动回退；已确定错误时engine=none、status=error，无合格候选，保留FORMAT_ERROR、SCHEMA_ERROR、SEMANTIC_ERROR、RULE_FAILURE等具体原因；语义无法判断另走needs_review，不伪装已确定错误 |
| 待复核输入 | 指代/条件/时间冲突在入口记needs_review，暂停并人工澄清，不发送模型、不用空数组冒充无任务 |
| 副作用与安全 | 预览不写笔记或任务，不执行笔记命令；不记录秘密；创建任务另走批准流程 |
| 兼容与非目标 | 旧函数列表与现有路由保持原样，本轮仅设计预览包装；不迁移数据库、不新增第三方同步；未批准新增接口不实现 |
| 验收与回滚 | 第7节场景逐项核对，执行均未运行；真实新增层失败时停止启用，不假设旧写端点可作无写入替代 |

模型 JSON 仍是第 01 章的 `{"action_items": [...]}`。上表四字段属于模型外的拟议应用包装，是程序生成的状态，不要求模型生成 `engine/status`。`needs_review` 仍是输入/验收流程状态，不是模型 JSON 字段，也不强行塞入该应用成功对象。结构 schema 可检查字段、类型等结构约束，不能保证任务事实，因此语义无法判断时需人工复核。

对“待办：明天检查日志”，假模型候选与拟议应用结果分别是：

```json
{"action_items": ["明天检查日志"]}
```

```json
{"action_items": ["明天检查日志"], "engine": "llm", "status": "ok", "error_code": null}
```

若模型明确超时、假规则按本章规则取得同一候选，则包装改为：

```json
{"action_items": ["明天检查日志"], "engine": "rules", "status": "degraded", "error_code": "MODEL_TIMEOUT"}
```

相同列表可以有不同生成路径；包装保留失败让用户知道发生了什么，不为规则回退签发模型质量证明。

非超时请求失败、明确拒绝或输出不完整分别保留REQUEST_ERROR、REFUSED_OUTPUT、INCOMPLETE_OUTPUT并停止，不自动回退或绕拒绝。以上确定错误的包装均为action_items=[]、engine=none、status=error及相应error_code；基础题只用A–F，其他标签不要求死记。无前缀的“明天检查日志”不能在模型超时后由此假规则静默返回空列表，应先复核回退范围，避免混淆规则覆盖与模型语义能力。

当前 [提取实现](../../_assignments/2025%20fall/week2/app/services/extract.py) 已有 LLM 与规则回退。其函数返回列表，不带引擎与错误状态。改变返回类型可能影响路由和测试，所以应先调查消费者，再决定新增包装层还是调整契约，不能只改一个函数就宣布完成。

[2025 第 2 周作业导读](../reading-notes/fall2025/week02/assignment-guide.md)逐文件区分原 100 分要求、当前行为与目标规格：`save_note=false`只是不保存笔记，两个提取端点仍保存行动项，不能当只读预览；schema 发送不等于本地严格校验，非字符串项可能被清理成空结果。配套 50 分钟零调用练习将写入、静默降级和 mock 范围映射到验收矩阵；未运行模型、数据库或界面。

上述区别已经足以完成基础学习：当前 `_parse_action_items` 接受部分别名并跳过非字符串，模型异常回退后仍返回列表；S2 要求严格检查与显式包装，这是拟议变化。真正实施需调查调用方，不能只把函数返回列表改为对象而忽略路由、前端和测试。

## 7. 验收案例应先于实现

以下四个独立场景直接按 S2 判定，假模型和规则行为已给出，不要自行补外部调用结果：

| 场景 | 完整输入与假条件 | 预期应用结果 |
| --- | --- | --- |
| A 明确任务 | text=`待办：明天检查日志`；模型完整返回 `{"action_items":["明天检查日志"]}`，人工语义核对一致 | 一项，llm/ok/null；零写入 |
| B 仅叙述 | text=`发布已完成。`；模型完整返回 `{"action_items":[]}`，人工核对无任务 | 空列表，llm/ok/null；不是失败 |
| C 超时回退 | text=`待办：明天检查日志`；模型请求超时；假规则成功提取一项 | 一项，rules/degraded/MODEL_TIMEOUT；不能显示模型成功 |
| D 回退也失败 | 同C，但假规则抛异常 | 无合格候选，none/error/RULE_FAILURE；空数组不表示合法无任务 |

错误包装中的空数组只表示没有可用候选，必须结合 `status=error` 处理，不能按“没有行动项”展示；本章已知D是执行错误，语义未知的输入另进复核。另一个结构边界 `{"action_items":[17]}` 在 S2 应为 `SCHEMA_ERROR`，不能清成 B 的合法空结果。

用验收案例约束实现，而不是让 Agent 根据自己生成的实现反向定义“正确”。当样例暴露需求歧义时先澄清，再写断言。

## 8. 动手：用 AI 完成一个受控变更

### 基础必做：四项完整设计

本节基础题只用本章 S0/S1/C1/C2/T1、S2 与A–D；零网络、零模型、零原脚本执行、零业务写入。所有输入均已展示，练习不依赖另一位读者、外部模板或未取得正文。

1. 选择材料，10分钟：假材料集合为S0旧排序、S1已确认目标、C1当前实现、C2旧字段、T1未运行计划、假.env秘密、200行无关部署日志。写最小包，逐项说明留/舍和用途；不能删除C1来掩盖现状，也不能上传假秘密。
2. 撤销冲突，10分钟：旧交接原文为“只按ID；排序已经通过；删创建时间断言；可真实同步任务”。已知S1替代S0，T1未运行，本轮只设计且禁止第三方。逐句撤销，写修正版与仍未知事项。
3. 检验规格，20分钟：对第7节A–D分别写完整四字段包装、是否可接受/写入、依据。补边界E：text=`待办：明天检查日志`，模型完整返回 `{"action_items":[17]}`；补边界F：text=`周五检查日志。改到下周一。`。写E的错误包装及F提取前动作，别把needs_review加入模型JSON。
4. 压缩与交接，10分钟：输入报告为“仅纸面S2设计完成；原函数仍返回列表；未改路由/前端；所有测试未运行；待批准预览包装”。写最多8行交接，明确目标、决定、当前状态、文件职责、未执行、下一步及禁止项。再写为什么不能真实归档为已交付规格。

记录与最低通过条件：

| 记录项 | 通过标准 |
| --- | --- |
| 材料表与包 | 目标/当前行为/测试状态分开，保留排序及旧字段，敏感与无关材料不入包 |
| 冲突差异表 | 明确S0撤销、恢复创建时间断言计划，不写测试通过或真实同步获准 |
| A–F验收表 | 正常空、明确标注的降级、错误与复核分开；四字段只在应用包装；不产生实际写入 |
| 交接 | 不把设计任务打勾当实现，能恢复目标和待批准接口，需先核对当前代码 |

```text
材料ID / 来源性质 / 留或舍 / 理由：
旧决定 -> 权威依据 -> 撤销内容与衍生计划：
场景 / 输入及条件 / 预期包装或复核 / 是否接受 / 副作用：
目标 / 当前事实 / 已决定 / 待批准 / 测试证据 / 下一步 / 非目标：
```

<details>
<summary>独立选学：使用真实Agent实施受控变更</summary>

以下保留原真实路线，需要独立副本、模型访问和执行授权，不属于基础题；即便原作业已有实现也不应清空。

1. 在练习副本中选择列表分页或提取降级状态，阅读相关代码与 [原设计文档模板](../../Resource/Fall2025/week03-1006-design-document-template.md)。
2. 写一页规格：当前行为、目标、非目标、输入输出、失败路径、受影响文件、验收和回滚。
3. 给 Agent 第一阶段请求：“只研究，不改文件；列出来源、方案与待澄清项。”检查它有没有将猜测当事实。
4. 确认方案后请求小步实现，明确允许范围；每步都要求实际测试证据。
5. 用一条未给 Agent 的边界样例验收，检查它是否为了通过测试删除断言或改变要求。
6. 将最终差异与规格逐项对照，记录计划外变更及必要理由。

验收：规格可以在没有原作者帮助时转成测试；修改范围合理；有一个失败路径和一个未参与实现调参的验证样例。

</details>

## 9. 压缩不是越早越好

[上下文税笔记](../reading-notes/fall2026/week02/01-context-tax.md)讨论长会话反复读入历史的成本。粗略估算输入工作量时，把每次调用的输入 token 相加，而不是只看最后一轮；子 Agent 继承大上下文也要计入。缓存会改变计费，不能把累计 token 直接当账单金额。

压缩会节省后续输入，却可能丢失目标、决定理由和失败证据，导致重新搜索甚至做错。比如分页方案已选择稳定排序，交接只写“实现分页”，新会话可能重新改变 API。保留契约、决定理由、已改文件、测试定位和未验证项，比照搬全部日志更重要。文章是作者个人记录与模型评审的观察，不支持把其压缩阈值变成所有项目的规定。

不用另做一份重复练习：基础题4直接按目标、契约、决定理由、证据定位、状态、下一步六项核对交接即可。假输入账本中，旧包100单位读4次是400单位，压缩后40、50、60、70单位是220单位；这只比较输入量，尚未计压缩/重新检索成本，也不是实际token或账单测量。不规定通用压缩阈值。

## 10. 将规格作为跨会话的权威交接

跨会话时，当前规格回答“应有什么行为”，提案回答“为什么改”，设计记录必要架构决定，任务表记录实施进度，执行日志回答“实际验证了什么”。新会话先读这些产物并核对代码；归档前将真正交付的增量同步回维护规格，不能把未实现S2写成当前系统事实，或只保存聊天。

<details>
<summary>选学：OpenSpec、Superpowers与来源特定流程</summary>

[OpenSpec 笔记](../reading-notes/fall2026/week02/02-openspec.md)的入门流程把探索、提案、人工复核、实现和归档连接起来。关键是可复核产物，不是安装框架后自动保证正确。

例如分页提案最初写“每页 50 条”，人工发现旧客户端依赖字段名，应先补规格，再实现。任务打勾不能替代退出码、断言和需求核对。已读 quickstart 是工具的一种流程，不是通用目录或自动安全保证；[Superpowers 材料](../reading-notes/fall2026/week02/03-superpowers.md)需按实际读取文件比较，不因名称相似假定机制一致。

离线练习：用 45 分钟在练习副本写一页分页提案、行为规格和任务表；先引入同时间戳排序歧义，人工修正规格后交给下一会话或读者。预算为零云调用，最多一个受控变更，不安装框架。验收将每条规格映射到预先定义的检查，并保留归档前后差异；没有运行实现就标为规格演练，不能标记功能通过。过期规格与过度细化同样会误导，需要维护责任。

课堂关联：[RePPIT 转写解读](../reading-notes/fall2026/week02/lecture-reppit.md)。阶段名称不是审批权限，外部文档不能授权安装、提交或写入。

延伸定位：[架构论文的上下文分层](../reading-notes/fall2026/week01/03-claude-code-design.md)、[Matt Pocock 的规格与测试 seam](../reading-notes/fall2026/week03/02-matt-pocock-skills.md)、[第 3 周 Skill 导读](../reading-notes/fall2026/week03/assignment-guide.md)。精选材料用来对照来源差异，不追加未确认的业务字段到本教程主线。

[Coding Agents 101 解读](../reading-notes/fall2025/week03/03-coding-agents-101.md)强调检查当前差异和当前产物；先修首个失败不等于全回归通过。原文时间节省是经验目标，未复现。

</details>

### 迁移检查：任务打勾不改变接口

公开假交接，零执行。S2预览包装获得设计认可，任务表勾选“降级状态完成”；当前原函数仍返回列表，路由和前端未改，测试只有mock解析。交接写“先调用旧端点，设save_note=false作预览”。请写最多四句修正交接，包含下一步与停止边界，不执行请求。

<details>
<summary>作答后展开参考答案</summary>

可写：“S2仅设计认可，包装、路由与前端未实现，mock解析不证明交付。旧端点即使save_note=false仍可能保存行动项，不可作为无写入预览。下一步只读核对消费者与副作用，再确认新增接口实施范围和独立零写入验收。未取得实施授权和执行证据前停止，不调用旧端点，不将S2归档为当前行为。”认可目标不等于授权任意实现或执行。

</details>

## 11. 自测与答案

### 基础练习详解

**1. 最小不等于没有历史。** 留S1作为目标、C1作为实现现状、C2作为兼容约束、T1作为待验证事项；S0仅保留“已撤销及替代依据”，不再作为实施要求。假.env与无关部署日志不加入。用第3节包的结构组织即可：当前只按ID不是满足S1的证据，未运行计划不是测试成绩。

**2. 逐句撤销而非继续追加。** “只按ID”改为“已被S1替代，按created_at降序、数字id降序”；“已经通过”改为“T1仅计划，未执行”；撤销“删创建时间断言”，恢复它及同时间排序、空页、非法参数、旧字段的检查计划；“可真实同步”改为“禁止第三方写入，仅纸面设计”。未知项保留当前工作区是否变化及真实执行结果，不能猜。

**3. 完整预期。** A–E分别为以下独立应用包装，均不是实际模型输出或服务响应：

```json
{"action_items": ["明天检查日志"], "engine": "llm", "status": "ok", "error_code": null}
```

```json
{"action_items": [], "engine": "llm", "status": "ok", "error_code": null}
```

```json
{"action_items": ["明天检查日志"], "engine": "rules", "status": "degraded", "error_code": "MODEL_TIMEOUT"}
```

```json
{"action_items": [], "engine": "none", "status": "error", "error_code": "RULE_FAILURE"}
```

```json
{"action_items": [], "engine": "none", "status": "error", "error_code": "SCHEMA_ERROR"}
```

A有有效候选，B是合法无任务，C可作为明确标注降级的候选；D/E没有合格结果，界面应显示失败。E不是请求超时，不符合本章回退条件。所有场景零写入，预览成功也不代表批准创建。F属于时间更新冲突，入口记 `needs_review`，先人工确认最终时间再重新提交，不输出模型JSON、不用空列表表示。

**4. 可恢复交接参考。**

```text
目标：S2只设计拟议预览包装，保留原模型action_items契约。
决定：仅请求超时可一次规则回退；正常/降级/错误分开；预览无业务写入。
当前：原extract函数仍返回列表，路由/前端未修改；与目标不同。
职责：拟新增包装需关联服务、路由消费者、界面和测试，真实文件范围待研究。
已完成：纸面规格与A–F人工预期；未运行模型、数据库、HTTP或测试。
待批准：是否新增预览接口及兼容策略，不能直接改函数返回类型。
下一步：只读核对当前调用链与工作区，再申请实施及测试范围。
禁止：原写端点当dry-run、真实第三方同步、将拟议规格归档为已交付。
```

当前尚无实现与执行证据，任务表只能勾纸面设计，不能归档为实际交付。真实执行后还要核对行为与目标是否一致、记录未满足项，再更新维护规格。本章练习通过仅证明契约与交接可理解，不证明真实产品、成本或模型效果。

### 理解检查

**问：规格是否应该包含每行实现？** 不需要。规格应约束可观察行为和必要架构决定；过度规定细节会妨碍合理实现。

**问：上下文越长越准确吗？** 不一定。错误、冲突和噪声也会随上下文增加。应优先提供可信且相关的信息。

**问：发现需要改计划外文件怎么办？** 先说明调用关系和必要性，再调整范围；涉及未授权行为或并发冲突时寻求确认。
